# 02-system-selection

文化的体系を選び、何のためにどこまで使うかを決めるときに読む。

## 3. 候補体系への二つの入口を使い分ける

文化体系への探索入口を、対象起点だけに固定しない。

探索利用では、少なくとも次の二つの経路を使い分けられる。

### 対象起点の入口

対象側でまだ保持しにくいものを見る。

- 複数の状態・位置
- 経路、中間点、分岐、戻り
- 周期、位相、蓄積、再来、ずれ
- 境界、移行帯、中心／周辺
- 複数の時間尺度
- 流れ、接続、詰まり
- 連続体と分節
- 既存の問題設定とは別の問いが必要だという兆候

この経路では、現在まだ処理できていない対象構造へ、どのような別の見え方を供給できるかから候補体系を探す。

### 体系起点の入口

探索利用で候補体系がすでに明示されている、対象の文化的・歴史的背景から自然に候補がある、同一案件で継続して扱っている、比較のために異なる認知文法を意図的に置く、または現在の問題設定そのものを別の認知場から揺らす必要がある場合は、対象側の具体的な問いを先に完成させなくても候補体系へ軽く触れてよい。

このときは、現在の問いに合う部分だけを先に切り出さない。`preview`の深さで、候補体系自身が何を位置・経路・周期・関係・遷移・境界として区別しているかという主要な全体像を、対象へ対応付ける前に一度見る。

体系起点のpreviewは、対象を全位置へ割り当てることでも、体系を採用することでも、fullまで読むことでもない。そこで生じた問い、対比、仮説、調査先、KJへ戻す材料候補、現在の問題設定への疑問は`framework_generated`として保持し、対象へ返す。

### 候補体系そのものを読む

どちらの入口から入っても、候補体系について、構成要素と分類原理、関係、時間・周期・段階、本来の適用領域、歴史的文脈、異説と限界を確認する。

候補を一つの適合点数で選ばない。

- 対象起点では、未処理の対象構造へどのような別の見え方を供給できるかを見る。
- 体系起点では、現在の問題設定へまだ含まれていないどのような区別や問いを供給できるかを見る。

何の関係もない体系を無制限に列挙することを新しい義務にはしない。体系数を増やすことではなく、現在の問題設定だけで探索可能性を先に閉じないことが目的である。

一つの用例で前景化しなかった位置・経路・周期・関係・象徴を、その用例だけを理由に体系の不要部分とみなさない。保存されている体系全体と、今回前景化した部分を分ける。

## 3a. 探索利用と帰属利用

### 探索利用

体系を、問い、対比、仮説、調査先、構成候補を生む認知場として使う。対象を全位置へ割り当てる必要はない。

ここで得たものは、対象側で独立に支えられるまでは`framework_generated`である。探索として有用でも、そのまま対象の事実・欠落・因果にはしない。

### 帰属利用

「対象にはこの位置構造がある」「この遷移が欠けている」など、体系の構造を対象所見として扱う。

この場合は、体系と対象の単位の同種性、割当手続き、外部規約、系譜差を確認する。詳細は`02a-framework-application.md`に従う。

**探索利用から帰属利用へ無言で切り替えない。** 帰属したい時点で条件を満たし直す。

## 3b. モデル用途

必要に応じて次を選ぶ。

1. **構造モデル**：関係と配置を見る。
2. **一貫性モデル**：単一対象の振る舞いを外部由来の型と比較する。
3. **時間モデル**：周期、蓄積、回帰、段階変化を見る。
4. **遷移モデル**：状態と遷移を試し、到達しない状態、一度も起きない遷移、戻らない状態を探す。

同じモデルでも出口が違う。探索利用では問い・比較軸を得る。帰属利用では対象側の材料で周期・遷移・不可逆性を確かめてから所見にする。

用途の選択、適用範囲、読み込み深度は別である。体系を採用しても、全要素・全解釈語・全遷移を使い切る義務はない。

時間・遷移モデルは静的配置から出にくい問いを生むが、**体系を走らせた結果は対象側で確かめるべき構造候補であり、それだけで対象の性質にはならない。**

## 3c. 同種性

欠落や偏りを対象へ帰属させる前に、体系の要素と対象の構造単位が同種かを見る。

同種性は体系単独の性質ではなく、**体系・層・対象の組**の性質である。同じ体系でも層によって異なる。単位の種類が同じでも分類原理が違えば、そこから欠落は導けない。

異種であっても探索利用には使える。

- 関係を表す動詞を得る。
- 対比軸を置く。
- 空白を問いに変える。
- 表現・構成候補を生成する。
- 問題設定が固定している単位を揺らす。

## 3d. 読み込み深度

`core/activation.md`の`probe / preview / full / enacted`を使う。

対象起点では通常probeから入る。体系起点では、`core/activation.md`に示した条件を満たす場合、previewを探索の入口として使える。

固定のfit閾値は置かない。高い見かけ上の適合が、帰属の妥当性や有用性を保証しないためである。

## 3e. 不採用・縮小の条件

次のような場合は深めない。

- どの結果にも適合し、反証可能な差が出ない。
- 対象側の問いが増えず、体系語彙だけが増える。
- 同種性や割当手続きが無いのに欠落・因果を帰属させようとする。
- 不可逆性、非対称性、局所性、証拠状態を薄める。
- 体系完成のために対象を読み替え始める。

不採用は、体系から生まれた問いをすべて取り消すことではない。対象へ戻して生き残ったものは来歴を保って残す。

採用する場合は、**探索／帰属、モデル用途、適用範囲、読み込み深度**を保ったまま`02a-framework-application.md`へ進む。
