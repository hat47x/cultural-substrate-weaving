# 08-governance-and-records

静的規則と動的材料、判断の来歴、長期的な再開記録を扱うときに読む。各状態の意味は、対応する`core/`／`methods/`配下の文書に従い、ここでは主に何をどのように記録するかを定める。

## 9. 静的層・資料層・動的層を分ける

1. **静的層**：発動条件、原則、文化体系の適用・検証方法、KJの作法。
2. **準静的な文化体系資料層**：原典、系譜、位置、関係、周期、象徴など、体系そのものを再利用できる形で保持する資料。
3. **動的層**：対象ごとに生じる材料、カード、問い、仮説、構成資源、判断、残差。

個別の対象で有効だった読みを、文化体系の正本や静的規則へ自動的に昇格させない。

## 10. 判断の来歴

必要に応じて、次の情報を残す。

- 判断理由と起源
- 元材料への参照
- 変更前の保持事項
- 文化体系の読み込み深度：`not_loaded / probe / preview / full / enacted`
- 利用：探索／帰属
- 帰属：`target_supported / framework_generated / cross_field_emergent / unresolved`
- 採否：`adopted / backgrounded / rejected / distorting / reopened`
- 当時の制約
- 反証条件
- 未解決事項と再開条件

毎回すべての欄を埋める必要はない。**来歴が失われると後の判断が変わり得る箇所だけ、必要な粒度で残す。**

判断や解釈を記録するときは、可能な範囲で、その判断を誰が行ったのかを元資料と結び付ける。利用者が述べた判断、生成AIがその場で加えた解釈、外部資料に書かれている評価を、同じ起源のものとして扱わない。

`framework_generated → target_supported`へ移す場合は、文化体系とは独立した対象側の支持を参照できるようにする。体系語彙を取り除けたという理由だけで、`target_supported`へ移さない。

## 11. 二重計上を避ける

同じ原因機構と採否を持つ記録は、一つの系譜として扱う。次のものを独立した支持として数えない。

- 同一資料の転載
- 一枚のカードから派生した複数カード
- 同じ所見を複数の文化体系から再発見したこと
- 同じ仮説の言い換え

証拠の出所と、そこへ至った発見経路も分ける。発見経路が増えても、それだけで証拠が増えたことにはならない。

## 12. 長期event ledger

長期案件では、すべての発言を記録形式へ変換せず、後から経過をたどる意味がある出来事だけを残す。

- `question_shift`
- `search_shift`
- `kj_reconfiguration`
- `artifact_adoption`
- `artifact_withdrawal`
- `decision_change`
- `delayed_reactivation`
- `repeated_transfer`
- `framework_contact_change`

event種別は、できるだけ**何が起きたか**を表すものにする。「有用だった」「害があった」といった評価をevent種別そのものに含めない。

必要に応じて、その出来事が起きたラウンド、元材料やKJ時点記録、文化体系の読み込み深度、採用・不採用となった内容、再開条件を結び付ける。評価や解釈も残す場合は、観測された出来事とは分け、誰がどの根拠から判断したのかを追える形にする。

たとえば、あるラウンドで文化体系を開かなかったことは、`activation_scope`などの状態として記録できる。一方、それが適切だった、有用だった、あるいは害を避けたという評価は別の判断であり、状態そのものから導かない。

このledgerは、自己評価の点数を蓄積するためのものではない。**実作業で何が変わり、何が残り、何が撤回され、後からどの材料が再び関係したのかを追う。**

過去の事例を後から読み直してeventを付ける場合は`retrospective`、あらかじめ観測系を置いた状態で記録する場合は`prospective`とする。どちらの場合も、観測のために実作業を歪めない。

## 13. 測定と評価を分ける

比較や測定を行った場合は、少なくとも次の四つを同じものとして扱わない。

1. 実際に観察できる差。
2. 記録された測定値。
3. その差や値に対する利用者の判断。
4. 生成AIや外部評価者が加えた解釈。

測定値が記録されているだけで、その値の意味や原因まで確定したとはみなさない。生成AIが評価軸を作り、自分の出力を採点し、その結果を解釈した場合も、測定値と評価判断の来歴を分けて残す。

後から判断が訂正・撤回された場合は、古い判断を上書きして消すのではなく、何がどのように変わったかを後からたどれる形を優先する。

## 14. 保存と作業窓

文脈を軽くするために古い材料を既定で削除しない。新材料、触れた残差、KJ時点記録、`probe`／`preview`は前景化の例であり、必要な範囲は現在の作業に応じて選ぶ。

規則が過剰に作用する場合は、原因に応じて、適用条件の限定、優先順位の変更、補助扱い、削除から選ぶ。削除する場合は担っていた機能を確認する。動的材料を減らして規則整理の代わりにしない。
