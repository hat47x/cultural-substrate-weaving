# 触媒的発見の経路と照明

作業の全体像をつかむとき、体系を生成規則として走らせるとき、生成した候補を現実の利用へ降ろすときに読む。

この文書は、個々の手順より上位にある体験の経路を示す。経路の動きは代表例であり、固定順序でも必須段階でもない。採否、停止、公開・行動への反映は`core/principles-and-constraints.md`の決定権に従う。

## 経路の動き

研究者が日常のなかで異質な概念に触れ、それを触媒として問いの見え方を組み替える体験を、次の動きとして再構成する。どの動きからも前の動きへ戻れる。一つの動きだけを使うことも正規の利用である。

| 動き | 行うこと |
|---|---|
| 抱く | 問い、対象材料、基準線、壊してはならない保持事項を置く（`methods/scope-and-facts.md`） |
| 出会う | 現在の分節から構造的に遠い全体系を選び、その構造核へ触れる（`methods/system-selection.md`） |
| 走らせる | 仮定を明示したまま、体系を生成規則として走らせる（下記） |
| 交える | 対象材料と交差させ、共鳴と押し返しの両方を見る（`methods/transformation.md`）。多数・異種材料の統合は`methods/integration.md`の接続契約で委ねる |
| 降ろす | 問い、観察・調査、小さな試し、構成、判断へと段階的に具体化する（下記） |
| 味わう | 実際に起きたことを受け取り、新しい材料として還す。採らなかった候補も印を保って残す（`core/iteration.md`） |

## 触媒収量を最大化する探索pass

文化体系が認知の運用に有効であるという仮説のもとで探索利用を行う場合、最大化するのは**体系の数、読んだ量、対応数ではなく、通常分析では生じにくい異なる認知操作から得られる発見増分**である。

単一の「似ている位置」を見つけた時点で探索を閉じない。体系の全体場をいったん保ったうえで、体系自身が持つ異なる操作方向を順に通し、そこで生まれた問い・区別・関係・遷移・反証・試行候補を対象側へ持ち帰る。

探索利用が委ねられ、発見増分を広く取りに行く場合は、次のpassを使える。固定順序ではなく、体系が持たない操作を分析者が補って「体系由来」とはしない。

1. **基準線を凍結する**
   - 体系を詳しく開く前に、現在の問い、対象側で確認済みの事実・関係、未解決、既存の分節を短く残す。
   - 後から体系語彙が問題設定そのものを書き換えたかを比較できるようにする。
2. **全体場を先に開く**
   - 対象へ対応付ける前に、体系自身の位置集合、関係網、隣接、対立、周期、境界、遷移、実践、象徴的近傍を可能な範囲で把握する。
   - 早い段階で「対象に使えそうな数個の意味」へ縮約しない。
3. **位置を変えて見る**
   - 配置、空位、隣接、中心／周辺、層、境界から同じ対象を見直す。
   - 「どこに当たるか」だけでなく、「別の位置から見ると何が見えなくなるか」を問う。
4. **場の中を移動する**
   - 前後、隣接、対立、補位置、生成／抑制、循環、戻り、不可逆性など、体系が定める移動を走らせる。
   - 一点対応では出にくい経路、分岐、到達不能、時間差を問いとして取り出す。
5. **実践知を認知操作へ変換する**
   - 各状態で何に注意を向けるか、何を行うか、何を避けるかという実践の層を、観察先、小さな試し、反証条件の候補へ変換する。
   - 領域判断そのものを文化体系へ委ねない。
6. **対象に押し返させる**
   - 共鳴だけでなく、不一致、抵抗、逆転、過剰、体系では分かれるのに対象では分かれない箇所を見る。
   - 押し返しから生じた第三構造は `cross_field_emergent` として、体系への一致と分けて保持する。
7. **構造的に遠い別の場で再分節する**
   - 外部の委任と資源が許す場合、最初の体系と構造型の異なる体系へ軽く接触し、最初の体系が固定した分節を別方向から揺らす。
   - 同じ結論を増やすことではなく、固有に増えた問い・関係・遷移候補と、体系間で食い違った箇所を取る。
8. **体系語を外して対象語へ戻す**
   - 候補を、体系名や象徴語なしでも対象へ向けた問い・観察・比較・試行として読める形へde-bindする。
   - de-bindingで意味が消える候補も捨てず、framework-specificな足場として来歴を保てる。
9. **候補を材料として統合し、対象へ返す**
   - 問い、区別、関係候補、遷移候補、反証条件、観察先、試行、残差を別カードとして扱い、必要ならcompatibleな `affinity-synthesis` へ渡す。
   - framework由来カードにgroupingや表札を先に決めさせない。
   - 統合後の候補を対象側の資料・観察へ戻し、独立に生き残るもの、押し返されるもの、保留するものを分ける。

一つの体系について、使える認知操作の例は次のように整理できる。

| 体系側の構造 | 認知操作として使うときの問い |
|---|---|
| 位置・類型 | 今の分節では同じに見えているものを、どこで分け直せるか |
| 隣接・近傍 | 直接の対応ではなく、近くにあるものから何が見えるか |
| 空位 | 「欠けている」と断定せず、何を調べる問いが立つか |
| 対立・補位置 | 逆側から見ると、現在の説明が何を隠しているか |
| 遷移・経路 | 何が前提で、次に何が起こり得て、どこで戻れなくなるか |
| 周期・位相 | 同じものが別の時点・尺度ではどう変わって見えるか |
| 境界・中心／周辺 | どこで分類が崩れ、何が境界に滞留するか |
| 実践知 | 次に何へ注意し、何を観察・試行すると現実から応答を得られるか |
| 象徴的近傍 | 通常語彙では離れている二つを、どの新しい問いで接続できるか |

各操作から得たものは、最初から一つの説明へまとめない。必要なら、少なくとも `question / distinction / relation-candidate / transition-candidate / falsifier / observation-or-trial / residual` を別々に外在化する。これにより、文化体系の豊かさを早い物語化で失わず、その後の親和統合で対象材料と再構成できる。

このpassは、すべての探索で最大深度や複数体系を必須化する規則ではない。**探索利用の目的が文化体系の認知的な可能性を広く取り出すことにあるとき、早期収束を避けて利用可能な操作空間を十分に開くための実行形**である。

## 体系を仮の生成規則として走らせる

体系の規則を、観察から帰納された要約ではなく、世界を生み出す生成規則として**仮に**扱う。「この系が世界を生むなら」と仮定したうえで、ためらわずに走らせる。

- **配置**：対象や、その要素・主体・局面は、どの位置にあるか。
- **空位**：閉じた集合のほかの位置には何があるはずか。空いた位置は何を問うか。
- **遷移**：前に何があり、次に何が来るか。何が戻れないか。生成と抑制はどう働くか。
- **補位置**：補い合う位置や対立する位置から見ると、同じものはどう見えるか。
- **実践**：その状態では、何に注意を向け、何を試すのがふさわしいとされるか。

体系が持たない層（たとえば遷移規則）を分析者が補って走らせた場合は、そのことを明示する。仮定の句（「この系として見るなら」）は、候補が現実の応答を得るまで外さない。走らせた結果は`framework_generated`であり、対象へ帰属させるには`methods/framework-application.md`の帰属利用の条件を満たし直す。

## 照らす：毒を禁じず、印を保つ

生成物が害をなすのは、多くの場合、内容の大胆さではなく、由来・仮定・射程の印を失ったときである。印を失った候補は、体系の権威を帯びた事実、全体の真理、あるいは対象自身の声として流通しやすい。

本スキルは、これを画一的な関門で止めない。経路の各動きで視点を移し、候補を照らす。

- **由来の光**：どの体系のどの位置・操作から来たのか、対象から来たのか、接触から生じたのか。
- **仮定の光**：生成規則の仮定の句が、まだ候補に付いているか。
- **全体の光**：同じ体系の補い合う位置や遷移から見ると、この候補は何を隠し、何を固めているか。型を遷移のなかの状態として見れば、型は固定された本質ではなく通過点になる。
- **対象の光**：対象材料はこの候補を支えるか、押し返すか。どこにも入らない候補が、孤立したまま見えているか。
- **具体の光**：誰が、何を、いつ、どう観察し、何が起きたら考えを改めるかを言えるか。

光がもたらすのは可視性であり、判定や削除ではない。照らされて露わになった投影や、蒸発しかけた仮定は、体系の偏りや次の作業への学びとして残せる。採否は外部の決定権へ返す。

照らす動きを、すべての候補に毎回課す記入欄にはしない。印が失われると後の判断が変わる箇所に使う。必要なら、候補に次の灯りを付けて運べる。

```text
candidate:
origin: framework:<体系/位置/操作> | target:<参照> | contact
as_if: <生きている仮定の句>
whole_view: <補位置・遷移から見えたこと>
reach: question | observation | trial | composition | claim | action
```

`reach`は、候補を現実へどこまで近づけようとしているかを記す。値によって許可や禁止は決まらない。

## 降ろす：具体化が光になる

洞察を現実の利用へ降ろすときは、候補を段階的に具体化する。

1. **問い**：対象へ向ける具体的な問いにする。
2. **観察・調査**：何を見れば、何を調べれば答えに近づくかを決める。
3. **小さな試し**：取り消せる範囲で、現実の応答を得られる行為にする。
4. **構成**：文章、設計、計画などの構成資源として使う。
5. **判断・行動**：採用、公開、実行へ進める。

この並びは、後になるほど現実への影響が大きくなる順を示す。どこまで進むか、どの段階を省くかは、外部の決定権と委任に従う。

具体化は、それ自体が照明になる。体系の語彙のままでは隠れていた仮定や投影も、「誰が、何を、いつ」を言葉にしようとすると露わになる。現実に近づく候補ほど多くの具体化を要するため、一律の閾値を置かなくても、光の量は射程に応じて自然に増える。

体系の実践の層から得た注意の向け先や行為は、着地の足場になる。ただし、それを領域の品質基準、安全基準、専門的な判断の代わりにはしない。領域の基準は、呼び出し側のコンテキストや領域スキルから受け取る。

## 味わう：結果を次の材料にする

実際に起きたこと、利用者の訂正、採用後の撤回は、新しい材料として受け取る。結果が体系の読みを押し返した場合は、何を前提にした読みが崩れたかを残す。後から支持された候補も、由来を対象由来へ書き換えない。複数roundにわたる再開は`core/iteration.md`の接続契約に従う。
