# 利用範囲・読み込み深度・実行状態

本スキルをどの範囲で使うか、文化体系をどこまで読むか、その時点で何を実行しているかを扱うときに読む。

## 0. 決定権を本スキルの外に置く

**本スキルは、利用するかどうか、どこまで使うか、いつ弱めるか・止めるかを独立に決める主体ではない。**

利用範囲、読み込み深度、停止、再開、優先順位は、著者の意思決定、または本スキル外で著者が生成AIへ与えている設定・指示・委任から受け取る。

外側の指示によって生成AIへ裁量が委ねられている場合は、その委任範囲で実行上の選択を行ってよい。ただし、課題が単純、閉じている、専門的、実務的、緊急であるといった分類を、本スキル固有の価値判断へ変換して利用範囲を自動的に狭めない。

明示的な利用範囲が与えられていない場合も、本スキル自身の静的な好みから禁止・抑制条件を作らない。必要な判断根拠が外側にある場合はそれを使い、判断主体と根拠を追えるようにする。

## 1. 利用範囲は許可段階ではなく状態ラベル

必要に応じて、現在の利用状態を次のように記録できる。

- **`non_activation`**：このラウンドでは本スキルの操作を実行していない。
- **`limited_use`**：KJ、来歴、候補想起、変換など、指定された一部の操作を実行している。
- **`exploratory_use`**：文化体系による候補供給とKJ統合を含む広い探索を実行している。

これらは優劣、推奨度、危険度を表さない。どの状態を選ぶかは課題種類から自動決定せず、外側の指示・委任を記録した結果として扱う。

同じ課題でも、著者・callerの目的が変われば利用範囲は変わり得る。誤字修正のような局所作業でも探索利用を指定でき、開いた制度構想でも限定利用を指定できる。

## 2. 読み込み深度は、何を開いたかを表す

文化体系の読み込み状態は、必要に応じて次のラベルで記録する。

- **`not_loaded`**：文化体系をまだ開いていない。
- **`probe`**：周期、経路、境界、中心／周辺、複数時間尺度、流れ、連続体、反復とずれなどから、問いの入口を探っている。
- **`preview`**：候補体系の主要な認知構造、位置、経路、周期、関係、遷移、境界へ軽く触れている。
- **`full`**：原典、系譜、象徴、複合構造まで読んでいる。
- **`enacted`**：体系固有の操作を実際に対象へ適用している。

これらも許可階段ではない。`probe`を通らなければ`preview`へ進めない、`full`を読んだら`enacted`へ進むべき、といった権限関係を表さない。

特定の体系や深度が外側から指定されている場合は、その指定を実行状態へ反映する。深度の選択まで生成AIへ委ねられている場合は、委任された目的に沿って選び、何を選んだかと理由を記録できるようにする。

## 3. 各深度から得られる情報を返す

深度を変えるたびに、次のような差を判断材料として返せる。

- 新しく立った意味単位、関係、問い、対比、調査先。
- 既存内容との重複。
- 体系語彙だけが増えている箇所。
- 対象の事実、境界、不可逆性、証拠状態とのずれ。
- 追加で読むと得られそうな情報と、必要になる資料・作業量。
- 現在の深度では未処理の部分。

これらは**縮小・停止を自動的に命令する条件ではない。** どの差を重視し、続けるか、戻るか、別体系へ移るかは、外側の価値基準・目的・委任に従う。

体系側から候補を広く開く場合の候補想起は `methods/system-selection.md`、体系を実際に対象へ接触させる操作は `methods/framework-application.md` に従う。ここでいう「従う」は、それらの方法操作を参照するという意味であり、本モジュールが新しい利用許可条件を作ることを意味しない。

## 4. 停止・縮小・再開を状態として記録する

外側の指示または委任された判断によって利用を止める、縮小する、別手法へ移る場合は、少なくとも次を残せる。

- その時点の利用範囲と読み込み深度。
- 停止・縮小・移行を決めた主体。
- 使われた判断基準と、その出所。
- 未解決の問い、残差、再開時に必要な材料。

外部要因で中断した場合は、その事実を価値判断へ変換せず、中断理由と再開条件を分けて記録する。

## 5. ラウンドの報告

利用範囲や深度が作業上重要な場合は、結果とともに次を報告できる。

1. どの操作・体系をどこまで使ったか。
2. その範囲を誰の指示・どの外部設定・どの委任で決めたか。
3. 各深度で何が増え、何が変わらなかったか。
4. 残差と、次に選べる操作。

本モジュールの役割は、利用を抑制することではなく、**外側にある決定権を保ったまま、実行状態と選択肢を見えるようにすること**である。
