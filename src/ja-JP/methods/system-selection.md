# 02-system-selection

文化的体系を選び、何のためにどこまで使うかを決めるときに読む。

## 3. 対象側または体系側から候補を探す

通常は、対象側でまだ保持しにくいものを手掛かりに候補体系を探す。代表例は次のとおり。

- 複数の状態・位置
- 経路、中間点、分岐、戻り
- 周期、位相、蓄積、再来、ずれ
- 境界、移行帯、中心／周辺
- 複数の時間尺度
- 流れ、接続、詰まり
- 連続体と分節
- 既存の問題設定とは別の問い

### 候補想起をモデルの自然連想だけに任せない

採用済み体系については、先にframeworks/portfolio.mdと該当ドシエを確認する。内部ドシエは候補を固定するためではなく、体系固有の構造核を毎回の検索品質に依存せず再利用するための基礎母集団である。外部探索は、未採用体系との新しい出会い、系譜差、異説、ドシエ不足の補完に使う。

探索利用では、現在の対象語彙に近い体系だけで候補探索を閉じない。状態格子、周期・暦、経路・流れ、方向、層とパスのように、対象の現在の分節とは異なる構造を持つ体系を**高い優先度で候補想起・検索する**。構造の遠さは、問いの見え方を組み替える触媒の力になり得る。

次の具体名は、採用推奨や完全な候補一覧ではなく、異なる構造型へ到達するための検索アンカーである。

- **状態・位置・分節を開くアンカー**：四季、五行、五大、八卦、方位（東西南北／東西中南北など）、虹の七色、チャクラ。
- **周期・暦・複数時間尺度を開くアンカー**：四季、十干、十二支、ツォルキン。
- **経路・流れ・層・パスを開くアンカー**：経絡、チャクラ、セフィロトとパス、八卦など関係や変化を構造化する体系。

一つの体系が複数の探索型へ現れてよい。この並べ方を伝統上の分類や体系間の同一性とはみなさない。同じ構造型の類似候補だけを増やすより、異なる構造型から少数ずつ候補へ上げる。

これらの名称は詳細知識の代わりではない。位置数、対応表、遷移規則、歴史的意味、系譜差、構造核に関わる異説は、実際に使う段階で資料へ戻って確認する。モデルの記憶だけで欠けた部分を補わない。

候補想起の段階では採否を急がない。一つの局所的な不一致や、最初のprobeで問いが立たなかったことを、その体系全体の探索価値の否定へ広げない。previewで主要な認知構造と限界へ触れ、対象へ返す問い・対比・調査先が立つかを見る。

一方、探索利用では外部利用条件と委任範囲に応じて、体系側からpreviewへ入ってよい。この場合は現在の問いに合う部分だけを先に切り出さず、体系自身が何を位置・経路・周期・関係・遷移・境界として区別しているかという主要な全体像を、対象へ対応付ける前に見る。

### 構造核を優先して取り出す

どちらの入口でも、体系から優先して取り出すのは次の構造核である。

1. **全体の分節**：世界全体を一つの系として、漏れなく重なりなく分けようとする分節原理と、閉じた位置集合。集合が閉じているほど、空いた位置がそのまま問いになる。
2. **遷移と位相**：隣接、対立、循環、生成と抑制、中心と周辺、可逆と不可逆、到達しない位置。
3. **状態ごとの実践知**：各状態で注意を向ける先、ふさわしい行為、避けること、現実との結び方。

あわせて、本来の適用領域、系譜、限界を確認する。系譜は、どの伝統・資料・系統に拠るかを後から辿れる程度に示す。文化的な変異、装飾、異説は、構造核を変えるものを優先して確認し、それ以外は生成・構成で文化的な質感が要る場合などに開く。すべての体系が三つの層を備えるとは仮定しない。欠けた層を分析者が補った場合は、体系の正本と区別する。

候補を一つの適合点数で選ばない。対象起点では、未処理の対象構造へどのような別の見え方を与えられるかを見る。体系起点では、現在の問題設定にはまだない区別や問いが生じるかを見る。無関係な体系を無制限に列挙することや、一つの用例で前景化しなかった部分を体系から切り捨てることを目的にしない。

### 適合度ではなく、必要な認知機能で体系を組む

探索利用で文化体系の認知寄与を広く引き出すとき、候補を「対象に最も似ている体系」一つへ早期収束させない。現在の対象理解がまだ十分に使っていない**認知機能**を供給できるかを見る。

代表的な機能は次である。

- 分節・位置を変える。
- 空位を、対象の欠落ではなく未質問の位置として見せる。
- 対立、補完、隣接、中心／周辺など別の関係原理を持ち込む。
- 周期、位相、遷移、生成・抑制、可逆・不可逆を時間へ持ち込む。
- 境界、尺度、層をずらす。
- 状態ごとの実践知から、注意・観察・試行候補を作る。
- 現在の問題設定そのものを反転・相対化する。

複数体系を使う場合も、候補数を増やすことを目的にしない。同じ構造型を重ねるより、必要なら**異なる分節原理・時間構造・経路構造・実践構造**を持つ体系を反照面として置く。第二体系は第一体系の妥当性へ投票するものではなく、第一体系が固定した見方を別原理から揺らすために使う。

どの機能をどの体系から得るかを、一つの総合fit点数へ畳まない。対象側の基準線と、体系接触後に新しく生じた問い・識別・調査先・試行を比較できる状態にする。

### 選定思考を外在化する

候補層が厚くなり、近接体系の選び分けが作業記憶だけでは不安定になる場合は、選定理由そのものを外在化する。

保持候補は、対象側baseline、不足している認知機能、各候補に期待する認知仕事、近接候補との差、第二体系で何を揺らしたいか、target-returnの問い・観察・反証候補、体系語を外したtarget language、選択を見直す条件である。

これはranking表ではない。空欄を埋めることも目的ではない。「何の認知仕事をさせるためにこの体系へ触れたのか」を後から再検査できるようにする。

repository / research workspaceが利用可能な場合は、`research/framework-candidates/scripts/framework_selection_workspace.py` を任意の補助として使える。literalな候補想起、exact operation labelの近接比較、未記入selection worksheetの生成だけを行い、自動routing・fit score・採用判定は行わない。

## 3a. 探索利用と帰属利用

### 探索利用

体系を、問い、対比、仮説、調査先、構成候補を生む認知場として使う。対象を全位置へ割り当てる必要はない。

ここで得たものは、対象側で独立に支えられるまでは`framework_generated`である。探索として有用でも、そのまま対象の事実・欠落・因果にはしない。

### 帰属利用

「対象にはこの位置構造がある」「この遷移が欠けている」など、体系の構造を対象所見として扱う。

この場合は、体系と対象の単位の同種性、割当手続き、外部規約、系譜差を確認する。詳細は`02a-framework-application.md`に従う。

**探索利用から帰属利用へ無言で切り替えない。** 帰属したい時点で条件を満たし直す。

## 3b. モデル用途

用途例は次のとおり。

1. **構造モデル**：関係と配置を見る。
2. **一貫性モデル**：単一対象の振る舞いを外部由来の型と比較する。
3. **時間モデル**：周期、蓄積、回帰、段階変化を見る。
4. **遷移モデル**：状態と遷移を試し、到達しない状態、一度も起きない遷移、戻らない状態を探す。

同じモデルでも出口が違う。探索利用では問い・比較軸を得る。帰属利用では対象側の材料で周期・遷移・不可逆性を確かめてから所見にする。

用途の選択、適用範囲、読み込み深度は別である。体系を採用しても、全要素・全解釈語・全遷移を使い切る義務はない。

時間・遷移モデルは静的配置から出にくい問いを生むが、**体系を走らせた結果は対象側で確かめるべき構造候補であり、それだけで対象の性質にはならない。**

## 3c. 同種性

欠落や偏りを対象へ帰属させる前に、体系の要素と対象の構造単位が同種かを見る。

同種性は体系単独の性質ではなく、**体系・層・対象の組**の性質である。同じ体系でも層によって異なる。単位の種類が同じでも分類原理が違えば、そこから欠落は導けない。

異種であっても探索利用には使える。代表例は次のとおり。

- 関係を表す動詞を得る。
- 対比軸を置く。
- 空白を問いに変える。
- 表現・構成候補を生成する。
- 問題設定が固定している単位を揺らす。

## 3d. 読み込み深度

`core/activation.md`の`probe / preview / full / enacted`を使う。

固定のfit閾値は置かない。高い見かけ上の適合が、帰属の妥当性や有用性を保証しないためである。

## 3e. 観察シグナルと利用状態

体系との接触中には、次のような状態を観察して記録できる。

- どの結果にも適合でき、反証可能な差が立ちにくい。
- 対象側の問いが増えず、体系語彙だけが増えている。
- 同種性や割当手続きが無いまま、欠落・因果を対象へ帰属させようとしている。
- 不可逆性、非対称性、局所性、証拠状態が薄くなっている。
- 体系を完成させるために対象を読み替え始めている。

これらは、探索の継続、読み込み深度の変更、不採用を自動的に決める停止条件ではない。外部利用条件が判断を依頼者へ留保している場合は判断材料として返し、実行AIへ委ねている場合はその委任範囲で使う。

ただし、探索上の利用状態と、対象所見として帰属できるかどうかは分ける。同種性や割当手続きなど帰属に必要な条件を満たさない候補は、そのまま対象事実へ昇格させず、`framework_generated`または`unresolved`として保持できる。

体系を不採用にした場合でも、そこから生まれた問いをすべて取り消す必要はない。対象へ戻して生き残ったものは来歴を保って残す。

継続する場合は、**探索／帰属、モデル用途、適用範囲、読み込み深度**を保ったまま`02a-framework-application.md`へ進む。
