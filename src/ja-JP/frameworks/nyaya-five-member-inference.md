# ニヤーヤ五支論証 — 主張・理由・例証・適用・結論

## 採用する構造核

CSWでは古典インドのNyāya、とくに初期Nyāyaで論証・他者向け推論を明示する五支の構造を認知資源として採用する。

基本形は次の五つである。

1. **pratijñā** — 何を立てるのかという主張。
2. **hetu** — その主張を支える理由。
3. **udāharaṇa / dṛṣṭānta** — 理由と結論側の関係を示す例証・既知例。
4. **upanaya** — その関係を今回の対象へ適用する段階。
5. **nigamana** — 適用後に改めて置かれる結論。

有名な煙と火の例は、丘に火があるという主張、煙があるという理由、煙と火の結びつきを示す既知例、丘への適用、結論という順で説明される。

CSWが借りるのは、**説明の流暢さの中に隠れた「理由から対象への橋」を露出させる操作**である。五項目へ文章を整形すること自体を目的にしない。

## CSWで強い認知操作

- thesis/reason split: 結論らしき文と、その根拠として働く文を分離する。
- corroborating-example probe: 理由と結論の関係を支える既知例が何かを見る。
- application check: 既知例で成り立つ関係が、今回の対象にも実際に適用できるかを別段階で確認する。
- inferential-bridge exposure: 「だから」の一語で飛ばされた橋を外在化する。
- positive/negative comparison: 必要なら似た例だけでなく、成り立たない側の例も探す。
- pseudo-reason audit: 理由に見える語が、実際には主張の言い換えや関係の未証明部分ではないかを見る。
- debate-facing restatement: 他者が追える順序へ論証を置き直す。

### selection workspaceで使うoperation ID

研究用profileとselection workspaceでは、上の操作を次のIDに束ねる。

- `argument-unfolding`: 五支へ展開し、他者が追える順序へ置き直す。
- `reason-rule-separation`: 今回の理由と、理由から結論へ進む一般化を分ける。
- `example-counterexample-probe`: 例証と反例から一般化の射程を調べる。
- `rule-application-audit`: 既知例の関係が今回の対象へ適用できるかを確認する。
- `inference-gap-detection`: 未確認の橋、追加仮定、疑似的な理由を残差として取り出す。

## 対象へ返す問い

- 今回、本当に立てたい主張は何か。
- その主張の理由として、対象側で観察されているものは何か。
- 理由と結論の結びつきを示す既知例は何か。
- その既知例は単なる類似ではなく、今回必要な関係を示しているか。
- 既知例の関係を、この対象へ適用する段階で何が追加仮定になっているか。
- 反例・不似合いな例を置くと、理由の射程はどこまで縮むか。
- Sanskrit語を外しても、主張→理由→例証→適用→結論の橋は追跡できるか。

## 他体系との区別

- アリストテレス四原因は「なぜ」の説明型を複数化する。Nyāya五支は、ある理由からある主張へ進む**推論の橋**を検査する。
- 四句分別は命題を二値枠から開く。Nyāyaは開いた命題のうち、どれがどの理由で支えられるかを問う。
- ジャイナ七分法は述定を視点・条件へ結び直す。Nyāyaは主張・理由・例・適用の接続を外在化する。

## 薄めてはいけない点

- 五支を「インド版アリストテレス三段論法」として同一視しない。
- Nyāya、仏教論理、Vaiśeṣika、Carakaの論争形式、後代Navya-Nyāyaを一つの不変な論理体系へ潰さない。
- 五支形式を埋めただけで妥当性・真理が得られるとは扱わない。
- 例証を独立証拠として二重計上しない。例が関係を説明しているだけなら、target-side supportとは別である。
- smoke/fireの定型例を、無関係なdomainへの自由な類推許可として使わない。
- anumānaやpramāṇaを、歴史的文脈を消したgeneric proof pipelineへ置き換えない。

## 現在の範囲

このdossierは、初期Nyāyaの五支論証を中心にする。

後代の推論理論、vyāpti、hetvābhāsaの詳細分類、Navya-Nyāyaの技術語彙、Nyāya以外のインド論理伝統は別の深化対象であり、ここへ自動統合しない。

## 探索と帰属

探索では、主張・理由・例証・適用を分けることで、未確認の橋や不足しているtarget-side evidenceを発見できる。

しかし、framework上きれいな五支になったことは、対象側の因果・一般則・結論が確認されたことを意味しない。実際の理由、一般化、適用可能性は対象資料へ戻して確認する。

## de-binding

対象へ返す前に、

1. pratijñā等の語を必要なprovenance以外では外す。
2. 主張、理由、既知例、対象への適用、結論を対象語で書く。
3. どの橋がframeworkによって生成・補完されたかを残す。
4. 理由と例証をtarget-side evidenceへ戻す。
5. 適用に失敗した例や反例はresidual / counterexampleとして残し、論証を自動修復しない。
