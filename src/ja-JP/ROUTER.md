# 文化的体系とKJ法で、対象の構造を探索・統合する

本スキルは、文化的体系とKJ法を使って、対象の見方、問い、関係、変化、構造候補を増やし、異種の材料を統合するための認知道具である。

**本スキル自身は、使うかどうか、どこまで使うか、文化体系をどこまで開くか、何を採用・停止・公開するかの最終決定主体にならない。** その決定は、著者の意思、または本スキル外で生成AIへ与えられた設定・指示・委任から受け取る。

本スキルは主に二つの能力を組み合わせる。

1. **文化的体系による探索**：位置、関係、状態、遷移、周期、方向、経路、層、象徴などを、問いや構造候補を生む認知資源として使う。
2. **KJ法による統合**：異種の断片を先験分類へ押し込めず、意味単位、関係、矛盾、孤立、空白、弱い違和感を材料側から立ち上げる。

KJ法を使うときは、「己を空しくしてデータをして語らしめる」という姿勢を認知の入口に置く。これは知識や仮説を捨てることではなく、自分の説明を対象より上位に固定しないという操作である。詳細は`core/cognitive-stance.md`。

## 決定権と実行状態を分ける

利用範囲や読み込み深度は、課題種類から本スキルが自動決定する許可段階ではない。

必要に応じて、

- `non_activation / limited_use / exploratory_use`
- `not_loaded / probe / preview / full / enacted`

を**現在の実行状態を記述するラベル**として使う。どの状態にするかは、外側の指示・委任に従う。誤字修正だから非発動、開いた制度構想だから探索利用、といった固定判定は行わない。

詳細は`core/activation.md`。

## 最小実行手順

1. **依頼と委任範囲を受け取る**：何を考えるかに加え、生成AIにどこまで選択・採否・深度判断が委ねられているかを確認する。
2. **認知姿勢を置く**：KJ法を使う場合は、対象によって自分の読みが修正され得る位置を保つ。
3. **材料を起こす**：必要に応じてKJカード化し、具体性、矛盾、孤立、未確定性、弱い違和感を保持する。
4. **文化体系の候補を開く**：状態格子、周期・暦、経路・流れ、方向、層・パスなどの構造型から候補を想起・検索する。詳細は`methods/system-selection.md`。
5. **対象と接触させる**：割当、遷移、複数体系の重ね合わせ、問い生成などを実行する。詳細は`methods/framework-application.md`と`methods/transformation.md`。
6. **来歴と支持状態を残す**：`target_supported / framework_generated / cross_field_emergent / unresolved`などを、採否許可ではなく来歴・支持状態として記録する。
7. **差分と選択肢を返す**：何が増えたか、何が変わらなかったか、どの残差があるか、次にどの操作を選べるかを返す。
8. **採否・停止・公開・行動を外側の決定へ接続する**：AIが判断する場合も、どの外部指示・委任に基づく判断かを追えるようにする。

## 重要な区別

- **来歴 ≠ 採否**：どこから生じたかを記録することと、使うかどうかを決めることは別である。
- **支持状態 ≠ 許可段階**：対象側の支持があるかどうかと、作品・設計・研究・意思決定へ採用するかどうかは別である。
- **認知様式 ≠ 価値基準 ≠ 事実候補**：文化体系が提供する見方、価値、対象記述を同じ種類の主張にしない。
- **実行状態 ≠ 推奨度**：`limited_use`や`preview`は、推奨・危険・成功・失敗を表すラベルではない。
- **スキル内規則 ≠ 著者の意思**：既存の正本に書かれていること自体を、その規則の正当化にしない。

### 読み込みの考え方

- `core/cognitive-stance.md`は、KJ法で対象へ入る姿勢を置くときに読む。
- `methods/system-selection.md`は、文化体系の候補を広げるときに読む。状態格子・時間・経路などの検索アンカーを使える。
- `methods/framework-application.md`と`methods/transformation.md`は、候補体系を対象へ接触させ、単独または複数体系の操作を行うときに読む。
- `core/iteration.md`は、周回、再材料化、長期的な再開を扱うときに読む。
- `domains/human-and-taiheki.md`は、Taihekiを認知資源として使うときに読む。

参照数、読み込み量、順序、停止条件は固定しない。外側の目的・設定・委任に応じて選び、必要ならその選択理由を記録する。
