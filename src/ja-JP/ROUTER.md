# 文化的体系を認知場として開き、対象へ戻して確かめる

**本スキルは、認知操作、候補構造、来歴、差分を提供する道具であり、価値判断、利用範囲、読み込み深度、停止、採否、公開・行動への反映を独立に決定しない。これらの決定権は、著者の意思決定、またはスキル外で著者が生成AIへ与えた設定・指示・委任に属する。**

本スキルは、文化的体系を答えや分類器として使うのではなく、対象を見るための一時的な認知場として開く。

1. **文化的体系による探索**：位置、関係、状態、遷移、周期、象徴を、通常分析とは異なる認知資源として使う。**体系との一致だけでなく、対象が体系を押し返す不一致・抵抗・逆転にも注意し、その緊張から元のどちらにも還元できない第三構造が生じるかを見る。**
2. **KJ法による統合**：異種の断片から、意味単位、関係、矛盾、孤立、空白を立ち上げる。

文化体系、対象材料、その接触から生じた構造は、由来を区別して追跡できる。`target_supported / framework_generated / cross_field_emergent / unresolved`などのラベルは来歴や状態を記録するためのものであり、それ自体から採用、発話、外部化、停止の可否を導かない。

材料の親和統合や複数roundの差分再開が必要な場合、利用可能なら専用のcompatible realizationへ委ねる。CSWはそれらの内部アルゴリズムを所有しない。

- one-round material synthesis: `affinity-synthesis` またはcompatible Method realization
- multi-round delta / reopen orchestration: `iterative-inquiry-synthesis` またはcompatible Method realization

compatible realizationがない環境でも、CSW自体の文化体系探索、帰属保持、対象側へのverification handoffは行える。ただし、実行していない親和統合やmulti-round orchestrationを実行済みとは称しない。

本スキルを使う際には、KJ法の「己を空しくしてデータをして語らしめる」という姿勢を認知操作として参照できる。これは知識や仮説を捨てることではなく、自分の説明を対象から修正され得る位置へ置くための方法である。どこまでこの姿勢や各技法を使うかは、スキル外の委任範囲に従う。詳細は`core/cognitive-stance.md`。

領域固有知識、品質基準、成果物の価値基準を本スキル自身は定義しない。必要な基準は、著者の指示、スキル外の設定、領域固有スキルや資料から受け取る。

課題が開いているか閉じているか、単純か複雑か、緊急かどうかといった課題種別そのものを、本スキル側の自動的な発動・抑制条件にはしない。著者が体系選定や利用深度の判断を生成AIへ委ねている場合は、その外部の委任範囲で判断する。**明示指定があれば**、課題の開閉に関わらず、少なくとも限定利用して基準線との差分を確かめる。

## 認知姿勢

対象から自分の読みを修正され得る位置に置く。**最初の見立てを当てることより、対象によって自分の見立てを変えられることを重く見る。**

これは知識や仮説を捨てることではない。十分に材料へ触れた後は大胆に考えてよいが、新しく生じた意味を元材料が最初から語っていた事実へ書き換えない。

詳細は `core/cognitive-stance.md` を読む。

## 最小実行手順

1. **外部の委任範囲を読む**：著者の依頼、スキル外の設定・指示から、今回委ねられている判断、利用範囲、資源制約を確認する。
2. **利用状態を記録する**：必要なら`non_activation / limited / exploratory`、文化体系の`not_loaded / probe / preview / full / enacted`を現在状態として記録する。状態名そのものは次の行動を決めない。
3. **必要な認知操作を選ぶ**：KJ、候補想起、文化体系の読み込み、変換、来歴記録などから、外部の委任を実行するための操作を使う。多数・異種の材料から構造を立ち上げる必要があれば、`methods/integration.md` の接続契約からcompatible synthesis realizationへ渡す。
4. **探索・統合する**：文化体系から問い、関係、状態、遷移候補を得たり、KJで材料を束ねたりする。複数の操作を往復してよい。体系固有構造を汎用語へ早く薄めない。
5. **由来を保つ**：対象由来、体系由来、接触から生じた構造、判断主体を区別して追える形にする。新しいframework contactが旧artifactや残差へ触れるなら、`core/iteration.md` の接続契約からcompatible iterative realizationへ渡す。
6. **判断材料を返す**：候補、差分、残差、反証、来歴を提示し、採用・停止・公開・行動への反映は外部の決定権へ返す。生成AIに判断が委任されている場合は、その委任の範囲で判断する。第三構造が生じても、対象側の独立supportなしに事実へ昇格させない。

文化体系の数、読み込み深度、全文読解の有無、体系固有操作の実行有無は、それ自体では成功・失敗・停止を意味しない。外部の評価基準で必要なら、それらを観測値として利用できる。

## 重要な区別

- **利用状態 ≠ 価値判断**：`not_loaded / probe / preview / full / enacted`は状態を記述する。どの状態が望ましいかは外部の判断である。
- **来歴 ≠ 行動許可**：対象由来・体系由来・接触由来を分けても、それだけで採用・発話・外部化の可否は決まらない。
- **de-binding ≠ 独立観察**：体系語彙を外して文が成立したことと、対象側に別の観察・資料があることは別の情報である。どちらをどの程度の証拠として扱うかは、外部の証拠基準に従う。
- **探索 ≠ 帰属**：体系から問いを得たことと、対象にその構造があると判断したことを別の出来事として記録できる。
- **対応 ≠ 統合**：体系とのきれいな対応は、それ自体では第三構造ではない。対象と体系の差が保存されたまま新しい区別・関係・問いへ組み替わったかを見る。
- **KJ利用 ≠ 文化体系利用**：KJと文化体系は別の認知操作であり、どちらをどう組み合わせるかは外部の委任に従う。
- **framework output ≠ synthesis authority**：文化体系から来た候補は、親和統合へ渡す材料にはなれるが、groupingや表札を先に決める権威ではない。

## 読み込み方

一括読み込みを避け、参照順・参照数・文化体系の候補数や深度は、本スキル自身の価値判断では固定しない。

- 外部から利用範囲や使用体系が指定されている場合は、その指定に沿って参照する。
- 著者が体系選定や読み込み深度を生成AIへ委ねている場合は、その委任を根拠として候補を想起・検索し、必要な参照へ進む。
- KJ、文化体系、反復分析、Taihekiなどの各参照は、能力・操作を提供する。Routerは、それらを使うべきか否かを課題種別だけから自動決定しない。
- 対象固有の情報は動的材料として扱い、静的な方法記述と区別して参照できる。
