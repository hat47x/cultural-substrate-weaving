# 08-governance-and-records

静的規則と動的材料、判断来歴、長期的な再開記録を扱うときに読む。各状態の意味は対応するcore／methods文書に従い、ここでは記録形式だけを定める。

## 9. 静的層・資料層・動的層を分ける

1. **静的層**：発動条件、原則、文化体系の適用・検証方法、KJの作法。
2. **準静的な文化体系資料層**：原典、系譜、位置、関係、周期、象徴など、体系そのものを再利用可能な形で保持する資料。
3. **動的層**：対象ごとに生じる材料、カード、問い、仮説、構成資源、判断、残差。

個別対象で有効だった読みを、文化体系の正本や静的規則へ自動昇格させない。

## 10. 判断の来歴

必要に応じて次を残す。

- 判断理由と起源
- 元材料への参照
- 変更前の保持事項
- 文化体系の読み込み深度：`not_loaded / probe / preview / full / enacted`
- 利用：探索／帰属
- 帰属：`target_supported / framework_generated / cross_field_emergent / unresolved`
- 採否：`adopted / backgrounded / rejected / distorting / reopened`
- 当時の制約
- 反証条件
- 未解決事項と再開条件

すべての欄を毎回埋めない。**来歴を失うと判断が変わる箇所だけ、十分な粒度で残す。**

`framework_generated → target_supported`へ移す場合は、文化体系とは独立した対象側の支持を参照できるようにする。体系語彙を除去できたことだけを移動理由にしない。

## 11. 二重計上を避ける

同じ原因機構と採否を持つ記録は一つの系譜として扱う。次を独立した支持として数えない。

- 同一資料の転載
- 一枚から派生した複数カード
- 同じ所見を複数文化体系から再発見したこと
- 同じ仮説の言い換え

出所と発見経路も分ける。発見経路が増えても証拠が増えたことにはしない。

## 12. 長期event ledger

長期案件では、すべての発言を記録形式へ変えず、意味のある出来事だけを残す。

- `question_shift`
- `search_shift`
- `kj_reconfiguration`
- `artifact_adoption`
- `decision_change`
- `delayed_reactivation`
- `repeated_transfer`
- `useful_nonuse`
- `harm_detected`

必要なら、発生したラウンド、元材料・KJ時点記録、文化体系の読み込み深度、採用・不採用内容、再開条件を結び付ける。

このledgerは自己評価点を蓄積するものではない。**何が実作業へ残り、何が消え、何が遅れて効き、どの条件では使わない方がよかったかを追う。**

過去事例へ後からeventを付ける場合は`retrospective`、あらかじめ観察する場合は`prospective`と区別できる。どちらでも観測のために実作業を歪めない。

## 13. 保存と作業窓

古い材料を削除して文脈を軽くすることを既定にしない。現在のラウンドでは、新材料、触れた古い残差、必要なKJ時点記録、必要なprobe／previewだけを前景化する。

規則が過剰に作用する場合は、適用条件を狭める、優先順位を下げる、補助扱いへ移す、機能を確認して削除する、の順で調整する。動的材料の削減を規則整理の代用品にしない。
