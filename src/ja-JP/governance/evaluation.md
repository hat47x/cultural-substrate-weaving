# 09-evaluation

適用結果を確定する前に、本スキル固有の増分、来歴、過剰適用を確認するときに読む。

## 11. 適用結果を確認する

1. 領域固有手法の**基準線**と、壊してはならない保持事項を置いた。
2. KJ法を使った場合、意味単位、証拠状態、来歴、孤立、未解決を保持した。
3. 文化体系を使った場合、対象側の未処理構造と、体系側から実際に供給された問い・関係を区別して追える。
4. `not_loaded / probe / preview / full / enacted`を区別し、深く読むこと自体を成果にしていない。
5. **探索利用と帰属利用**を混ぜていない。帰属利用では必要な同種性、割当、系譜、規約、遷移条件を検査した。
6. 体系を完成させるために対象を読み替えず、合わない部分を棄却・背景化・保留した。
7. **除去検査を証拠生成と誤解していない。** 体系語彙を外せても、それだけで`target_supported`へ昇格させていない。
8. `target_supported / framework_generated / cross_field_emergent / unresolved`を必要に応じて分け、対象所見には独立した対象側の支持を確認した。
9. 調査・診断では問い・仮説・反証条件へ、生成・構成では構成資源へ、利用目的に合った形で戻した。
10. 転載・派生・複数体系からの再発見を、独立した支持として二重計上していない。
11. 観測された差、利用者の判断、生成AIの評価、測定値を同じものとして扱っていない。
12. 領域固有の正確性・品質・実行可能性を、本スキル自身の評価で代替していない。

## 増分を見る

文化体系の利用回数や対応数ではなく、次のような対象・実作業側の**追跡可能な変化**を見る。

- 具体的な問い、反証条件、調査先が増えた。
- 資料探索や観察対象が変わった。
- KJのまとまり、関係、空白が組み替わった。
- 対象側の材料で新しい所見が支えられた。
- 成果物、研究計画、設計、判断へ実際に採用された。
- 一度採用されたものが、後に撤回・変形・再利用された。
- 古い残差が後の材料で再活性化した。

これらは出来事であり、それだけで「良かった」「悪かった」「CSWの効果だった」とは決めない。誰がその意味づけをしたか、どの材料を根拠にしたかを分けて読む。

これらを単一の品質点へ潰さない。

## 測定と評価を分ける

比較や測定を行った場合は、少なくとも次を分ける。

1. 実際に観察できる差。
2. 記録された測定値。
3. 利用者自身の判断。
4. 生成AIまたは外部評価者の解釈。

生成AIが評価軸を作り、自分の生成物を採点し、その差から方法の有効性を説明した場合、その説明を測定値そのものとして扱わない。評価者が別チャットであっても、AIによる判断であることは変わらない。

後から利用者が訂正・撤回した場合は、その後続履歴を優先して読み、古いAI評価を人的判断へ読み替えない。

## 過剰適用を確認する

- 対象より体系の方が整って見えるほど一対一対応が増える。
- 空いた位置を埋めようとする。
- 体系由来の問いが証拠なしに対象事実へ変わる。
- 派生物が複数の独立支持として数えられる。
- 対立、不可逆性、局所性、非対称性が調和的説明へ回収される。
- 説明量は増えるが、実成果物・調査・判断が動かない。
- 観測のための作業が実課題より重くなる。

徴候があれば、対象側の材料へ戻り、読み込み深度、利用目的、帰属、適用範囲のどこで混同したかを見る。

この確認自体も生成AIによる評価になり得る。可能な範囲で、具体的な対象差分、利用者の訂正、元材料への参照へ戻す。

## 長期案件

必要に応じて`core/iteration.md`と`08-governance-and-records.md`のeventを使う。eventは、まず何が起きたかを記録する。出来事の有用性・害・因果をevent名へ埋め込まず、評価が必要なら判断主体と根拠を別に残す。

後の実作業へ何が残ったかを見るが、それだけで方法の因果効果を証明したとはみなさない。

## 領域固有スキルとの関係

領域固有の品質基準、専門的正確性、実務手順は本スキルでは定義しない。必要に応じて領域固有スキル、資料、規格、実務手順を基準線として用いる。

本スキルの評価対象は、**文化体系およびKJ法を加えた過程で、問い・材料配置・調査・構成・判断にどのような追跡可能な差が生じたかを記録し、その差に対する評価の来歴を混同しないこと**である。
