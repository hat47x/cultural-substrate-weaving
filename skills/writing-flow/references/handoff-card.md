# 受け渡しカード（任意の雛形）

探索や構想を、別の担当・別の製品のハーネスへ渡すときの雛形です。使うかどうか、どの欄を残すかは、渡す側と受け取る側が決めます。保存先・権限・記録形式は、その製品の担当が持ちます。この雛形を、共通の記録基盤や必須の書式にしないでください。

```text
# 受け渡しカード

## 入力と版
- 対象：
- 参照した本文と版（ファイル名と、分かるなら版の識別子）：
- 参照した製品資料と版：
- 文化資料（使った場合）：

## 変えてはいけないこと
- （製品の禁止事項、利用者の条件、変えない数値や結果）

## 前回までの成果
- 場面・構想の要旨：
- 決まったこと（配置・順序・帰属・記録の使い方など）：
- 決まっていないこと（用途など）：

## 名付けた枝
- 枝の一文：
- その枝が指す具体（誰が、何を、どこで）：

## 次の担当への依頼
- 扱ってほしいこと：
- 説明の節を作らず、場面や所作で示してほしいこと：
- 数値や結果は、このカードにある分だけを使い、無い値を補わないこと：

## 受け取る側が決めること
- 保存先、権限、記録の形式：
- このカードのどの欄を残すか：
```

## 使うときの注意

- 枝は一文だけでなく、指す具体まで書く。一文だけだと、人物や物の同一性がずれやすい。
- 数値を補わないと明記する。書いていなければ、受け取り手の判断に委ねられる。
- 版は日付だけでなく、対象の版の識別子まで書く。日付だけでは、受け取り手が資料を開き直すことになる。
- カードに無い製品事実を、受け取り手が推測で足さないように書く。
- カードは私的な作業記録に置き、公開するときは、開発者や関係者への影響を別に確認する。

## 由来の区分を使う場合（任意）

受け渡しカードの各欄に、その内容がどこから来たかを1語だけ添えられます。使うかどうか、どの欄に添えるかは、渡す側と受け取る側が決めます。全部の欄に添える必要はありません。

添える語は、[生成過程の由来を保持する](../../cultural-substrate-weaving/SKILL.md)で区別している4つに対応します。

- `source_material` — 原稿や資料にすでにあること。
- `generated_proposal` — 体系から生まれた問い・仮説・構成案。
- `contact_reading` — 原稿と体系の接触から新しく生まれた読み。
- `author_stated` — 著者が明示した方針や判断と、生成AIが新しく提示した案。

使うときの注意：

- 区分は由来だけを運びます。何が書いてあるかは欄の本文が持ち、語に内容を含めません。
- 「仮説」「問い」「比較」は値にしません。これらは `generated_proposal` の内容として、欄の本文に書きます。
- 全候補へのラベルや一覧表は要りません。必要な欄にだけ添えます。
- この語は、受け取る側が保存先・権限・記録の形式を決めるときの助けです。共通の記録基盤や必須の書式にはしないでください。
