# KJ Atlasのdogfoodを用いて認知上の増分とスキルの共進化を評価する

## 目的

KJ Atlas自身のプロダクト設計やソフトウェア上の課題を、KJ Atlasのキャンバスと生成AIで実際に検討するdogfoodを、`cultural-substrate-weaving`の比較検証の場として利用する。

ここで確かめたいのは、「文化体系を使うと深く見える」という印象ではない。通常の領域分析と比べて、文化体系による構造探索とKJ統合が、対象へ戻した後にも残る問い、関係、反証、空白を増やし、人間とAIの認知制御を改善するかを観察する。

スキル自身の改善もdogfoodと並行して行う。ただし、実験で見つかった問題をそのままスキル規則へ取り込まない。まず`AGENTS.md`で定めたskill / caller contextの境界を適用する。

## 比較する4条件

原則として、同じ未解決のソフトウェア課題と、同じsource snapshotを使う。

| Arm | 外部表象 | cultural-substrate-weaving | 主に見る差 |
|---|---|---|---|
| A | 通常チャット/文書 | なし | 基準線 |
| B | 通常チャット/文書 | あり | スキル単体の増分 |
| C | KJ Atlas | なし | KJ/キャンバスという外部表象の増分 |
| D | KJ Atlas | あり | 組合せによる増分と相互作用 |

必要な代表ケースに限り、人間のみの参照条件を追加してよい。

各armは独立したコンテキストで開始する。他armの途中成果は見せない。新しい資料を発見した場合も、次ラウンドの共通入力にすると決めるまでは、他armへ混入させない。

## 何を「認知能力の向上」と呼ぶか

単一の総合点や「IQ向上」のような一つの尺度にはまとめない。

次の能力が対象側の証拠によって改善したときに、増分があったとみなす。

1. **探索制御**: 最初の仮説や既存分類から離れ、重要な空白、対立、時間変化へ注意を移せる。
2. **意味保持**: 生材料が持つ固有の訴え、異論、孤立、保留を、早すぎる要約で失わない。
3. **根拠制御**: 最終所見から原資料へ戻ることができ、AIの一般論や幻覚を対象事実と区別できる。
4. **反証制御**: 自分やAIが気に入った仮説に反する材料を保持し、必要なら構造を変更できる。
5. **依存校正**: AI提案を適切なときには使い、誤り、無関係、過剰一般化があるときには棄却できる。
6. **再訪制御**: 時間を置いた後や新しい資料が加わった後に、判断過程を再構成して訂正できる。
7. **停止制御**: 対象側の新しい増分がなくなったら終了し、文化体系やKJ操作そのものを目的化しない。

## 主に観測する失敗

- premature classification: 先にある分類へ材料を押し込む。
- anchoring: 最初のAI案、既存ADR、最初の表札へ固定される。
- automation bias: AI提案を根拠確認なしで採用する。
- cognitive offloading: 比較、反証、判断そのものを人間がAIへ委譲する。
- provenance loss: 結論から元資料へ戻る経路を失う。
- dissent collapse: 対立や少数意見を、整った一つの説明へ溶かしてしまう。
- framework capture: 外部体系の語彙や構造が対象を上書きする。
- KJ ritualization: 束ね、表札、図解を行うこと自体が目的になる。
- verbosity illusion: 文章量や論点数の多さを、深さと取り違える。
- endless exploration: 対象側の新しい増分がないのに探索を続ける。

## 1ケースで保存する記録

最低限、次を保存する。

- `Question`: 開いた問い。最初から結論を埋め込まない。
- `Source snapshot`: 使用したrepository commit、issue / ADR、外部資料。
- `Baseline`: Arm Aが何を見つけ、何を見落としたか。
- `Framework candidates`: Arm B/Dで何を、なぜ候補にしたか。適用できなかった候補も残す。
- `Raw KJ material`: C/Dの生カード。出所と、事実 / 解釈 / 不確実性の境界を保つ。
- `Emergent structure`: 束、表札、関係、対立、空白。
- `Surviving findings`: 体系語を除き、対象へ戻した後にも成立した所見。
- `Rejected findings`: 対象へ戻すと成立しなかった所見。
- `AI reliance`: 採用、修正、棄却したAI提案と、その理由。
- `Decision`: issue、ADR候補、実装、追加調査、保留、棄却へどう変換したか。
- `Revisit`: 後日または新資料追加後に、何が維持され、何が変わったか。

## 増分をどう判断するか

### 生存所見

「新しいことを多く言った」ことではなく、次をすべて満たす所見を重視する。

1. 基準線に同じ意味の所見がない。
2. 体系名、象徴語、対応表を除いても成立する。
3. 対象の資料、コード、観察へ戻して支持または反証できる。
4. 設計判断、追加調査、反証、保留のいずれかを実際に変える可能性がある。

件数だけで勝敗を決めない。重要な反証や空白が1件見つかることの方が、多数の軽い論点を増やすより価値を持つ場合がある。

### 保持監査

Arm C/Dでは、最終叙述を元カードまで戻し、次を確認する。

- 孤立カードが不当に消えていないか。
- 対立が「どちらも大切」といった一般論へ溶けていないか。
- 不確実なカードが確定事実へ昇格していないか。
- 重要な出所が失われていないか。
- 最初に「壊さない」とした材料が、最終成果でも実際に守られているか。

## スキル変更への帰属ゲート

実験結果は、次の順で分類する。

### 1. スキル本体に属する

次の場合だけ、`src/<locale>/`の変更候補とする。

- 文化体系から構造候補を得る手順そのものが、繰り返し誤った探索を生む。
- 対象へ戻す検査、removal / substitution、KJ統合、停止、provenanceなどの方法規則が不足している。
- 複数の領域やケースで、同じ方法上の欠陥が繰り返し現れる。

### 2. caller / domain contextに属する

次は原則としてスキルへ入れない。

- ソフトウェア設計で何を良い設計とみなすか。
- セキュリティ、性能、UX、プロダクト戦略などの領域知識。
- 依頼文が結論を誘導していたことによる問題。
- 生成AI一般の文体、追従性、過剰要約を補正する一般ルール。

### 3. KJ Atlasに属する

- カード、出典、異論、履歴、再配置などをUI / APIが保持できない。
- 外部表象が利用者の注意を誤った方向へ誘導する。
- AI proposal-only、人間確定、undo / revisitなどの製品境界が実利用を妨げる。

### 4. モデルまたは実験に属する

- 特定モデルだけに見られる挙動。
- arm間の材料差や順序による汚染。
- blindでない評価者の期待効果。

帰属できない場合はスキルを変更せず、未決として保持する。

## 改善ループ

1. 実課題を4-armで実行する。
2. 差分を生カードとして保持する。
3. KJ統合で、失敗や増分の構造を立ち上げる。
4. 帰属ゲートを通す。
5. スキル固有の欠陥なら、最小限の変更案を作る。
6. 変更を生んだケースへ再適用する。
7. 過去の異なるケースにも再適用し、回帰や過適合を確認する。
8. 増分が再現しなければ、変更を撤回するか、適用範囲を限定する。

変更によって説明量だけが増え、対象側の生存所見や失敗防止が増えないなら採用しない。

## 実験ケースの選び方

閉じた定型作業ではなく、`core/activation.md`の条件を満たす、開いた問題を使う。

初期候補:

- KJ Atlasのプロダクト価値と一次利用仕事。
- AIによる束ね、表札、反対視点の責任境界。
- offline / self-hostとcloud collaborationの製品境界。
- 複雑性と初回利用時の分かりやすさをどう両立するか。
- 第三者の実利用を通じた価値検証設計。
- 実装済みなのに設計文書上では未実装と誤認される「設計 / 実装ドリフト」をどう防ぐか。

一つのテーマに偏らず、技術、プロダクト、運用の異なる課題を含める。

## 現時点では変更しないもの

この文書は評価プロトコルであり、現時点では方法論の正本`src/ja-JP/`を変更しない。

実験結果が得られる前に、「KJ Atlasと併用するための専用規則」や「ソフトウェア開発用規則」をスキルへ追加しない。これらはcaller / domain contextへ置き、スキル固有の増分だけを後から正本へ返す。
