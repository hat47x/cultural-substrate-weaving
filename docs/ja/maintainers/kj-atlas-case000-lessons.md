# KJ Atlas Case 000から得た初期教訓と帰属判定

- Status: Observational / no skill change
- Date: 2026-08-29
- Source: `hat47x/kj-atlas` の既存dogfood `doc_kj_atlas_dogfood_r1.json`〜`r5.json`
- Related: `kj-atlas-cognitive-coevolution.md`

## 目的

KJ Atlasでは、本比較プロトコル以前から、KJ Atlas自身の開発課題をキャンバスで扱うR1〜R5のdogfoodが行われていた。

この既存実践を「方法が成功した証拠」として後付け利用せず、比較実験前の Case 000 として読み、何が観測でき、何がまだ帰属できないかを分類する。

この文書の目的は、**観察が得られたという理由だけでスキルへ規則を追加しないこと**でもある。

## Case 000で観察された正の兆候

### 1. 時間をまたいだ問いの状態が保存された

R1問題提起、R2現状把握、R3本質追求、R4構想、R5具体策が別artifactとして残り、前段の問題が後段で再評価されている。

これは再訪可能な外部表象の価値候補である。

**帰属:** 現時点では主としてKJ Atlas/外部表象。スキル固有増分とは判定しない。

### 2. カードにsourceを残す実践が広く行われた

ADR、issue、設計文書、コード、セッション観察等がカードの出所として記録された。

ただし自由記述sourceは必ずしも不変のcommit/行/識別子へ解決できない。

**帰属:** provenanceを保持すべきという方法原則はスキル中核と整合するが、不変参照の具体的表現はKJ Atlas/領域実装の責務。現時点でスキル変更なし。

### 3. 一部のdogfood論点が後続開発契約へ変換された

例として、R3で問題化された「三要素整合をissueテンプレートが要求していない」という状態は、現在のKJ Atlas issue templateではADR-0067に基づくBusiness/Data/Function欄の追加へ変化している。

**帰属:** 対象側で判断が実行可能な形へ変換された例。ただしKJ Atlas/スキルのどちらが因果的に必要だったかは対照なしでは判定不能。

## Case 000で見つかった評価上の欠落

### E1. 対照条件がない

同じ問いを通常チャット/文書で扱った比較がないため、R1〜R5で得た所見をKJ Atlasまたは本スキル固有の増分へ帰属できない。

**帰属:** experiment design。

**Skill change:** なし。

### E2. 問いの段階構造が先に固定されている

問題提起→現状把握→本質追求→構想→具体策という段階自体が探索方向を与えている。

本スキルの `core/iteration.md` は、こうした問いを代表例として許容するが固定段階とはしておらず、必要なら戻る/飛ぶ/局所深掘りするとしている。

したがってCase 000の固定段階は、現時点では方法欠陥ではなくcaller/experiment側の条件とみなす。

**帰属:** caller / experiment design。

**Skill change:** なし。

### E3. 採用されなかったAI提案が十分に保存されていない

最終カードは残るが、AIが何を提案し、人間がなぜ棄却・修正したかの完全なledgerがない。

このためAI依存校正を評価できない。

**帰属:** KJ Atlas product / experiment instrumentation。

**Skill change:** なし。AI一般の提案ログ仕様を本スキルへ追加しない。

### E4. 時点の異なる内部主張が同じ資料集合に存在する

例:

- R3ではissue templateの三要素欄が不足していたが、現在は追加済み。
- DOGFOOD issueには、初期の不足認識が後段で「実装済みだった」と訂正される例がある。
- 初期対応案が後段で品質上の理由から変更された例がある。

これは時間・遷移を見る能力の実験材料になり得るが、「本スキルを使えば必ず解ける」とはまだ言えない。

**帰属:** target data + experiment opportunity。

**Skill change:** なし。現行スキルには既に時間/遷移を探索する能力があり、まず比較で増分を測る。

### E5. KJ操作の完遂と対象側増分が混同され得る

5ラウンドを完遂したこと自体は、対象について重要な発見が増えた証拠ではない。

**帰属:** experiment evaluation。

**Skill change:** なし。現行 `core/iteration.md` は、抽象度や説明量だけが増え対象側増分がなくなれば停止するとしているため、まずその規則が実際に効くかを測る。

## 現時点でスキルへ追加しない規則

Case 000だけを根拠に、次を `src/<locale>/` へ追加しない。

- ソフトウェアissue/ADR固有のprovenance形式。
- Git commit/line参照を必須とする規則。
- AI proposal ledgerの一般仕様。
- KJ Atlas専用のR1〜R5段階。
- ソフトウェア設計品質の評価軸。
- 「古いissue記述を常に後段まで読む」等のGitHub固有ルール。

これらはcaller/domain/KJ Atlas/experiment側に置く。

## Case 001へ持ち込む教訓

スキル変更ではなく、比較条件へ次を反映する。

1. 同じ問い・同じ資料で基準線と比較する。
2. 固定された問題解決段階を一つのarmだけへ与えない。
3. AIの採用/修正/棄却を保存する。
4. sourceの存在と事実性を分ける。
5. 初期記述と後段訂正が同居する実資料を自然な校正テストとして使う。
6. KJ/体系操作の回数ではなく、対象へ戻して生存した所見で判定する。
7. スキル変更候補は、複数ケースで方法固有の再現性が出るまで保留する。

## 現時点の判定

Case 000は、KJ Atlasと生成AIを組み合わせた自己参照的開発dogfoodに**実用可能性の兆候**があることを示すが、`cultural-substrate-weaving` 固有の増分も、KJ Atlas固有の認知増分も証明しない。

今回スキルを変更しないことは「成果なし」ではない。観察を適切な層へ帰属し、方法論へ不要な規則を取り込まないことが、共進化時の過適合を防ぐ最初の制御結果である。
