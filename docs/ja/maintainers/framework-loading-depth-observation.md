# 文化体系の読み込み深度を長期観察する

- Status: Research protocol / no runtime rule change
- Date: 2026-08-30
- Updated: 2026-09-04
- Related: `v39-deepseek-api-validation.md`, `kj-atlas-cognitive-coevolution.md`, `framework-use-lifecycle-trace.md`

## 目的

v39 Stage Pでは、補助比較として`B1 representation-only - B0 domain/KJ = -0.209722`という結果が得られた。

この結果からは、体系固有の操作を行う前であっても、厚い文化体系の資料を作業コンテキストへ読み込むこと自体が、anchoringや過剰適用につながる可能性を仮説として考えられる。ただし、Stage Pは5ケースだけの診断的pilotであり、Stage Cでは同じ比較を確定していない。この数値や当時の生成AIによる評価だけから、読み込みの深さや非発動の適切さを一般化しない。

現行runtimeは、発動範囲と読み込み深度を別々に扱う。

- 発動範囲: 非発動／限定利用／探索利用。
- 読み込み深度: `not_loaded / probe / preview / full / enacted`。

そのため、この文書でも「使ったかどうか」と「どこまで読んだか」を一つの尺度へまとめない。まずは、**実課題で何を読み、何が起き、その後の問い、KJ再編、成果物、撤回、再利用へ何が残ったか**を長期的に観察する。

## 観察単位

一つの文化体系に接触する機会ごとに、観察上意味がある場合だけ記録する。Living Labの正式なround/eventを残す場合はschema 0.2を正とし、この文書の項目は補助来歴として使う。

### 1. 発動範囲

現行の`activation_scope`に合わせて、次のいずれかを記録する。

- `non_activation`: 文化体系を開かず、領域固有手法やKJなどで作業した。
- `limited_use`: 必要な一部の能力だけを使った。
- `exploratory_use`: 文化体系による探索とKJによる材料統合を往復した。

この値は、そのラウンドで何が起きたかを表す。`non_activation`であることだけから、有用性、害回避、適切さ、失敗を判断しない。

### 2. 実際に読んだ深度

現行`core/activation.md`の読み込み深度に合わせて記録する。

- `not_loaded`: 文化体系を開かなかった。
- `probe`: 対象起点で、別の認知場を開く具体的理由があるかを探った。
- `preview`: 候補体系の主要な認知構造と限界へ軽く触れた。
- `full`: 原典、系譜、象徴、複合構造まで読んだ。
- `enacted`: 体系固有の操作を実際に行った。

Living Labの`framework_contacts`へ記録する場合、接触がなかった`not_loaded`はcontactを作らず、接触した体系について`probe / preview / full / enacted`を記録する。

深度は順番に必ず進む段階ではない。previewでKJへ戻ることも、fullまで読んでもenactedへ進まないこともある。

### 3. 読み込み前の対象側の時点記録

文化体系を詳しく読む前に、必要に応じて次を短く残す。

- 現時点の問い。
- 対象側で確認できている事実や関係。
- 未解決、矛盾、孤立しているもの。
- すでにある領域分析やKJの基準線。

これは、後から文化体系の語彙によって問題設定そのものが置き換わっていないかを確かめるための比較点になる。

### 4. 読み込み後に観測された変化

価値判断を先に置かず、まず何が変わったかを記録する。

- 新しい対象側の問いが生じた。
- 調査先が変わった、または増えた。
- 新しい関係候補や反証条件が生じた。
- KJの束、表札、関係、空白が変わった。
- 成果物や判断へ採用された。
- 後から撤回、再編、再利用された。
- 文化体系の内部説明だけが増え、対象側には新しい変化が確認できなかった。

「有用だった」「害だった」「深く読むべきだった」といった評価を残す場合は、この観測と分け、誰の判断かと根拠を追える形にする。

### 5. anchoring / captureの候補となる観測

次のような出来事が見られた場合は、そのまま観測として残す。

- 文化体系の語彙が対象側の語彙より前面に出た。
- 体系上の位置を埋めることだけを目的とした探索が始まった。
- 対象にはない因果、段階、周期が追加された。
- 最初の体系解釈に反する材料の扱いが変わった。
- 別の体系へ替えたとき、対象側の所見より体系ごとの説明差が大きくなった。
- removal check後に主要所見が残らなかった。

これらが観測されたことと、それを`anchoring`、`framework capture`、害、不適切な適用と評価することは分ける。評価する場合は判断主体と根拠を残す。

### 6. 非発動・縮小・途中終了

次も正規の観測対象である。

- 文化体系を開かなかった。
- `probe`または`preview`で止まった。
- `full`まで読んだが`enacted`へ進まなかった。
- 一度深めた後に読み込みを縮小した。
- 後のラウンドで再び深く開いた。

ここでは「早く止めた方がよかった」「使わなかったことが有用だった」とは記録状態だけから推論しない。止めた理由が利用者判断、AI判断、外部制約などとして残っている場合は、出所を分けた解釈として保持する。

## 長期的に確認する差

読み込み深度との関係は、その場の文章だけでなく、後続ラウンドも含めて見る。

### delayed question value

異なる深度で生じた問いが、後から新しい資料を拾う力にどのような差として残ったか。

### delayed anchoring

一度導入した文化体系の語彙や関係が、後のKJの束、検索対象、判断へどのように残ったか。固定化と評価する場合は、その評価主体と根拠を分ける。

### reconfiguration

後から届いた資料によって、文化体系由来の束や関係が維持、分解、再編されたか。

### artifact lifecycle

文化体系との接触後に生じた構造が、設計、文章、判断などへ採用され、その後に維持、撤回、再利用されたか。

## KJ Atlasのdogfoodで使う場合

既存の4-arm比較を5-arm、6-armへ増やさない。

Arm B/Dで文化体系へ接触した場合に、この文書で定義した読み込み情報を**実験者側の補助来歴**として残す。

これにより、

- skillを使ったかどうか。
- KJ Atlasを使ったかどうか。

という主比較を維持したまま、同じskill armの中で実際の`framework_contacts`と読み込み深度を後から診断できる。

読み込み深度は、実験者が均等に割り当てる処置ではない。そのケースで実際に起きた接触として記録する。したがって、深度別の単純平均、非発動件数、途中終了件数を因果効果や品質スコアとして扱わない。

## 方法論変更へ昇格させる条件

読み込み深度に関するruntime変更を検討する場合も、一つの結果やAI評価から規則化しない。

少なくとも、次を確認する。

- 異なる実課題で、同じ観測パターンが反復している。
- 深度の違いと、その後の問い、KJ再編、成果物、撤回などの差を追跡できる。
- 利用者による直接修正や対象側の証拠と、AIによる解釈を分けている。
- caller、domain、model、experiment固有の条件では説明しきれない。
- 現行runtimeの既存規則の言い換えではない。

反復した観測から、より浅い読み込み、より深い読み込み、あるいは深度を固定しないことのいずれが方法上必要かを改めて判断する。最初から一方向の改善仮説へ寄せない。

## 現時点では変更しないもの

この観察だけを理由に、次を`src/<locale>/`へ追加しない。

- 新しい固定読み込み階層。
- 「一度に読むファイルはN件まで」といった固定上限。
- 特定frameworkの禁止や優遇。
- token量を認知品質の代理指標とする規則。
- B1 representation一般を有害とみなす規則。
- 非発動、浅い利用、深い利用のいずれかを一律に優遇する規則。

## 現時点の判定

現行runtimeには、発動範囲と読み込み深度を分け、対象へ戻りながら縮小、終了、再開できる仕組みがすでにある。

次に必要なのは、どの深度が正解かを先に決めることではない。**実課題で何を読み、その後に対象側で何が起き、どの判断が誰によって加えられたのかを分けて記録すること**である。
