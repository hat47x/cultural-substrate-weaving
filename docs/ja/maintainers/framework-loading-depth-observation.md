# 文化体系の読み込み深度を長期観察する

- Status: Research protocol / no runtime rule change
- Date: 2026-08-30
- Related: `v39-deepseek-api-validation.md`, `kj-atlas-cognitive-coevolution.md`

## 目的

v39 Stage Pでは、補助比較として`B1 representation-only - B0 domain/KJ = -0.209722`という結果が得られた。

この結果からは、体系固有の操作を行う前であっても、**厚い文化体系の資料を作業コンテキストへ読み込むこと自体が、anchoringや過剰適用につながる可能性**を仮説として考えられる。ただし、Stage Pは5ケースだけの診断的pilotであり、Stage Cでは同じ比較を確定していない。

現行runtimeには、すでに次の制御がある。

- 非発動／限定適用／全体適用を分ける。
- 現在の判断に必要なファイルだけを読む。
- 限定適用では、直接必要な参照一つから始める。
- 一括読み込みを避ける。
- frameworkを採用するかどうかと、どこまで深く適用するかを分ける。

そのため、現時点で`index → preview → full`のような新しい固定階層を方法論へ追加する必要はない。まずは、**実課題でどの程度まで資料を読んだときに、何が増え、何が歪んだのか**を長期的に観察する。

## 観察単位

一つの文化体系を適用する機会ごとに、観察上必要な場合だけ次を残す。

### 1. 発動状態

- `none`: 文化体系を使わなかった。
- `limited`: 特定の問い、層、検査だけに限定して使った。
- `full`: 複数の構造探索とKJ統合を組み合わせた。

これは現行`core/activation.md`の三段階に対応する。

### 2. 実際に読んだ範囲

ファイル数そのものはKPIにしない。どの種類の情報まで作業コンテキストへ入れたかを記録する。

- `selection_only`: 体系の候補、用途、不採用条件だけを確認した。
- `application_rule`: 割当、反転、代替、除去など、適用手続きまで読んだ。
- `framework_detail`: 個別体系の要素、象意、歴史的対応などを外部資料から詳しく読んだ。
- `multiple_frameworks`: 複数体系の詳細を同じラウンドで読んだ。

現行repositoryでは、個別体系について厚いdossierを静的層に持っていない。そのため`framework_detail`は、主に動的に取得した外部資料を指す。

### 3. 読み込み前の対象側の時点記録

文化体系を詳しく読む前に、少なくとも次を短く残す。

- 現時点の問い。
- 対象側で確認できている事実や関係。
- 未解決、矛盾、孤立しているもの。
- すでにあるdomain/KJの基準線。

これは、後から文化体系の語彙によって問題設定そのものが置き換わっていないかを確かめるための比較点になる。

### 4. 読み込み後に増えたもの

次を分けて記録する。

- 新しい対象側の問い。
- 新しい調査先。
- 新しい関係候補。
- 反証条件。
- 実成果へ採用された構造。
- 文化体系の内部説明だけが増えたもの。

説明量が増えただけなら、有用な増分とは数えない。

### 5. anchoring / captureの兆候

次のような兆候が見られた場合は記録する。

- 文化体系の語彙が対象側の語彙より前面に出た。
- 体系上の位置を埋めることだけを目的とした探索が始まった。
- 対象にはない因果、段階、周期を暗黙に補った。
- 最初の体系解釈に反する材料の扱いが弱くなった。
- 別の体系へ替えても同じ対象側の所見へ戻らず、体系ごとの説明だけが増えた。
- removal checkを行うと主要所見が残らなかった。

### 6. useful nonuse / early stop

次のような場合も、有効な観察として残す。

- 文化体系を読まない方が明瞭だった。
- `selection_only`の段階で候補を棄却できた。
- 適用手続きまで読んだが、詳細資料へ進む必要はなかった。
- 詳細まで読んだものの増分がなく、対象へ戻った。

使わなかったことを失敗扱いしない。

## 長期的に確認する差

読み込みの深さに意味があったかどうかは、その場の文章だけでなく、後続ラウンドも含めて見る。

### delayed question value

浅い利用または深い利用から生じた問いが、後から新しい資料を拾う力を変えたか。

### delayed anchoring

一度導入した文化体系の語彙が、後のKJの束や検索対象を不必要に固定し続けなかったか。

### reconfiguration

後から届いた資料によって、文化体系由来の束を自然に壊し、組み替えられたか。

### artifact adoption

文化体系を外した後にも残る構造が、実際の設計、文章、判断へ採用されたか。

## KJ Atlasのdogfoodで使う場合

既存の4-arm比較を5-arm、6-armへ増やさない。

Arm B/Dで文化体系を使った場合に、この文書で定義した読み込み情報を**補助観察**として残す。

これにより、

- skillを使ったかどうか。
- KJ Atlasを使ったかどうか。

という主比較を維持したまま、同じskill armの中で「どこまで深く読んだか」を後から診断できる。

読み込みの深さは、実験者が均等に割り当てる処置ではない。そのケースで現行runtimeが実際に選んだ深さとして記録する。したがって、深さ別の単純平均を因果効果として扱わない。

## 方法論変更へ昇格させる条件

次のような所見が、複数の異なる実課題で繰り返し現れるまでは、読み込み階層を静的なruntime規則へ追加しない。

### より浅い読み込みを規則化する候補

- 詳細な文化体系資料を読む前の問いだけで、十分な成果が繰り返し得られる。
- 詳細まで読んだ後に、forcingやprovenance lossが繰り返し増える。
- 早めに止めた方が、後のKJ再編や対象固有性を保てる。

### より深い読み込みを正当化する候補

- 詳細資料を読まなければ生じなかった対象側の問い、反証、構造が繰り返し生じる。
- その所見がremoval checkの後にも残り、実成果へ採用される。
- 後続ラウンドでも、framework captureではなく対象理解として再利用される。

## 現時点では変更しないもの

この観察だけを理由に、次を`src/<locale>/`へ追加しない。

- 固定の`index / preview / full`階層。
- 「一度に読むファイルはN件まで」といった固定上限。
- 特定frameworkの禁止や優遇。
- token量を認知品質の代理指標とする規則。
- B1 representation一般を有害とみなす規則。

## 現時点の判定

現行runtimeには、すでに「必要な参照だけを読む」「限定適用から始める」「増分がなければ停止する」という選択的な読み込みが含まれている。

次に必要なのは新しい規則ではない。**その選択が実課題でどのように働き、どの深さで有用な増分やanchoringが生じるのかを記録すること**である。
