# 文化体系の利用過程を追跡する

- Status: Research observation template / no runtime rule change
- Date: 2026-08-30
- Updated: 2026-09-04
- Related: `framework-loading-depth-observation.md`, `kj-atlas-case001-longitudinal-companion.md`, `v39-deepseek-api-validation.md`

## 目的

文化体系について、**候補に上がったこと、実際に接触したこと、体系固有の操作を行ったこと、対象側の成果へ採用されたこと**を分けて記録する。

これらをすべて「frameworkを使った」とまとめると、次の違いが見えなくなる。

- 候補には上がったが、文化体系へは接触しなかった。
- `probe`や`preview`まで進んだが、対象側の操作は行わなかった。
- `full`まで読んだが、`enacted`へ進まなかった。
- 体系固有の操作を行った後、対象側へ残ったものと残らなかったものが分かれた。
- その場では採用されなかった問いが、後の資料によって再び意味を持った。

この記録は実行手順ではない。`candidate → contact → operation → artifact`を順番に必ず進めるものでも、どこまで進んだかを品質尺度にするものでもない。**実際に何が起きたかと、その出来事への評価を後から取り違えないための補助来歴**である。

Living Labの正式なround/eventを残す場合はschema 0.2を正とし、この文書の記録はその補助情報として扱う。

## 記録単位

一つの文化体系候補について、観察上意味がある場合だけ、一行または短いブロックを残す。候補を網羅的に列挙することは目的にしない。

### `candidate`

その体系が候補に上がった経緯を、対象側の言葉で残す。

- 対象のどの問い、空白、関係に反応したか。
- 利用者から明示的に指定されたのか、探索中に候補となったのか。
- 候補化の時点で、どの材料を参照していたか。

候補に上がっただけなら、ここで止めてよい。候補から外れた場合も、それだけで「不適切な体系だった」と評価しない。

### `contact`

実際に文化体系へどの深度で接触したかを残す。

現行`core/activation.md`とLiving Labの`framework_contacts`に合わせ、接触した場合は次を使う。

- `probe`
- `preview`
- `full`
- `enacted`

文化体系を開かなかった場合はcontactを作らず、round側の`activation_scope: non_activation`などで状態を記録する。

可能であれば、参照した資料、ファイル、外部sourceも残す。読み込み深度の扱いは`framework-loading-depth-observation.md`に従う。

### `operation`

体系固有の操作を実際に行った場合だけ、その内容を残す。

- 操作名または短い説明。
- 何を対象材料として操作したか。
- 操作の途中で縮小、変更、中断した場合に何が起きたか。

資料を読んだだけなら`none`でよい。操作しなかったことを欠落や成功とはみなさない。

### `target_change`

文化体系との接触後に、対象側で観測できた変化を記録する。

例:

- 新しい問いが生じた。
- 調査先が変わった。
- 関係候補や反証条件が生じた。
- KJの束、表札、配置が変わった。
- 設計、文章、判断などのartifactへ採用された。
- 後から撤回、再編、再利用された。
- 対象側では追跡できる変化が確認できなかった。

文化体系の語彙や説明が増えただけの場合も、その状態をそのまま記録してよい。「増分がなかった」「有害だった」といった評価は別に扱う。

### `assessment`

有用性、害、適切さ、因果、停止理由などの判断を残す必要がある場合に使う。

少なくとも、次を分ける。

- 誰の判断か: 利用者、生成AI、外部評価者、その他。
- 何を根拠にしたか。
- 観測された出来事のどこを評価しているか。

生成AIが「ここで止めるのが適切だった」「この体系は不要だった」と判断しても、それを観測事実やrouting規則へ昇格させない。利用者による判断についても、観測された状態とは分けて来歴を残す。

### `reopen_condition`

何が起きたら、この候補、問い、操作を再び開くかを残す。

非採用や途中終了を永久的な除外へ変換しない。後続資料、新しい問い、別の利用者判断によって再接触する余地がある場合は、その条件を残す。

## 短い記録例

```text
framework: 五行
candidate: 自己改善loopの「促進」と「抑制」を別の関係動詞で見る候補として浮上
contact: probe
target_change: feedback loopの抑制側を確認する調査問いが生じた
assessment:
  source: ai
  statement: この時点では詳細対応へ進まなくてもよいと判断した
  evidence: 対象側の問いはprobeだけで具体化した
reopen_condition: 抑制側の実データが追加されたとき、必要ならpreviewへ進む
```

```text
framework: 易
candidate: 状態遷移の不在を検査できる可能性
contact: preview
operation: none
target_change: 遷移条件を明示する問いが残った
assessment:
  source: user
  statement: このラウンドでは体系固有操作まで行わない
reopen_condition: 遷移の時系列資料が追加されたとき再検討する
```

例中の`assessment`は、この文書の補助表記である。正式なLiving Lab記録ではschema 0.2の出所付き`interpretations`などへ対応づける。

## 長期ラウンドでの読み方

この記録を、その場の成功率やframework利用率へ集計しない。

後のラウンドでは、たとえば次を確認する。

- `candidate`だけ残した問いが、後の資料で再び意味を持ったか。
- 接触深度の違いが、後続の検索、KJ再編、artifactへどのように残ったか。
- `operation`した内容のうち、対象へ戻した後にも何が残ったか。
- `target_change`が後から維持、撤回、再利用されたか。
- 当時の`assessment`が後続材料によって支持、修正、撤回されたか。
- 非発動や途中終了が後続ラウンドで変更されたか。

ここで重要なのは、当時の停止判断を正解として再確認することではなく、**観測された履歴と、その時点で誰がどう解釈したかを分けたまま時間を追うこと**である。

## KJ Atlas Case 001での扱い

独立A〜D比較のarmや処置を増やさない。

B/Dで文化体系を扱った場合、必要に応じてこの記録を**実験者側の補助来歴**として残す。blind reviewerには、armや文化体系を推測できる情報を渡さない。

Case 001の独立B/Dは、事前登録済みのskill snapshotへ固定されている。新しいCSW文書やこの記録様式をarmのmodel/operator inputへ追加しない。**run出力と既存run recordを固定した後に、すでに残っている記録から実験者が補助記録を作る。** そのために追加質問、追加の文化体系探索、再実行を行わない。現在の方法論改善が、凍結済みの比較条件へ逆流することを防ぐためである。

長期companion laneでは、重要なframework接触があったラウンドに限って、この来歴を添える。こちらは独立A〜Dとは別のprospective観察であり、使用した`method_ref`も記録する。

## 方法論正本へ昇格させる条件

この記録様式自体は研究用であり、`src/<locale>/`のruntime規則ではない。

単一の`assessment`、非発動、途中終了、AI評価からroutingを狭めない。方法変更を検討する場合は、少なくとも次を確認する。

- 異なる実課題で同じ観測パターンが反復している。
- framework接触と、その後の問い、KJ再編、artifact、撤回などを追跡できる。
- 利用者による直接修正とAI解釈を分けている。
- caller、domain、model、experiment固有の事情では説明しきれない。
- 現行runtimeの既存規則の言い換えではない。

反復する停止判断そのものではなく、その前後で対象側に何が起きたかを材料にする。そこから、routingを広げる、狭める、深度を変える、何も変えない、のいずれも候補として残す。

## 現時点の判定

現段階で必要なのは、文化体系の利用を新しい固定階層へ変えることではない。

> **候補化、接触、操作、対象側の変化、評価を分けて観察し、後続材料による維持・撤回・再活性化まで追えるようにする。**

この区別を保ったまま実データを蓄積し、規則化はその後に判断する。
