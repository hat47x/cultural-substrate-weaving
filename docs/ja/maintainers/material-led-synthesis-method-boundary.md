# material-led-synthesis 方法境界案

作成日: 2026-09-06

## 位置づけ

`material-led-synthesis` は、CSWからKJ法由来の材料統合技能を分離する際の**作業名**である。公開名は未確定であり、`kj-method` をそのまま一般名として使わない。

ここで先に分離するのは `SKILL.md` ではなく、モデルや実装方式が変わっても保持すべき**方法定義**である。

```text
Method Definition
    != Agent Skill realization
    != human procedure realization
    != code-assisted realization
    != Method Application Record
```

この境界は、別系統で整理済みの Cognitive Method Definition / Realization / Application Record と同じ考え方を採る。方法の核と、現在のプロンプト実装を同一視しない。

## 方法定義の目的

異種・不揃い・相互に緊張を含む材料から、分析者が先に分類体系を置かずに意味単位と関係を立ち上げ、元材料へ戻しながら全体像を統合する。

成果は「きれいな分類」ではなく、材料から支持される構造、残った対立、孤立、空白、未解決を、後から再検査できる形で残すことである。

## 適用範囲

適する対象:

- 多数または異種の断片を、既成カテゴリへ押し込めずに統合したい。
- 記事、発言、観察、資料、仮説など、証拠状態の異なる材料が混在している。
- 既知テーマへの分類より、未知の関係や空白を見つけることが重要である。
- 元材料への追跡可能性と、生成AIによる意味の上書き防止が必要である。

単なる既知カテゴリへの仕分け、固定taxonomyへのcoding、少数項目の単純整理だけなら、この方法を優先しない。

## 入出力の最小契約

入力は、元へ戻れる `source material` または、それに追跡可能な `meaning-bearing unit` を基本とする。

出力は少なくとも次を表現できること。

- 意味単位カード
- 束と表札
- 束どうしの関係配置
- 叙述
- 孤立・対立・空白・未解決
- 元材料への来歴
- 派生関係

特定のJSON schemaやUI canvas geometryは方法定義に含めない。

## 不変条件

### 材料主導

材料を既成カテゴリへ流し込まない。分類名を先に置いてからカードを集めない。

### 意味単位

カードは機械的に最小化した断片ではなく、単独で何を訴えているか読める意味単位とする。

分割と結合は同じ境界判断の両方向として扱う。

- 意味の一体性を守る必要が強いなら、結合を保つ。
- 観察と解釈、確認と推測など、証拠状態の継ぎ目を守る必要が強いなら分ける。

文字数や一文一命題を境界判定の代用にしない。

### 意味統合の核

カード化、表札化、上位統合では、粒度は違っても同じ核操作を使う。

1. 境界を決める。
2. 各材料が失えば同じ意味でなくなる核を取る。
3. 必要に応じて元材料をいったん伏せ、核から統合候補を立てる。
4. 元材料へ戻し、歪みを修正する。

この核は、重複整理や精選にも結果として使えるが、枚数削減を目的にしない。

### 戻し検査

統合後は元材料へ戻す。少なくとも次を点検する。

- 元に無い因果を足していないか。
- 人物の内面を補っていないか。
- 不要な一般化をしていないか。
- 評価の向きを変えていないか。
- 推測を断定へ、伝聞を事実へ変えていないか。
- 行為者や責任の向きを落としていないか。
- 意図して落とした差異が記録されているか。

この一覧は閉じたtaxonomyではなく、生成AIで頻出する検査観点である。

### 来歴と二重計上防止

source provenance と discovery route を区別できること。派生カードや同一出来事の転載を、独立した意味反復として二重に重く扱わないこと。

来歴情報は監査に使う。最初の束ねの幾何を、出所・話者・立場・種別で決めない。

### 孤立・対立・空白の保持

どの束にも入らないカードを無理に収容しない。対立を調和へ均さない。配置から見えた空白は、存在する事実としてではなく、次に確かめる問いとして保持する。

### 図解と叙述の往復

関係配置と叙述を別々の最終成果にしない。叙述で新しい関係が生じたら、図解と元材料へ戻す。図解にあって叙述で落ちたものも残差として点検する。

## 既存Skillとの境界

### Affinity Mapping

既存の `think-affinity-mapping` は、既存項目をボトムアップに束ね、後からテーマ名を付け、追跡可能性と外れ値を残す用途に適する。

その仕事だけで足りる場合は、`material-led-synthesis` を呼ばず既存Skillへ委ねてよい。

一方、意味境界の再判定、伏せて立てる統合、戻し検査、証拠状態の継ぎ目、関係配置から叙述への往復まで必要な場合は、同じ方法とは扱わない。

### Concept Mapping

既に概念化された項目を明示的な命題ネットワークへする用途には利用できる。ただし、材料をconcept nodeへ早期変換するため、KJ系のA型図解を常に置換するものではない。

### Evidence vs Inference Sort

完成した主張の独立監査には利用できる。束ねる前に全カードへ種別札を付ける用途には使わない。

## CSWとの接続契約

CSWは材料統合の内部手順を所有しない方向へ移す。

CSW側に残す責務は次である。

- 文化体系から得た構造候補の由来を保持する。
- `canonical cultural source != derived correspondence != exploration routing authority` を守る。
- 文化体系から得た問い・仮説を、対象側の観察と同じ階層へ自動昇格させない。
- 材料統合が必要なとき、独立した方法 realization を呼べるようにする。
- 統合後の対象所見と、framework-generated / unresolved な候補を再び混同しない。

これにより、CSWは文化体系による探索に集中し、材料統合方法の改良や置換をCSWのリリース周期から分離できる。

## Realizationの扱い

最初のAgent Skill realizationは、現行 `src/<locale>/methods/integration.md` を材料に作る。ただし単純コピーはしない。

方法定義に属する不変条件と、CSW固有の接続規則を分けてからSkill化する。

将来、既存の外部Skillがこの方法定義の不変条件と評価fixtureを満たすなら、そのSkillを新しい realization として採用し、独自 realization を廃止または縮小できる。したがって「今は既存Skillへ全面移譲できない」ことを、永続的な独自実装の理由にはしない。

## 評価fixture候補

分離前後および realization 差し替え時に、少なくとも次を同じ材料で比較する。

- 過剰細分化で一つの体験の意味が壊れない。
- 観察と解釈、確認と推測の継ぎ目が潰れない。
- 表札が分類名へ逃げない。
- 元材料に無い因果・内面・一般化・評価方向を付加しない。
- 派生カードを独立反復として二重計上しない。
- 孤立カードと対立を消さない。
- 空白を事実として捏造しない。
- 叙述が図解より根拠なく整いすぎない。
- source provenance と discovery route を区別する。

この評価を満たすことを、Skill名や手順の文面一致より優先する。
