# KJ Atlas Case 001の長期継続チャット観察

- Status: Prospective observational companion / not an experimental arm
- Date started: 2026-08-30
- Related target case: `hat47x/kj-atlas` Case 001 — KJ Atlasの存在目的と一次利用仕事
- Related: `kj-atlas-cognitive-coevolution.md`, `framework-loading-depth-observation.md`, `v39-deepseek-api-validation.md`

## 目的

KJ Atlas Case 001のA〜D比較とは別に、長期間継続している実作業チャットの中で、`cultural-substrate-weaving`が生み出した問い、残差、KJ再編が、時間をまたいでどのように働くかを観察する。

この観察線は、比較実験のarmではない。

長期チャットには、すでに次のような文脈が蓄積している。

- v39 API検証の結果。
- その診断から生じた方法改訂。
- KJ Atlasの価値仮説やdogfoodの来歴。
- 過去ラウンドから持ち越した未解決事項。

さらに、`cultural-substrate-weaving`自身も継続的に更新される。

そのため、この観察線から「skillの因果効果」を推定しない。見るのは、**どの問い、残差、適用判断が、後の実作業へ実際に残ったか**である。

## A〜D比較とは分けて扱う

Case 001のA〜Dは、同じsnapshotと独立したcontextを使う比較条件である。

この長期観察をA〜Dへ含めない理由は次のとおりである。

1. すでに大量のprior contextがある。
2. method snapshotが固定されない。
3. 実験運営者が既存仮説を知っている。
4. 新しいGitHub資料や実装変更が自然に入ってくる。
5. ユーザー自身の判断や問いも時間とともに変化する。

長期観察で有用なパターンが見つかった場合に限り、必要な部分を後からfresh-context比較へ切り出す。

## 対象

Case 001と同じ中心問いを参照する。

> KJ Atlasは、既存のAIチャット、ホワイトボード、質的分析ツール、文書/issue管理では十分に満たしにくい、どの利用仕事のために存在するべきか。現在の設計・実装・dogfoodは、その価値をどこまで実現し、何をまだ実証できていないか。

ただし、長期観察ではこの問いだけに固定しない。後から入った資料によって、問いそのものが変形、分岐、縮小することを許す。

## 重要なラウンドで残す最小記録

毎メッセージを記録する必要はない。KJ構造、方法上の判断、実成果が変わったときだけ残す。

### `round_ref`

その時点の日時または識別子。

### `method_ref`

そのラウンドで実質的に使っていた`cultural-substrate-weaving`のcommitまたはbranch。

途中でmethodが変わった場合、変更前後を同じ条件として扱わない。

### `new_material`

新しく加わったGitHub資料、実装、検証結果、利用者観察、外部資料。

### `reactivated_residual`

以前は結論にならなかった問い、孤立、矛盾のうち、今回の新しい材料によって再び意味を持ったもの。

### `framework_use`

- `none`
- `limited`
- `full`

必要であれば、`framework-loading-depth-observation.md`で定義した読み込み情報も付ける。

### `kj_change`

以前のまとまりが、どのように維持、分解、再編されたか。

### `artifact_or_decision`

issue、ADR、実装、調査計画、文書、採否など、実際に何が変わったか。

### `nonuse_or_harm`

使わない方がよかった文化体系、途中で止めた理由、対象を歪めた操作。

### `reopen_condition`

何が起きたら、次にこの問いを再び開くか。

## 長期観察で特に見るもの

### 1. delayed question value

以前に生じた問いが、後から新しい資料を受け取ったときに初めて役立ったか。

その場では答えにならなくても、後の資料を拾うための受け皿として働いたなら記録する。

### 2. KJ reconfiguration

新しい材料が既存の束へ追加されるだけでなく、以前の束や表札を壊し、別の構造を作ったか。

### 3. artifact adoption

長期探索から生じた所見が、実際のissue、ADR、実装、文書、検証計画へ変換されたか。

### 4. useful nonuse

文化体系を使わない、または限定利用で止める判断が、対象固有性や作業速度を守ったか。

### 5. delayed framework capture

一度導入した文化体系の語彙や関係が、その後の資料まで不必要に同じ型へ読み込ませ続けていないか。

### 6. method evolution

観察結果を受けてskill自身が変わった場合、その変更が後のケースでも本当に役立ったか。

「方法が変わったから結果も良くなった」と自己証明しない。変更後も、失敗や不採用を同じように残す。

## prospective開始前から存在するretrospective材料

prospective観察を始める前の履歴には、少なくとも次がある。

- whole-field / native-enactmentを厚くする方向へ発展したこと。
- v39で、強制native enactmentの負の結果が得られたこと。
- 単発API検証から、ラウンド式KJの長期観察へ重点を移したこと。
- 遅延KJ周回とbounded framework applicationを方法論へ取り込んだこと。
- Stage P `B1 - B0`を確定規則にはせず、読み込み深度の観察課題として残したこと。

これらは後から読み返すretrospective材料であり、成功率や因果効果の計算には使わない。

## prospective開始点

この文書を開発線へ統合した時点以降を、長期観察のprospective期間とする。

開始時点の観察問いは次のとおりである。

1. `limited`適用は、`full`適用より対象固有性を保ちながら、有用な問いを残せるか。
2. 文化体系を詳しく読まない判断が、その後のKJ再編を柔らかく保つか。
3. 文化体系から生じた問いが、数ラウンド後のGitHub資料、実装、第三者利用結果を拾う力を変えるか。
4. 過去の残差が再活性化したとき、前回の表札を正解として固定せず、組み替えられるか。
5. 長期観察から生じた方法変更が、独立したCase 001 A〜Dまたは後続Case 002/003でも必要と確認されるか。

## skill変更へ帰属させる条件

この観察線だけを根拠に、`src/<locale>/`を変更しない。

方法変更候補について、少なくとも次を確認する。

- 長期観察で、具体的な実害または実用上の増分が見られた。
- 同じ問題が別の実課題、または独立比較でも繰り返し現れた。
- caller / domain / product固有の問題ではなく、二つの中核能力に属する。
- 最小限の変更で直せる。
- 変更後に、元ケースとは異なるケースへ戻して回帰を確認できる。

## 現時点の判定

この長期観察の価値は、A〜Dより高い点数を出すことではない。

> **一度の回答では見えない、問いの遅延効果、未解決事項の再活性化、KJ構造の再編、実成果への採用、使わない判断からの学習を、実作業を続けながら観察すること**

にある。

因果比較と長期改善を分けて扱うことで、比較の厳密さを守りながら、ラウンド式KJが本来持っている時間軸も失わない。
