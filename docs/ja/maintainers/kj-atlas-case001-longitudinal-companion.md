# KJ Atlas Case 001の長期継続チャット観察

- Status: Prospective observational companion / not an experimental arm
- Date started: 2026-08-30
- Updated: 2026-09-04
- Related target case: `hat47x/kj-atlas` Case 001 — KJ Atlasの存在目的と一次利用仕事
- Related: `kj-atlas-cognitive-coevolution.md`, `framework-loading-depth-observation.md`, `framework-use-lifecycle-trace.md`, `v39-deepseek-api-validation.md`

## 目的

KJ Atlas Case 001のA〜D比較とは別に、長期間継続している実作業チャットの中で、`cultural-substrate-weaving`が生み出した問い、残差、KJ再編が、時間をまたいでどのように働くかを観察する。

この観察線は、比較実験のarmではない。

長期チャットには、すでに次のような文脈が蓄積している。

- v39 API検証の結果。
- その診断から生じた方法改訂。
- KJ Atlasの価値仮説やdogfoodの来歴。
- 過去ラウンドから持ち越した未解決事項。

さらに、`cultural-substrate-weaving`自身も継続的に更新される。

そのため、この観察線から「skillの因果効果」を推定しない。見るのは、**どの問い、残差、framework contact、KJ再編が、後の実作業、成果物、撤回、再利用へ実際に残ったか**である。

また、観測された状態とその評価を分ける。非発動、限定利用、途中終了などは、それ自体では有用性、害、適切さを意味しない。利用者、生成AI、外部評価者などの判断を残す場合は、観測された出来事とは別の来歴として扱う。

## A〜D比較とは分けて扱う

Case 001のA〜Dは、同じsnapshotと独立したcontextを使う比較条件である。

この長期観察をA〜Dへ含めない理由は次のとおりである。

1. すでに大量のprior contextがある。
2. method snapshotが固定されない。
3. 実験運営者が既存仮説を知っている。
4. 新しいGitHub資料や実装変更が自然に入ってくる。
5. ユーザー自身の判断や問いも時間とともに変化する。

長期観察で意味のあるパターンが見つかった場合に限り、必要な部分を後からfresh-context比較へ切り出す。

## 対象

Case 001と同じ中心問いを参照する。

> KJ Atlasは、既存のAIチャット、ホワイトボード、質的分析ツール、文書/issue管理では十分に満たしにくい、どの利用仕事のために存在するべきか。現在の設計・実装・dogfoodは、その価値をどこまで実現し、何をまだ実証できていないか。

ただし、長期観察ではこの問いだけに固定しない。後から入った資料によって、問いそのものが変形、分岐、縮小することを許す。

## 重要なラウンドで残す最小記録

毎メッセージを記録する必要はない。KJ構造、方法上の判断、実成果が変わったときだけ残す。

Living Labの正式なround/eventを残す場合はschema 0.2を正とする。以下は長期companionで見落としを防ぐための補助観点であり、独自の評価eventを増やすための項目ではない。

### `round_ref`

その時点の日時または識別子。

### `method_ref`

そのラウンドで実質的に使っていた`cultural-substrate-weaving`のcommitまたはbranch。

途中でmethodが変わった場合、変更前後を同じ条件として扱わない。

### `new_material`

新しく加わったGitHub資料、実装、検証結果、利用者観察、外部資料。

### `reactivated_residual`

以前は結論にならなかった問い、孤立、矛盾のうち、今回の新しい材料によって再び意味を持ったもの。

### `activation_scope`

現行Living Labと同じ語彙で、そのラウンドの発動範囲を記録する。

- `non_activation`
- `limited_use`
- `exploratory_use`

この値は状態の記録であり、そのラウンドが良かった、悪かった、適切だったという評価ではない。

### `framework_contacts`

文化体系へ実際に接触した場合だけ、体系名と読み込み深度を残す。

- `probe`
- `preview`
- `full`
- `enacted`

必要であれば、`framework-loading-depth-observation.md`と`framework-use-lifecycle-trace.md`の補助来歴を添える。`non_activation`ならframework contactを作らない。

### `kj_change`

以前のまとまりが、どのように維持、分解、再編されたか。

既存の島がなお材料の核をよく表している場合、新しいカードが加わっただけで組み替えたことにはしない。局所追補で済んだ場合も、その状態をそのまま残す。

### `artifact_or_decision`

issue、ADR、実装、調査計画、文書、採否など、実際に何が変わったか。後から撤回または再利用された場合も追跡する。

### `interpretation`

観測された出来事について、有用性、害、因果、適切さ、停止理由などの判断を残す必要がある場合に使う。

少なくとも、誰の判断かと、何を根拠にしたかを残す。生成AI自身の「使わない方がよかった」「ここで止めたのが成功だった」といった判断は、利用者判断や観測事実と同じ根拠へ溶かさない。

### `reopen_condition`

何が起きたら、次にこの問いを再び開くか。

非発動や途中終了を永久的な除外へ変えず、新資料、別の問い、利用者判断の変更などによって再び開く条件があれば残す。

## 長期観察で特に見るもの

### 1. delayed question value

以前に生じた問いが、後から新しい資料を受け取ったときに再び意味を持ったか。

その場では答えにならなくても、後の資料を拾うための受け皿として働いた場合は、その再活性化を記録する。有用性の評価は必要に応じて別に残す。

### 2. KJ reconfiguration

新しい材料が既存の束へ追加されるだけだったか、以前の束や表札を実際に分解・再編したかを見る。

「新資料が来た」という理由だけで再編を成功条件にしない。維持された島も、意味が変わらなかったという観測として扱う。

### 3. artifact lifecycle

長期探索から生じた所見が、実際のissue、ADR、実装、文書、検証計画へ変換されたか。その後に維持、撤回、再利用されたかも追う。

### 4. framework contact change

文化体系を開かなかった、浅く接触した、深く読んだ、体系固有操作まで行った、といった接触状態が、ラウンドをまたいでどのように変化したかを見る。

ここから「使わない方がよかった」「深く使う方がよかった」と先に結論しない。後続の問い、KJ再編、artifact、利用者修正との関係を追い、評価を加える場合は判断主体を分ける。

### 5. delayed framework capture

一度導入した文化体系の語彙や関係が、その後の資料、検索、KJ配置へどのように残ったかを観察する。

対象側の材料に反して固定化したと評価する場合は、その観測材料と評価主体を分ける。

### 6. method evolution

観察結果を受けてskill自身が変わった場合、その変更後に別の実課題で何が起きたかを追う。

「方法が変わったから結果も良くなった」と自己証明しない。変更後も、維持、失敗、不採用、撤回を同じように残す。

## prospective開始前から存在するretrospective材料

prospective観察を始める前の履歴には、少なくとも次がある。

- whole-field / native-enactmentを厚くする方向へ発展したこと。
- v39で、強制native enactmentに対する負の評価を含む診断結果が得られたこと。
- 単発API検証から、ラウンド式KJの長期観察へ重点を移したこと。
- 遅延KJ周回とbounded framework applicationを方法論へ取り込んだこと。
- Stage P `B1 - B0`を確定規則にはせず、読み込み深度の観察課題として残したこと。

これらは後から読み返すretrospective材料であり、成功率や因果効果の計算には使わない。当時の評価語が残っている場合も、現在のLiving Lab event種別へ読み替えず、歴史的な解釈として扱う。

## prospective開始点

この文書を開発線へ統合した時点以降を、長期観察のprospective期間とする。

開始時点から継続して確認する問いは次のとおりである。

1. 発動範囲やframework contactの深度が異なるラウンドで、その後の問い、KJ再編、artifactにどのような差が残るか。
2. 文化体系を詳しく読んだ場合と読まなかった場合で、後続資料の受け取り方や既存構造の再編にどのような違いが現れるか。
3. 文化体系から生じた問いが、数ラウンド後のGitHub資料、実装、第三者利用結果によって維持、修正、撤回、再活性化されるか。
4. 過去の残差が再活性化したとき、前回の表札を正解として固定せず、必要に応じて組み替えられるか。
5. 長期観察から生じた方法変更候補が、独立したCase 001 A〜Dまたは後続Case 002/003でも方法固有の差として確認されるか。

これらは「浅い方がよい」「深い方がよい」「非発動がよい」といった方向をあらかじめ仮定しない。

## skill変更へ帰属させる条件

この観察線だけを根拠に、`src/<locale>/`を変更しない。

方法変更候補について、少なくとも次を確認する。

- 長期観察で、追跡可能な対象側の変化または利用者による直接修正が見られた。
- 同じ問題が別の実課題、または独立比較でも繰り返し現れた。
- 観測された差と、その差への利用者・AI・外部評価を分けている。
- caller / domain / product / model / experiment固有の問題ではなく、二つの中核能力に属する。
- 現行規則の言い換えではなく、最小限の変更で扱える。
- 変更後に、元ケースとは異なるケースへ戻して回帰を確認できる。

非発動、途中終了、単発の負の結果、生成AI自身の評価だけを根拠に、文化体系や適用可能性を狭める規則を作らない。一方で、観測された材料そのものは捨てず、出所を分けたまま将来の再検討材料として残す。

## 現時点の判定

この長期観察の価値は、A〜Dより高い点数を出すことではない。

> **一度の回答では見えない、問いの遅延効果、未解決事項の再活性化、KJ構造の維持と再編、実成果の採用・撤回・再利用、framework contactの変化を、実作業を続けながら観察すること**

にある。

因果比較と長期改善を分け、さらに観測された出来事とその評価を分けることで、比較の厳密さを守りながら、ラウンド式KJが本来持っている時間軸も失わない。
