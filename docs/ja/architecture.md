# アーキテクチャ

## 価値から実行へ

CSWは、文化体系の視点から対象の本質構造を捉え直し、発見を問い・比較・構成へ具体化する。実行入口は`src/<locale>/ROUTER.md`に置き、問題群の構造読解と体系固有の操作による発見を、依頼に合わせて選べるようにする。両者は往復できる。

詳細は、視点による構造読解、体系選定、発見と具体化、帰属と変換、体系資料、記録へ分ける。親和図法による材料統合と複数回の継続管理は別スキルへ委ね、その内部手順をCSWへ戻さない。領域固有の判断は依頼者の文脈や領域スキルから受け取る。日本語の仕上げには外部のyomiyasuを併用できる。

## ソースと配布

`src/ja-JP/`をCSWの意味上の正本とし、`src/en-US/`には同じ相対パスで翻訳を置く。`adapters/`はプラットフォームごとの設定と説明を持ち、`scripts/build.py`が配布物を生成する。個別の仮説、対応関係、判断記録は利用先のプロジェクトに置く。

```text
src/<locale>/ + adapters/
             |
             v
       scripts/build.py
             |
             +-- OpenAI Skill / Codex Plugin
             +-- Claude Code Plugin
             +-- ChatGPT GPT更新パック
             +-- Microsoft 365限定アダプター
             +-- 正本文書パック
```

OpenAIとClaude Code向けには短い実行入口と、必要に応じて開く参照群を配布する。ChatGPT向けのKnowledgeは、基本姿勢、視点と発見、対象への返却と接続、体系資料、限定的な身体観、記録と振り返りの六群に分ける。Microsoft 365向けは8,000文字以内の自己完結した実行指示に範囲を絞り、方法資料は人間用の参照として区別する。親和図法の内部手順は、どのアダプターにも埋め込まない。

分離スキルの研究実現は`research/skill-prototypes/`に残す。CSW配布物の再生成は、三スキルの公開や英語版の独立査読を意味しない。

## 翻訳と生成物の整合

`i18n/translation-manifest.json`は、英語版が翻訳した日本語正本のハッシュを記録する。日本語だけが更新されれば、翻訳の同期確認は失敗する。生成時にはソース内の参照を配布先の配置に合わせ、参照切れと内容のずれを検査する。

同じ規則を言語やプラットフォームごとに手作業で複製せず、正本とアダプターから再現できる状態を保つ。現在の設計判断は[本質価値から組み直すプロダクト構成](maintainers/value-first-product-design.md)を参照する。
