# アーキテクチャ

## 四つの層

1. **意味上の正本**: `src/ja-JP/`
2. **翻訳**: 正本と同じ相対パスを持つ`src/<locale>/`
3. **アダプター**: `adapters/`に置く、プラットフォーム・言語固有のテンプレート
4. **動的層**: 個別プロジェクトの中で作る仮説、対応関係、棄却案、判断記録

## ビルドの流れ

```text
src/<locale>/ + adapters/<locale>/
             |
             v
       scripts/build.py
             |
             +-- OpenAI Skill
             +-- Claude Code plugin
             +-- ChatGPT GPT更新パック
             +-- Microsoft 365 Copilot Agent
             +-- 正本文書パック
```

## 翻訳を同期する仕組み

`i18n/translation-manifest.json`には、日本語正本の各ファイルについて、英語版がどのハッシュ時点を翻訳したものかを記録します。日本語正本だけを更新して英語版が追随していない場合、検証は翻訳を「古い」と判定して失敗します。

## なぜ成果物を生成するのか

同じ規則を言語ごと、プラットフォームごとに手作業で管理すると、少しずつ内容が分岐します。生成処理を使うことで、共通の言語資源とアダプターから、各プラットフォーム向けの成果物を同じ手順で再現できます。
