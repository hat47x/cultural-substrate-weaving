# Jain sevenfold predication — discovery-value comparison

Status: qualitative retrospective desk comparison / no blind experimental finding

## Question and anti-circular method

Capability overlap alone cannot decide runtime adoption. Compare three entrances to the **same fixed material**, preserving the sequence:

1. **Generic ex-ante**: ordinary requirements / incident / performance review, without Jain vocabulary, perspective-binding instructions, or a preselected claim matrix.
2. **Jain contact**: use the sourced native relation of standpoint-conditioned predication, with source provenance and no automatic truth promotion.
3. **Post-contact matched specialist**: reconstruct the strongest ordinary claim/scenario matrix after the job is identified.

Do not confuse 3 with 1. Record the target-side **newly selected question**, not the number of framework labels or rows produced.

This is an analyst-authored comparison of what documented standard methods call for, not a blinded experiment showing how reviewers actually behave. The decision below is bounded to the two tested SIer targets and is open to falsification.

## Fixed target A — migration status

Initial question: "Is the platform migration complete? Yes / No."

Target data: read migrated, write not migrated, batch partial, archival explicitly excluded.

### Generic ex-ante path

Even without a cultural framework, an ordinary migration/requirements review needs a completion criterion, a scope, a level (program vs component), and source evidence before issuing a valid status. Once the supplied target facts conflict, a normal review has a direct reason to split by component and mark out-of-scope separately.

NASA requirements guidance calls for correct system level, explicit assumptions, clear predicate, completeness, and meaningful don't-care conditions.

### Jain contact and target return

A Jain-derived pass binds each assertion to component, time, and declared criterion, then keeps unresolved/inexpressible residuals distinct. This yields a coherent claim matrix but **does not uncover a missing SIer job** that the initial request and ordinary review would fail to select.

Catuṣkoṭi still differs: it deliberately asks "both / neither / wrong predicate" *before* repairing the yes/no frame. Jain's main move here is the subsequent conditioning of assertions, naturally supplied by the ordinary scope review once the conflict is visible.

## Fixed target B — API performance

Initial claim: "The API is fast." Operations has internal p95=120ms; support has mobile route p99=1.8s (hypothetical observations).

### Generic ex-ante path

A performance review must ask which route, actor or workload, percentile, unit, observation window, SLO/threshold, and measurement evidence support "fast". A stakeholder-independent aggregate cannot be defended until these are specified. Ordinary requirements guidance explicitly asks for measurable performance values and testability; a behavior-driven example begins from preconditions and verifies an observable outcome.

### Jain contact and target return

The Jain pass also conditions both propositions by standpoint/metric and marks the cross-route global statement unresolved. The de-bound result is useful, but the target *already* demands metric and scope qualification in an ordinary professional review. No additional cross-standpoint comparison or vocabulary gap is exposed by the framework in this fixture.

## Alternative / strongest-case test

Could `indescribability-probe` supply a unique discovery? The studied targets offer:

- not applicable: migration excluded scope;
- undefined predicate: "complete" or "fast" lacks a scope/criterion;
- not yet supported: aggregate status lacks evidence.

Conventional review can retain these as separate residuals rather than forcing a false answer. Treating them as seven ontological statuses or as mystical ineffability would **reduce** accuracy.

A future target with a real representational failure that ordinary requirements / CSW core / Catuṣkoṭi do not prompt is an explicit reopening condition. The present fixtures do not demonstrate that.

## Contact-path comparison

| Cognitive job | Generic ex-ante SIer review | Jain contact | Incremental discovery |
|---|---|---|---|
| identify affected perspective / actor | stakeholder / component / customer route | standpoint-conditioned claim | no clear increment |
| bind asserted property to time/metric/condition | requirements / performance criteria | qualified assertion | no clear increment |
| reconcile apparently conflicting claims | align observation and scope | standpoint comparison | no clear increment |
| rotate contexts | multi-scenario comparison after initial disagreement | perspective rotation | no clear increment on the fixed targets |
| preserve non-expressible residual | TBD/TBR, wrong predicate, N/A, evidence gap | indescribability probe | no clear increment on fixed targets |

## Decision and limits

The **discovery-overlap** counter-hypothesis is supported on these two SIer task families. The same cognitive job is selected from ordinary target conditions before framework contact, and the de-bound result does not expose a further target-side question.

Together with capability overlap, this **supports removal from general default runtime**, while keeping a sourced `profile-ready` candidate for explicitly requested Jain studies, comparative standpoint analysis, and future tasks that show a real discovery residual.

This is a product decision based on limited qualitative evidence, **not** proof that Jain philosophy adds no discovery value generally. Neither near-neighbor difference from Catuṣkoṭi nor cultural diversity alone proves default-runtime value.
