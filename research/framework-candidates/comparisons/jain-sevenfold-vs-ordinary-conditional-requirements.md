# Jain sevenfold predication vs ordinary conditional requirements review

Status: adopted-core requalification / capability-overlap comparison

## Question

Once the cognitive job is known — qualify a strong assertion by context, conditions, and evidence — can ordinary analysis reproduce the de-bound Jain operations?

This asks about **capability**, not whether the method would have been selected before framework contact.

## Fixed targets

A. The migration dashboard described in `research/framework-candidates/worked-examples/jain-sevenfold-predication.md`.

B. The "API is fast" claim with internal p95 and mobile-facing p99 observations in that same file.

## Matched ordinary baseline

NASA's requirements guidance asks authors to use correct system levels, one subject/predicate per requirement, explicit assumptions, defined performance parameters, unambiguous wording, complete scope, and verifiable acceptance conditions.

- NASA, *How to Write a Good Requirement*: https://www.nasa.gov/reference/appendix-c-how-to-write-a-good-requirement/

Cucumber/Gherkin makes `Given` context / preconditions, `When` event, and `Then` observable result explicit; scenario outlines/examples cover alternative initial conditions and observations.

- Cucumber, *Gherkin Reference*: https://cucumber.io/docs/gherkin/reference

A strong conventional review can therefore produce:

| De-bound Jain operation | Ordinary target-side method | Residual capability on fixtures |
|---|---|---|
| perspective-binding | stakeholder / route / component / time scope | none |
| qualified-assertion | condition-bound requirement / Given-When-Then scenario | none |
| contradiction-decomposition | align scope, metric, version, and observation window before comparing | none |
| perspective-rotation | scenario matrix over segments / components / stakeholders | none |
| indescribability-probe | flag undefined predicate, non-applicable state, unresolved term / new vocabulary needed | low; not the tradition's philosophical notion of inexpressibility |

For target A, the ordinary matrix distinguishes migrated read path, unmigrated write path, partial batch path, and excluded archival scope. For target B, it separates p95/internal traffic from p99/mobile traffic and does not infer global performance from either observation.

## Boundaries

This comparison does **not** identify Jain standpoint doctrines with Gherkin, equate sevenfold predication with software test cases, or assert that all scholarly readings of syāt mean "if".

Modern requirements practice reproduces the **de-bound target operations** for these particular SIer targets. The traditional metaphysical/epistemic structure remains independently meaningful.

## Result

The matched ordinary method reproduces the tested target-side operations with little or no capability residual.

This does not itself justify demotion. The stronger discovery-value question asks whether an unprompted ordinary review of the same targets would select these dimensions **before** Jain contact.
