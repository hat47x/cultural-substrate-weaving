## Fixed target

A policy sentence appears in meeting notes, a chat message, and a later summary.

At first glance, the target can be narrated as:

> Three artifacts support the same policy claim.

The actual lineage is:

```text
meeting statement

  -> quoted by chat
  -> summarized in memo
```

The memo also changes one phrase.

## Ex-ante baseline A — CSW core before framework selection

No cultural framework has been opened.

CSW's always-on governance already requires:

- origin and source references to remain traceable;
- reposts and derived records from one source not to count as independent support;
- discovery path and evidence-source independence to be distinguished;
- framework-generated material not to become target-supported without independent target evidence;
- observation, recorded value, user judgment, and AI interpretation not to be conflated.

Applied directly to the target, these rules produce:

- the three documents must not be counted as three independent supports;
- the common origin must be identified;
- the wording change must remain traceable to a later transformation;
- source-chain evidence and proposition evidence must be recorded separately.

The central hadith-derived discovery job is therefore already active before framework selection.

## Ex-ante baseline B — ordinary provenance practice

A generic provenance review naturally asks:

- what entity was derived from what?;
- was content quoted or revised?;
- who generated each entity?;
- are two artifacts independent or descendants of one source?;
- what changed between revisions?;
- is the provenance assertion itself verified?;
- what does provenance establish, and what still requires content-side evidence?

W3C PROV explicitly models derivation, quotation, revision, agents, and provenance bundles.

C2PA provides an especially clear modern boundary: verifiable provenance can establish origin/history/authenticity properties, but provenance alone does not establish that the represented content is true, accurate, or factual.

Sources:

- W3C PROV Model Primer: https://www.w3.org/TR/prov-primer/
- W3C PROV Overview: https://www.w3.org/TR/prov-overview/
- C2PA Guiding Principles: https://c2pa.org/principles/
- C2PA Explainer: https://c2pa.org/specifications/specifications/1.3/explainer/_attachments/Explainer.pdf

## Hadith contact

The de-bound hadith pass asks:

- what is the content?;
- what is the claimed transmission path?;

- which handoff is observed, asserted, missing, or reconstructed?;
- which wording variants align with which path?;
- does strong provenance evidence support only lineage, or also the proposition itself?

These are coherent and useful questions.

## Product-specific discovery test

Hadith has unusually high **historical relevance to CSW's design values**.

But runtime discovery value is not the same as design-history relevance.

For the current product, the key hadith-inspired safeguards have already been promoted into always-on core rules:

```text
same origin != independent support
provenance != content truth
discovery path != evidence source
asserted edge != verified edge
```

Because core rules run before framework selection, hadith contact cannot claim first discovery of those distinctions in ordinary CSW execution.

The framework may still make the ideas vivid or memorable, but mnemonic reinforcement alone does not justify default framework-selection complexity.

Every one of these questions is already selected by the normal CSW provenance/evidence discipline or ordinary provenance modeling.
