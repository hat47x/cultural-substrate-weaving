# Classical stasis theory vs ordinary issue triage

Status: runtime requalification / same-target ordinary-baseline comparison

## Purpose

Classical stasis theory is already in the CSW runtime corpus. This comparison applies the current Registry standard retroactively:

> after de-binding, does the framework still add a target-relevant cognitive operation that a strong ordinary incident / issue triage does not already provide?

The target is the existing release-incident worked example.

## Fixed target

After a release incident:

- one participant says rollback never happened;
- another says the action should not count as a rollback;
- a third accepts the event but argues it was justified;
- a fourth argues that only the incident commander had authority to decide.

The current stasis pass separates fact, definition, evaluation, and competence / procedure, and asks what evidence would settle each question.

## Condition A — stasis-derived pass

The de-bound operations are:

1. separate apparently unified disagreement into issue types;
2. avoid evaluating an event whose occurrence is still disputed;
3. detect a shift from occurrence to naming / classification;
4. isolate evaluation after the underlying event is conceded;
5. separate authority / forum / timing / procedure from the substantive issue;
6. detect when an interlocutor answers a different issue type from the live one;
7. map each issue type to the evidence that can answer it.

The incident therefore produces distinct target questions:

- did rollback actually occur?
- what operational definition counts as rollback?
- if it occurred, was it justified?
- who had authority to decide and under which procedure?

## Condition B — strong ordinary incident / issue triage

Use no cultural framework.

Create an issue table in target vocabulary:

| Field | Question |
|---|---|
| observed event | what happened according to logs and timeline? |
| classification | what operational definition or category applies? |
| evaluation | was the action acceptable under the applicable criteria? |
| authority / process | who could decide, under which runbook or escalation rule? |
| evidence | which record can answer this row? |
| unresolved | what remains open after the available evidence is checked? |

Then require every claim or rebuttal to name the row it answers. If a response moves from one row to another, record an issue-type switch rather than treating it as a refutation.

This ordinary baseline produces the same questions and the same evidence separation.

## Operation-by-operation comparison

| De-bound operation | Stasis-derived pass | Ordinary issue triage | Residual difference for this target |
|---|---|---|---|
| dispute-state separation | fact / definition / quality / procedure | event / classification / evaluation / authority-process rows | none |
| fact-before-evaluation | conjectural issue before quality | establish event record before judging acceptability | none |
| definition-shift audit | fact -> definition shift | event -> classification row switch | none |
| quality-after-concession | isolate evaluative issue after fact concession | evaluate only after event/classification state is explicit | none |
| competence / procedure | translative or procedural issue | authority, forum, escalation, timing, runbook ownership | none |
| stasis-switch detection | identify movement between issue states | require each response to name the issue row it answers | none |
| evidence relevance | evidence depends on issue type | evidence column per issue row | none |
| historical rhetorical taxonomy | classical provenance and variant history | absent | provenance only; no extra target-side operation |

## Near-neighbor boundary

The existing distinctions from Nyāya and scholastic disputed-question remain real:

- Nyāya examines whether a reason supports a conclusion;
- disputed-question preserves objections through pointwise replies;
- stasis locates the kind of issue currently disputed.

However, difference from other cultural frameworks is not sufficient for runtime retention. The ordinary issue-triage baseline already reproduces the target-relevant stasis operations.

## Result

For the tested SIer disagreement target, the ordinary-baseline counter-hypothesis survives.

The useful output of the stasis pass is an issue taxonomy plus switch detection. A strong incident / requirements / decision-review process can represent those distinctions directly without importing the historical rhetorical framework.

No additional target-side question remains after the cultural vocabulary is removed.

## Runtime consequence

The current evidence does **not** support keeping classical stasis theory as a general default runtime framework for SIer disagreement analysis.

Preserve the profile, source basis, worked examples, and historical boundary because stasis theory remains relevant when:

- the user explicitly asks for classical rhetoric or stasis analysis;
- the target is historical rhetoric, legal-rhetorical history, or comparative argumentation;
- a future target demonstrates a distinct operation not reproduced by ordinary issue triage.

For ordinary incident, design, policy, or review disputes, prefer direct target-language issue triage.

## Product-value consequence

Stasis is a clear example of a culturally grounded framework whose historical structure is useful to understand but whose tested de-bound runtime work can be supplied directly by an ordinary engineering review practice.

Removing it from the default runtime would reduce framework-selection overhead without reducing the tested cognitive coverage.
