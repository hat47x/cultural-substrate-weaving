# Catuṣkoṭi vs Jain sevenfold predication

Status: runtime requalification / near-neighbor differentiation

## Purpose

Catuṣkoṭi and Jain sevenfold predication can both appear when a target resists a simple yes/no answer.

They should not be treated as interchangeable multi-valued logics.

## Catuṣkoṭi

Primary cognitive job:

> challenge the binary proposition frame itself.

Starting from P, probe:

- P;
- not-P;
- both;
- neither.

For CSW, "both" and "neither" are not automatically truth values.

They are prompts to inspect:

- mixed time;
- mixed scope;
- different actors or layers;
- missing categories;
- a predicate that does not apply.

## Jain sevenfold predication

Primary cognitive job:

> bind assertions to explicit standpoint, circumstance, or aspect.

The useful de-bound questions are:

- under which condition is this claim valid?;
- under which condition is the opposite claim valid?;
- which aspect or time changes the predication?;
- what remains inadequately expressible under the current vocabulary?

## Same migration target

Target:

> Is the platform migration complete? Yes / No.

### Catuṣkoṭi pass

First asks whether the yes/no frame survives:

- complete for read path;
- incomplete for write path;
- mixed at aggregate level;
- not-applicable for an excluded subsystem.

The gain is recognizing that one Boolean predicate is malformed at the current scope.

### Jain pass

Once dimensions are visible, it asks for conditioned assertions:

- complete with respect to public read traffic;
- incomplete with respect to write processing;
- not evaluated for the excluded archival subsystem.

The gain is binding each assertion to its standpoint / scope.

## Non-substitutability

Catuṣkoṭi cannot be reduced to "add conditions to each claim."

Its strongest runtime role is earlier: forcing the original binary frame to confront both and neither.

Jain predication cannot be reduced to "four corners plus extra labels."

Its strongest role is making the omitted condition or standpoint part of the assertion.

## Runtime implication

Near-neighbor distinctness supports a clean selection boundary:

- use catuṣkoṭi when the missing job is **breaking the proposition frame**;
- use Jain predication when the missing job is **qualifying an assertion by standpoint or condition**.

This distinction does not by itself prove runtime value. Catuṣkoṭi still must show discovery value beyond ordinary requirements/state review.
