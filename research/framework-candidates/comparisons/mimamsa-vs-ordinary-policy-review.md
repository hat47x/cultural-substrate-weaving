# Mīmāṃsā hermeneutics vs ordinary policy / requirements review

Status: runtime requalification / same-target ordinary-baseline comparison

## Purpose

Mīmāṃsā is already in the CSW runtime corpus. This comparison applies the current Registry standard retroactively:

> after de-binding, does the framework still add a target-relevant cognitive operation that a strong ordinary policy / requirements review does not already provide?

The target is the existing deployment-policy worked example.

## Fixed target

A deployment policy says:

> For production changes, obtain approval. Emergency changes may proceed immediately when service restoration cannot wait. Record the reason afterward.

The current Mīmāṃsā pass asks:

- whether "record the reason afterward" belongs only to the emergency exception or to all production changes;
- which phrases syntactically depend on which others;
- which readings are semantically workable;
- what condition activates the exception;
- whether approval and emergency execution conflict under the same actor, time, condition, and purpose;
- which interpretation is explicit and which part is supplied from context.

## Condition A — Mīmāṃsā-derived pass

The de-bound operations are:

1. identify one or more prescriptive units;
2. use syntactic expectancy to test attachment;
3. use semantic fitness to reject impossible or strained connections;
4. distinguish explicit wording from context-supplied interpretation;
5. decompose apparent norm conflict by actor, action, time, condition, and purpose.

The pass produces a scope map and unresolved interpretation questions.

## Condition B — strong ordinary policy / requirements review

Use no cultural framework.

Normalize each normative statement into:

- subject / actor;
- action;
- trigger or condition;
- effect or obligation / permission;
- exception;
- duration or temporal boundary;
- follow-up action;
- source text span;
- explicit versus inferred linkage.

Then perform ordinary grammatical and requirements review:

1. attach modifiers to the clauses they grammatically and semantically govern;
2. identify exception scope;
3. mark any condition or linkage not explicit in the text;
4. compare two rules only when actor, action, time, condition, and purpose overlap;
5. return ambiguity to the policy owner instead of manufacturing one interpretation.

This produces the same target questions:

- does "record the reason afterward" apply only to emergency changes?
- what exactly activates the emergency exception?
- can approval and emergency execution both apply to the same case?
- which links are written and which are inferred?

## Operation-by-operation comparison

| De-bound operation | Mīmāṃsā-derived pass | Ordinary policy / requirements review | Residual difference for this target |
|---|---|---|---|
| prescriptive-unit detection | determine one vs multiple prescriptions | segment normative statements and exception clauses | none |
| purpose / action unity | test whether clauses serve one prescription | group by actor, action, trigger, effect and follow-up | none |
| syntactic expectancy | inspect what expressions require or modify | grammatical attachment / dependency review | none |
| semantic fitness | reject semantically unworkable connection | domain-semantic consistency review | none |
| explicit vs context-supplied | preserve supplementation boundary | mark explicit vs inferred requirements | none |
| norm-conflict decomposition | compare same actor/action/time/condition/purpose | ordinary rule-overlap / conflict review | none |
| Bhāṭṭa / Prābhākara theoretical background | preserves historical interpretive alternatives | absent | historical provenance, not a new target-side operation |

## Near-neighbor boundary

The existing comparison with classical stasis theory and Nyāya remains valid.

- stasis locates the type of dispute;
- Nyāya exposes the bridge from reason to conclusion;
- Mīmāṃsā focuses on how prescriptive text is connected and scoped.

However, being different from those cultural frameworks is not enough for runtime retention. The ordinary baseline already reproduces the target-relevant Mīmāṃsā operations.

## Result

For this deployment-policy target, the ordinary-baseline counter-hypothesis survives.

The Mīmāṃsā-derived pass is historically coherent and provides a useful intellectual lineage for thinking about prescriptive texts, but after de-binding it does not add a distinct operation beyond a strong policy / requirements review.

The same conclusion also applies to the second runbook example: exception attachment, duration, recovery condition, follow-up action, explicit wording, contextual supplementation, and rule conflict can all be represented directly in an ordinary structured review.

## Runtime consequence

The current evidence does **not** justify keeping Mīmāṃsā as a general runtime framework merely for policy, runbook, or requirements interpretation.

A runtime removal should preserve the research profile and source basis, because Mīmāṃsā remains a legitimate research substrate and may still matter when:

- the target is comparative hermeneutics;
- the user explicitly asks for Mīmāṃsā;
- the historical interpretive tradition itself is part of the subject;
- a future target demonstrates a distinct operation not reproduced by ordinary policy review.

For ordinary SIer analysis, prefer direct requirements / policy normalization.

## Product-value consequence

Runtime cultural diversity is not itself the product goal.

If a framework's de-bound operation is fully reproduced by a simpler ordinary method, retaining it in the default runtime library adds selection complexity and cultural overhead without increasing what CSW can actually ask or distinguish.

This comparison therefore supports demoting Mīmāṃsā from general runtime adoption while preserving it as a sourced `profile-ready` research candidate.
