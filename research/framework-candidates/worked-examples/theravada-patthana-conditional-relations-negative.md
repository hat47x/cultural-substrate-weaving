# Theravāda Paṭṭhāna conditional-relations negative example

Status: hypothetical / research-only

## Target

A three-step offline export is failing:

```text
generate file
  -> compress file
  -> upload file
```

Logs show that compression never starts because file generation exits with an I/O error.

There is currently one observed upstream failure and one straightforward sequential dependency.

## Why the framework should not be forced

A differentiated multi-condition network is not needed yet.

Introducing several relation modes, reciprocal-support questions, or a large set of possible conditions would create analysis work that the target material does not justify.

The ordinary target-side result is simpler:

1. inspect the I/O failure;
2. verify that successful file generation is a prerequisite for compression;
3. rerun the sequence;
4. reopen broader condition analysis only if the failure remains unexplained or multiple independent conditions appear.

The correct CSW result is non-activation.

## Stop condition

Stop or weaken Paṭṭhāna contact when:

- the target is adequately represented by one short sequential chain;
- relation modes have to be invented before the target exhibits them;
- analysts begin mapping every dependency to a historical paccaya label;
- a typed dependency graph already captures every useful target-supported distinction;
- network density increases while concrete tests or observations do not.

Non-activation is preferable to replacing one obvious failure with an ornate causal diagram.
