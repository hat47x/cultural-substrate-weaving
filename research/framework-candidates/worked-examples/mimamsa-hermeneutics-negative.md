# Mīmāṃsā hermeneutics non-activation example

Status: negative example / runtime requalification support

## Target

A policy engine stores each rule as a structured object with explicit fields:

- actor;
- action;
- trigger condition;
- effect;
- exception scope;
- duration;
- follow-up action;
- priority;
- source requirement ID.

The schema rejects missing attachment information. Tests cover exception scope and rule conflicts.

## Why Mīmāṃsā should not be activated

The target already makes the relevant distinctions explicit.

There is no unresolved question about:

- where one prescription begins or ends;
- which phrase modifies which rule;
- whether a link is explicit or supplied by context;
- whether two rules conflict under the same actor, action, time, condition, and purpose.

Applying Mīmāṃsā here would restate distinctions already represented directly by the target.

## Correct CSW result

Use ordinary schema validation and rule-conflict tests.

Do not activate Mīmāṃsā merely because the material is normative or contains rules.

Reopen the framework only if the target returns to ambiguous natural-language prescriptions whose unit, attachment, supplementation, or conflict cannot be made explicit by the existing policy representation.

## Boundary

Non-activation does not imply that Mīmāṃsā is historically unimportant or analytically invalid.

It means only that this target already supplies the de-bound operations directly, so framework contact would add cultural provenance without adding a new cognitive job.
