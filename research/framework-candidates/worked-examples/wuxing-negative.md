# Wuxing non-activation example

Status: negative example / runtime requalification support

## Target

A service model already stores:

- directed influence edges;
- edge type: amplifying, constraining, or unknown;
- confidence and evidence per edge;
- reinforcing and balancing loop IDs;
- separate graph snapshots for normal load, spike, recovery, and degraded mode;
- intervention observations showing which links change after throttling or backoff adjustments.

## Why Wuxing should not be activated

The target already externalizes the complete de-bound cognitive job.

There is no missing operation around:

- separating enabling and constraining relations;
- preserving edge direction;
- finding feedback loops;
- asking whether one node has different roles on different edges;
- finding a missing relation;
- comparing relation patterns over time.

Mapping the existing graph onto five phases would add a cultural representation without generating another target-side question.

## Correct CSW result

Use the target's signed / typed causal-loop model.

Do not activate Wuxing merely because the target contains cycles, feedback, or balancing behavior.

Reopen the framework only when its historical structure is itself relevant, the user explicitly requests it, or a future target demonstrates a de-bound operation that survives strong ordinary-baseline comparison.

## Boundary

Non-activation does not claim that Wuxing and modern system dynamics are historically or conceptually identical.

It means only that this target already performs the tested de-bound review operations directly.
