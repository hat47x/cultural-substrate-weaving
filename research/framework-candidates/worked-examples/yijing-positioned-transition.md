# 易経：配置と中間遷移を対象へ戻す構成例

状態：仮想の業務システム例。対象の実行結果・採用の有効性は未観測。

## 固定対象

あるデータ移行で、旧形式から新形式へ段階的に切り替える。作業者は六つの二値条件を記録することにした。以下の六項目は**対象の設計者が作った仮のモデル**であり、六爻の伝統的な意味・卦名との対応ではない。

| 下から数えた位置 | 二値で表した対象条件 | 1の意味 |
| --- | --- | --- |
| 1 | read compatibility | 旧／新両方を読める |
| 2 | write compatibility | 両形式への書込みを許す |
| 3 | dual write | 新旧への同時書込みを行う |
| 4 | backfill check | 過去分の検証が完了している |
| 5 | read switch | 新形式を主たる読込先にする |
| 6 | rollback route | 旧形式へ戻る手順が利用可能 |

ここでは、初期の仮置きを下→上で `(1,1,0,0,0,1)`、変更後の仮置きを `(1,1,1,1,0,1)` とする。状態が現実に存在するか、六項目が独立しているか、どの中間状態が安全かは未確認。

## 体系への接触：位置と変化の区別

六つの位置を保持し、第3と第4を切り替える。**固定された二値の反転だけ**なら、反転する順序が違っても最終ベクトルは同じである。

| 経路 | 初期 | 中間 | 終点 |
| --- | --- | --- | --- |
| 第3位置→第4位置 | `110001` | `111001` | `111101` |
| 第4位置→第3位置 | `110001` | `110101` | `111101` |

*ベクトルは位置1～6を左から右に表す。爻の方向を下から上とするのは操作の位置指定であり、上記二値の業務上の意味はCSW側の割当である。*

同じ終点に到着することと、**途中に通った状態が同じであること**を混同しない。反転の可換性は有限二値ベクトルの数学的性質であり、現実の変更作業が可換・安全である保証ではない。

## 生成した問いを、対象側に戻す

- `111001`（dual-write開始・backfill未検証）を通ると、二形式の整合性に関して何を確認すべきか。
- `110101`（backfill検証済み・dual-write未開始）を通る間、新しい注文更新が発生した場合、再同期は必要か。
- read switchが0の間、rollback routeが存在するという文書上の記載だけで十分か。実際にrollbackを試した記録はあるか。
- read switchを1へ変更する際、どの状態・前提条件が必要か。これは今回の二つの切替経路からはまだ分からない。

これらは**検証すべき質問**であり、`111001`または`110101`が危険だという確定事実ではない。

| 対象側の証拠 | 支持・反証に使える問い |
| --- | --- |
| データ移行仕様と各flagの意味 | 六位置の割当と有効な構成が実在するか |
| 状態遷移ログとfeature flag履歴 | 二つの順序のうち、どの中間状態を実際に通ったか |
| 旧・新レコード差分と更新イベント | どの経路で不整合が生じ得るか、実際に生じたか |
| 不変条件・テスト・復旧実演結果 | それぞれの中間状態が安全条件を満たすか |

## 体系固有の意味を混同しない

易経の六爻・上下卦・解釈史は単に任意の六個のfeature flagと同義ではない。この作例は六つの**位置を保った構成の変化**を仮に使うだけであり、具体的な卦名・爻辞・吉凶・占筮の判断をソフトウェアへ帰属しない。伝統における変爻規則の唯一の再現を主張しない。

また、`2^6`通りを列挙することだけなら通常の組合せテストでも可能であり、同じ終点への二経路を問うことは通常のstate transition/model checkingでも可能である。

**比較前の結論：** この資料が示すのは、固定された二値配置から中間状態の違いを質問として生成できるという*操作可能性*だけである。追加発見の固有性・対象への有効性は[通常手法の比較](../comparisons/yijing-vs-ordinary-state-transition-review.md)と[発見仮説](../comparisons/yijing-discovery-value.md)で別に吟味する。
