# Sāṅkhya — 生成層と観測上の区別を対象へ返す正例

Status: 仮想のtarget-return fixture / 効果実験ではない / 採用判断なし。

## 固定した対象と既知情報

ある架空の業務システムで、10:00の設定変更以後「注文処理の成功率が下がった」というダッシュボード表示について調査する。比較を成立させるため、次の情報を**最初から与える**。

- O1: UIの「成功率」表示が設定変更後に低下した。
- O2: API gatewayの受信成功・失敗カウンタには同じ傾向が見られない。ただしgatewayカウンタが業務完了を表すとは限らない。
- O3: dashboard値は、実処理そのものではなく、event収集 → 正規化 → 分類 → 集計 → 閲覧者別filterを経て計算される。
- O4: 分類器の設定が10:00に更新された。更新が成功率低下の原因だとはまだ証明されていない。
- O5: 同じ時刻について、担当部署Aと部署Bのdashboardでは異なる成功率が表示されている。
- O6: raw business transaction receipts、分類前後のevent標本、filter定義、集計SQL、計測の欠損率、比較可能な実処理結果は与えられていない。

ここで「成功率低下」は**表示上の観測**であり、真の注文完了率の低下でも分類変更による見かけ上の変化でもあると断定しない。

## 文化体系への接触（生成候補）

古典Sāṅkhyaのpurūṣa / prakṛtiの区別、生成系列、現れたものから前段へ遡る構造は、CSWでは**生成の主体が何かを説明する哲学ではなく、暫定的な質問生成の契機**に限定する。25 tattvaをITの層へ割り当てない。

### 層を遡る（layer-backtracking / production-tree）

ダッシュボードの表示から、集計、分類、正規化、event収集、業務処理へと順に資料を照合する。

- どこで「成功」の定義が変わり得るか。分類前の同一eventの扱いは変更前後で変わったか。
- 画面に現れた指標は、どの入力、変換、集計単位とfilterで生じるか。
- 10:00の設定変更は、実業務の状態を変えたのか、観測・分類・可視化の規則を変えたのか。

### 観測位置と処理を分ける（observer-process split）

purūṣaを「ダッシュボード閲覧者」と同一視しない。CSWが借りるのは、**対象内で生じる処理と、対象を分類・記述している操作の区別を問いとして開くこと**だけである。

- 部署A/Bの差は、元の注文集合、集計時刻、閲覧権限、filter、対象期間のどの違いから生じるか。
- A/Bが見た数字は同じ測定対象・分母・時刻についてのものか。
- 集計された状態を、注文自身の状態として扱ってしまっていないか。

### 上流と混合の候補を吟味する

単一の「障害原因」で説明できるとは決めず、業務処理の変化、分類定義、filter、収集欠落などの**対象側の検証可能な候補**を分ける。三guṇaを原因の三分類や人物の固定性格として対応づけない。三方向の混合が対象データから独立に定義できなければ、この操作は撤回する。

## 対象へ戻して確かめる順

| 問い | 必要な独立資料 | 判定できること |
| --- | --- | --- |
| 実際の注文完了率が変わったか | raw transaction receiptsと業務完了の仕様 | gateway counterやUIだけでは結論不可 |
| 分類変更で指標が変わったか | 同じ入力eventを旧/新分類定義で処理した差分 | 設定変更との時間的相関を因果と取り違えない |
| 部署A/Bの表示差は何か | filter・分母・permission・集計タイミング | 観測差なのか対象差なのかを分ける |
| 欠損・遅延は影響するか | event到達率、処理遅延、再試行記録 | 未観測の資料がなければ保留 |

## 出力の限界

ここに書いた質問は構成された仮説である。「分類器が原因」「注文は正常」「観察者が現実を創った」は**いずれも認定していない**。

通常のdata lineage、metric definition、SRE monitoring、ETL debuggingでも同じ層別の問いを自然に生成できる。その能力重複を[比較資料](../comparisons/sankhya-vs-ordinary-data-lineage-review.md)で別に扱う。体系に触れる前から同じ問いを得られる場合は、この構成例を**追加発見の証拠としない**。

## 文化的・典拠上の範囲

Sāṅkhya-Kārikāにおけるpurūṣa / prakṛtiは単なる「観測者／計測対象」という現代的な対置ではない。現代のデータ処理の因果関係やITアーキテクチャの正しさを古典哲学が保証することもない。
