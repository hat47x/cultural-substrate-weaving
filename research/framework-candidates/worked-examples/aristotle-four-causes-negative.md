# Aristotle's four causes non-activation example

Status: negative example / runtime requalification support

## Target

A design record already contains four explicit sections:

- stakeholder objective and success criteria;
- resource / environmental / implementation constraints;
- logical architecture and algorithm;
- behavior, state transitions, and failure mechanisms.

Each section is linked to requirements, tests, and evidence.

## Why the framework should not be activated

The target already separates the explanatory jobs that the de-bound four-causes pass would prompt.

Renaming them as material, formal, efficient, and final causes would add historical vocabulary without opening a new target-side question.

## Correct CSW result

Use the existing design record and test links.

Do not activate Aristotle's four causes merely because the user asks "why does this design behave this way?"

Reopen the framework only if the target's explanation is collapsed into one vague cause statement and ordinary design review has not already separated purpose, structure, mechanism, and constraints.

## Boundary

Non-activation does not deny the historical value of Aristotle's explanatory theory.

It means only that this target already supplies the de-bound cognitive distinctions directly.
