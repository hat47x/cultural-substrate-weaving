# Nyāya target-return worked example

Status: hypothetical / research support for runtime adoption

A team claims that a recurring batch failure is caused by one configuration change.

A Nyāya pass does not accept the causal wording. It unfolds the argument.

- thesis: the configuration change causes the batch failure.
- reason: failures appear when the changed setting is present.
- example: another independently observed case shows the same relevant setting-to-failure relation.
- application: the current batch has the conditions that made the comparison case relevant.
- conclusion: the causal claim remains plausible after the bridge is checked.

If the comparison case only looks similar, or the current batch lacks the relevant condition, the application fails. The target-facing result is not “Nyāya says the cause is wrong.” It is the narrower question: which observed relation actually licenses moving from the setting to the failure?

The framework labels can then be removed while the missing-warrant question remains.
