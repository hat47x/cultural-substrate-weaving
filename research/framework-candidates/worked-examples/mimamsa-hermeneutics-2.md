# Mīmāṃsā hermeneutics target-return example 2

Status: hypothetical / runtime adoption support

A runbook says:

> When cached data is stale, refresh it. If the refresh service is unavailable, stale data may be served for up to ten minutes. After recovery, refresh immediately.

This target differs from the earlier approval-policy example because the main ambiguity is not a general rule versus an emergency authorization. It is how an exception condition and a following instruction attach to the surrounding prescriptions.

A Mīmāṃsā-inspired pass asks:

- Does “for up to ten minutes” modify only the permission to serve stale data?
- Does “after recovery” terminate the exception or start an independent rule?
- Is the second “refresh” the same action referred to in the first sentence?
- Which connection follows from syntax and semantic fit, and which connection is supplied from operational context?
- Do “serve stale data” and “refresh immediately” conflict at one time, or apply to different conditions?

After de-binding, the useful result is not a Sanskrit-derived interpretation. It is a traceable scope map for rule, exception, duration, recovery condition, and follow-up action. This is distinct from merely summarizing the runbook because it preserves which links are explicit and which are supplied.
