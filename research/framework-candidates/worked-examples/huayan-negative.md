# Huayan non-activation example

Status: negative example / runtime requalification support

## Target

The platform already documents:

- bounded contexts for Identity, Billing, Support, and Analytics;
- context-specific Account models;
- shared identifiers without one canonical domain entity;
- context maps and translation boundaries;
- multiple architecture views;
- an explicit list of differences that must survive integration.

## Why Huayan should not be activated

The target already performs the de-bound cognitive jobs:

- role-defined identity;
- whole/part context dependence;
- viewpoint switching;
- integration-with-difference.

Huayan would mainly rename existing design work.

## Correct CSW result

Use the target-side models directly.

Do not activate Huayan merely because the system contains parts and wholes.

## Stop condition

Stop or weaken contact when framework language increases explanation length without adding a new target-side question, or when context-specific identity and preserved differences are already explicit.
