# Classical stasis theory non-activation example

Status: negative example / runtime requalification support

## Target

An incident review already stores every disputed statement with:

- issue ID;
- issue type: observed event, classification, evaluation, or authority/process;
- exact claim;
- supporting evidence;
- unresolved state;
- links showing when a reply changes issue type.

The review UI rejects a response that silently answers a different issue.

## Why stasis should not be activated

The target already externalizes the complete de-bound cognitive job.

There is no missing operation around:

- separating fact from definition;
- delaying evaluation until the event state is explicit;
- distinguishing authority/process from substance;
- detecting an unacknowledged issue shift;
- deciding which evidence can answer which issue.

Applying stasis would rename an existing issue-triage structure without generating an additional target-side question.

## Correct CSW result

Use the target's own issue model.

Do not activate classical stasis theory merely because a disagreement exists.

Reopen the framework only if the target lacks an issue-separation mechanism or if classical rhetorical provenance is itself relevant to the requested work.

## Boundary

Non-activation does not mean that stasis theory is historically trivial or analytically invalid.

It means that this target already performs the de-bound operation directly, so framework contact would add provenance rather than a new cognitive job.
