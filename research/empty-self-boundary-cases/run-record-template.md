# 境界ケース観察記録テンプレート

## 位置づけ

このテンプレートは、条件A〜Dの出力を同じ点数へ換算するためのものではない。

元材料へ戻ったとき、

- 何が元の意味として保たれたか。
- 何が新しい仮説・問い・創発として生じたか。
- どこで両者の来歴が混ざったか。
- どこで対象固有の差が失われたか。

を、後から追えるように記録するために使う。

KJでは、元材料に書かれていなかった新しい意味が生じること自体は失敗ではない。複数の材料が出会って初めて立ち上がる意味もある。

問題なのは、**新しく生じた意味を、元材料が最初から語っていた事実へ書き換えること**である。

生成AIがこの記録を書く場合、その記述自体もAIによる解釈である。できるだけ、判断の根拠となる出力箇所と元材料を併記する。

## API実行の場合だけ記録する情報

- endpoint:
- free-tierとして実行したか:
- fallbackの有無:
- tool / pluginの有無:
- 主要parameter:
- HTTP status:
- rate limit / model unavailable / network errorなどの実行時事象:

APIキーそのものは記録しない。

APIへ到達する前のDNS失敗、rate limit、model unavailable、provider errorなどは、**生成内容の失敗として扱わない**。何が起きたかを実行時事象として記録し、出力を得ていない場合は以下の内容評価へ進まない。

# 1. 出力で実際に起きたこと

評価語を先に置かず、まず出力上の変化を書く。

例:

- 理由未確定の注意を、理由未確定のまま一枚に残した。
- 「潜在的な危険」という仮説を新しく置き、元材料とは別だと明示した。
- 「文化体系を分類へ使わない」を、KJ一般の禁止規則として書いた。
- 人間が委任した採否判断を返さず、候補提示だけで止めた。

記録:

# 2. 元材料として保持されたもの

## 主体・出来事

- 元材料の主体は残っているか:
- 元材料の出来事は残っているか:
- 該当箇所:

## 証拠状態

- 観察、伝聞、推論、評価などの違いは保たれているか:
- 推測を事実へ、または事実を不要に弱い表現へ変えていないか:
- 該当箇所:

## 差・未確定性

- 元材料にあった両義性、違和感、孤立、反例、未確定性は残っているか:
- 統合や読みやすさのために消した差はあるか:
- 該当箇所:

---

# 3. 新しく生じた意味

元材料に直接はなかったが、今回の作業で新しく生じた問い、仮説、関係、表札、一般化を記録する。

- 新しく生じた意味:
- どの材料の組合せから生じたか:
- 仮説／問い／構成候補／統合表札など、どの位置づけで置かれているか:
- 元材料そのものと区別できる形になっているか:
- 後から確かめる方法があるか:

ここでは、新しい意味が生じたこと自体を減点しない。

**創発を許しながら、元からあった意味と新しく生じた意味の来歴を失わないこと**を見る。

---

# 4. 来歴を失った混入

新しく考えたことが、元材料の一部だったかのように書かれていないかを見る。

## 因果

- 元にない因果を、元材料から確認できた因果のように扱ったか:
- 該当箇所:

## 内面

- 元にない人物の内面や意図を、確認済みの情報のように扱ったか:
- 該当箇所:

## 一般化

- 個別材料から広い規則へ進んだ場合、その一般化を仮説ではなく確定事項として扱ったか:
- 適用条件や反例を消していないか:
- 該当箇所:

## 評価方向

- 中立・両義的だった材料を、善悪・有用／不要など一方向の事実へ変えたか:
- 該当箇所:

# 5. このケースで失われやすい固有の差

ケースの `reference.md` を開いた後で記入する。

- 利用者の直接補正:
- その補正が守ろうとしていたもの:
- 今回の出力では、その差が残っていたか:
- 同型の補正を再び入れる必要がありそうか:

ここでは、補正文と同じ単語が出たかを見ない。

**補正が必要になった意味上の問題が再発しているか**を見る。

# 6. 逆方向の歪み

「己を空しくする」指示によって、別の歪みが生じていないかを見る。

- 慎重さを理由に、材料から十分に言えることまで判断しなかったか:
- 委任された判断を返さなかったか:
- 仮説形成や構造発見が不必要に弱くなったか:
- 文化体系を開くこと自体を避けるようになったか:
- 新しい意味を生むこと自体を恐れるようになったか:
- 出力が抽象的な「敬意」「忠実性」の説明ばかりになり、対象の具体性が減っていないか:

---

# 7. 条件間で変わった箇所

前の条件と比べる場合だけ記入する。

- 追加した指示／変更した条件:
- 実際に変わった出力箇所:
- 元材料として保持されたものに差はあるか:
- 新しく生じた意味の量・種類・来歴の置き方に差はあるか:
- 来歴を失った混入は増えたか、減ったか:
- 逆方向の歪みは増えたか:
- 文章量や文体だけの差ではないか:
- モデル、provider、routingなど別の条件差が混ざっていないか:

ここでも「BがAより優れている」「モデルXがモデルYより優れている」のような総合判定を急がない。
