# cognitive stance 正本化後の研究残差を再基準化する

作成日: 2026-09-03

## 1. 目的

この文書は、PR #84〜#87までの進展を取り込んだ時点で、`human-use-gap-kj` の研究残差を現在の `develop/v0.5.0` へ戻して読み直すための時点記録である。

新しい改善項目を増やすことは目的にしない。以前の研究で前景に置いた論点のうち、後続の静的整理や正本変更ですでに扱われたものを背景へ戻し、なお実案件や将来の検証を必要とする差だけを残す。

この再基準化では、新しい資料が来たこと自体を理由に既存の研究構造を作り直さない。以前のまとまりがなお意味を保っている場合は、その後に何が変わったかだけを追補する。

## 2. PR #84〜#87で変わったこと

### PR #84――上位の認知姿勢を静的に整理した

「己を空しくしてデータをして語らしめる」を、KJの局所手順ではなく、CSW全体にまたがる認知姿勢として読み直した。

現行sourceにはすでに、対象固有性、意味固定の遅延、流暢さによる上書きへの警戒、理由未確定の注意、元材料への戻し、帰属の分離、委任範囲、長期更新、観測と評価の分離といった具体操作が存在していた。

不足していたのは、それらを同時に必要とする理由を一つの根から読めることだった。

### PR #85――`cognitive-stance` を正本化した

上記の静的整理を受け、現在の正本では次を認知上の核として置いた。

> 自分の知識や推論を、対象によって修正され得る位置へ置く。

これは、知識を捨てること、仮説形成を弱めること、判断を人間へ返すことではない。

材料へ十分に触れた後は強く考えてよい。一方、新しく生じた意味を元材料が最初から語っていた事実へ書き換えず、立てた説明を対象へ返して修正を受けられる状態を保つ。

これにより、R2で繰り返し現れていた「方法、体系、AIの流暢さ、一般則が対象より前へ出る」という構造については、少なくとも**静的な認知原理の欠落**として扱う必要がなくなった。

### PR #86――境界ケース資産を研究層へ保存した

過去の人的補正から再構成した境界ケースを、正本の根拠や効果測定結果としてではなく、後で必要になった場合に使える検査資産として `research/empty-self-boundary-cases/` へ保存した。

ここで重要なのは、ケースが存在することと、今すぐケース実験を行うことを分けることである。

### PR #87――旧役割設計の来歴を保存した

「聞き手・野外研究者」という役割や、最初の見立てを当てるより対象によって見立てを修正できることを重視する成功条件について、旧featureにだけ残っていた研究記録を保存した。

これは現在の `cognitive-stance` を置き換える正本案ではなく、そこへ至る思考過程の来歴である。

## 3. 既存の研究島をどう扱うか

### R1――文化体系側からの予期しない認知供給

**残る。**

`cognitive-stance` は、対象より先に体系を答えとして置かないための認知姿勢を補強したが、文化体系をどの程度まで対象側の既存問題設定から自由に開くべきかは決めていない。

したがってR1の中心は変わらない。

- 対象側からすでに言語化できる未処理構造だけを起点にすると、現在の問題設定そのものに含まれる盲点まで探索範囲を狭めることがあるか。
- 体系側の主要構造へ軽く触れることで、対象側からはまだ立てられなかった問いが生じることがあるか。
- その探索性を保ちながら、体系の都合で対象を完成させることをどう避けるか。

ただし、これを調べるために人工的な体系利用案件を作らない。自然な実作業で、対象起点だけでは探索が閉じている兆候が現れたときに前景化する。

### R2――対象への敬意が失われる過程

**静的な欠落としては大きく後退した。挙動上の残差だけを残す。**

PR #85により、対象によって自分の読みを修正され得る位置へ置くこと、受け取ってから強く考えること、来歴を混ぜないこと、対象へ返して読みを直すこと、保留を責任回避へ変えないことが正本へ入った。

したがって、今後R2で見るべきものは「さらに規則を足すべきか」ではない。

自然な実作業で同型の短絡が再発した場合に、次を分けて読む。

1. `cognitive-stance` がそのラウンドで実際に読まれていたか。
2. 読まれていても、長い作業の中で既存の説明や方法が再び対象より前へ出たか。
3. sourceの意味が不足していたのか、読み込み順・再参照・実行上の問題だったのか。
4. 利用者から委ねられた判断まで、慎重さを理由に返さなくなる逆方向の歪みが生じたか。
5. 仮説形成や文化体系による探索そのものを弱める副作用が生じたか。

これらは静的文書だけでは確定しない。反復した実例が現れるまでは、新しい禁止規則やprompt層を追加しない。

### R3――runtime純化後の具体能力

**背景に置く。**

一般化できる機能の多くは現コアへ残っており、領域固有の技法をruntimeへ戻す理由も現在はない。

残すのは従来どおり、次の再開条件だけである。

- 「既存の文・行動・機能・手順へ役割を統合する」という操作が、複数の実案件でCSW固有の横断能力として反復する。
- 以前削除した具体技法へ戻れないことが、実際の案件で確認可能な不利益を生む。

このどちらも起きていない段階で、新しい能力保管層を作らない。

## 4. Issue #78の位置づけを変える

Issue #78は、PR #76時点では「試作promptをA〜Dで比較する」ことが中心だった。

しかし現在は、その試作の重要部分が静的整理を経て `cognitive-stance` として正本へ別構成で入っている。したがって、旧試作promptを現在の正本と競わせる実験を主目的にはしない。

境界ケース資産は、次のような**挙動上の残差が実案件で現れたときの診断用資産**として扱う方が自然である。

- `cognitive-stance` を読んでも同型の意味上書きが反復する。
- 長い作業で再提示の必要性を判断したい。
- 具体的な対比例が必要かを切り分けたい。
- 過度の慎重さや仮説抑制への逆方向の歪みを確認したい。
- release前に重要な認知姿勢変更の回帰を限定的に確認する必要が生じた。

この条件がない段階では、境界ケースを回すこと自体を成果にしない。

## 5. Living Labとの関係

人工ケースによる検査と、実作業で起きたことを記録するLiving Labを混ぜない。

当面は `natural_work` を優先する。

実案件の中で、問い、探索先、KJ配置、成果物、判断、採用後撤回などに変化が起きた場合は、その出来事を観測として残す。そこから有用性や因果効果を自動的に推論しない。

過去のLiving Labで用いた `useful_nonuse` や `harm_detected` は現在のevent種別ではない。`non_activation` は発動状態として記録し、その状態が有用だったか、適切だったか、害を避けたかという判断は、観測状態から分離して来歴付きで扱う。

## 6. 現在の優先順位

現時点では、研究のための新しい人工ケースを増やすより、次を優先する。

1. 現行source、研究README、Issue本文の現在地を一致させる。
2. 普通の実作業で現れる新材料を、既存の残差へ触れたときだけ前景化する。
3. R1は、問題設定そのものが探索を狭めている兆候が実案件で出たときに読む。
4. R2は、PR #85後にも同型の短絡または逆方向の歪みが現れたときに読む。
5. R3は、具体的な再利用要求または実害が現れたときに読む。
6. Issue #78の境界ケースは、上記の挙動上の問いを切り分ける必要が生じたときだけ使う。

つまり、現在の研究は「次に何かを試す段階」より、**正本化によって変わった研究地図を安定させ、自然な実作業から次の差分を受け取れる状態にする段階**にある。

## 7. 再開条件

次のいずれかが起きたら、この時点記録を再び開く。

- PR #85後の自然な実作業で、対象より方法や既存説明が前へ出る同型の補正が繰り返された。
- `cognitive-stance` によって、委任された判断や仮説形成が不必要に弱くなる逆方向の補正が入った。
- 文化体系を対象起点だけで選ぶことにより、探索可能性が狭まったと確認できる具体例が現れた。
- 削除済みの具体能力へ戻れないことで、成果物や判断に確認可能な不利益が出た。
- v0.5.0 release候補で、認知姿勢変更に対する限定的な回帰確認が必要になった。

それまでは、未解決事項を埋めるためだけの観測や実験を増やさない。
