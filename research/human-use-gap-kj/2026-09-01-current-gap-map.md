# 人的利用KJカードと現行スキルの照合メモ

作成日: 2026-09-01

この文書は `2026-09-01-initial-cards.md` の生カードを、現行 `develop/v0.5.0` の runtime source と照合するための作業記録である。

ここでの「含まれる／不足」は最終評価ではない。生成AIによる読み取り自体が誤りを含み得るため、**どこに何が書かれているかを先に対応付け、規範的な採否は後段へ送る。**

## 照合区分

- **明示あり**: 現行 source に意味がかなり直接的に書かれている。
- **部分あり**: 関連原則はあるが、生カードの主要な差分が明示されていない。
- **別層候補**: runtime core に直ちに書くべきか自体が未確定。
- **要再確認**: 現行 source の読みだけでは判断しない。

---

## HC-001 新資料が来ても既存島を安易に壊さない

**暫定: 部分あり。**

`core/iteration.md` は、以前のまとまりを正解として固定しないこと、元材料・KJ時点記録・孤立・保留関係・未解決を上書きしないこと、新材料が触れたときに再び前景化できることを定めている。

一方、生カードが指しているのは、再編成可能性だけではない。**既存島の核がなお材料をよく表している場合には、局所追補だけで済ませ、構造全体を動かさない判断**である。この安定性は現行では弱い。

### 残差

- `reopen` と `reconfigure` の間に、「触れたが核は変わらなかった」という状態をどう扱うか。
- 新材料が既存島に意味差分を与えなかった場合、何を保存すれば十分か。
- 安定性を固定化へ変えない条件。

---

## HC-002 カード量増加時の意味保存型統合

**暫定: 明示ありに近い。**

`methods/integration.md` は、カード数削減を目的にしないこと、カードの意味単位・証拠状態を守ること、表札・高次統合後に元材料へ戻って比較することをすでに中核へ含む。

### 残差

人的長期運用では、カード量が増えたときに既存島を壊さず近接カードだけを整理する場面がある。現行記述は統合操作そのものには強いが、**長期島の安定性と統合負荷の関係**は HC-001 と一緒に再検討する余地がある。

---

## HC-003 04理論と核融合法を一つのコア技術として扱う

**暫定: 明示あり。ただし由来の見え方を再確認。**

`methods/integration.md` は、カード化、表札、高次統合を異なる技法へ分裂させず、一つの認知操作として扱っている。意味の境界を取り、核を取り出し、元カードを一時的に外して一文を立ち上げ、元へ戻して比較する流れもある。

### 残差

- 現行操作が、利用者の「生成AIに扱いやすい方をベースに、他方の良い部分を取り入れる」という直接指示を十分に保持しているか。
- 特定研究者の方式を固定手順として権威化していないか。
- 実際の材料に応じて操作強度を変えられるか。

現段階では新しい技法追加ではなく、**現在の一コア化が人的指示の意味を失っていないかの監査対象**とする。

---

## HC-004 意味として生きている単位／証拠状態で切る

**暫定: 明示あり。**

`methods/integration.md` にかなり直接的に含まれている。

このカードは現行 source への追加候補というより、今後の改変で失わないための基準カードとして扱う方が自然である。

---

## HC-005 人間の操作用メタデータを意味分類へ昇格させない

**暫定: 部分あり。**

現行 `methods/integration.md` は、カード本文と provenance を分け、confidence・役割・重要度・感情・type のようなメタデータをカード分類の意味軸へ持ち込まない方向を持つ。

ただし人的利用で重要だったのは、**人間がUIや作業上の便宜で付けた印は、その人が明示的に比較へ使うときだけ意味操作に使う**という可変性である。

### 残差

「メタデータを使わない」ではなく、「何のために人間が付けた印なのかに従う」という委任・操作意図の側面が HC-008 / HC-009 と接続する。

---

## HC-006 理由未確定の『何か気になる』を保持する

**暫定: 明示あり。**

現行 `methods/integration.md` の「理由を発明せず、説明できない注意をそのまま残せる」という設計と整合する。

このカードも追加規則ではなく、現行の重要な保持事項として扱う。

---

## HC-007 文化体系の用途を普遍禁止へ固定しない

**暫定: 部分あり。**

現行 `methods/system-selection.md` と `methods/framework-application.md` は探索利用と帰属利用を分離し、対象を全位置へ割り当てる必要がないことを示す。一方、`core/iteration.md` には「文化体系をKJの分類軸にしない」という強い表現がある。

人的指示では、政治・社会調査の初期KJでは先験分類を避ける一方、創作構造、象徴設計、比較研究、体系自体の研究などでは意図的な分類・再配列が望ましい場合もあると補正されている。

### 残差

現行の「KJを文化体系の分類軸にしない」が、文脈限定の操作原則なのか、無条件禁止として読めるのかを精査する必要がある。

これは有力な現行ギャップ候補だが、**すぐ緩和文へ変更せず、どの工程・用途で何が起きるかを材料から再確認する。**

---

## HC-008 AIへの委任範囲は工程ごとに変わる

**暫定: 未表現に近い。**

現行 source には、スキルの発動範囲や文化体系の読み込み深度はあるが、**人間がAIへどの判断をどこまで委任したか**を独立した軸として扱う記述は弱い。

### 残差

- カード化だけ委任する場合。
- 束ね・表札まで委任する場合。
- 一定範囲の採否まで委任する場合。
- 人間が都度見る場合と、ノールックで委任する場合。
- AIが勝手に権限を広げないことと、勝手に自己縮小しないこと。

これは runtime に入れるか governance に置くかを含めて検討が必要。

---

## HC-009 人間の方法制御入力と対象材料を分ける

**暫定: 部分あり。**

現行には「依頼者から委ねられた課題範囲を勝手に縮めない」「対象の保持事項を守る」等はあるが、人間からの指示のうち、**対象について語っているもの**と、**方法の使い方を制御しているもの**を区別する明示的モデルは弱い。

### 残差

- 人間の制御入力をKJ生カードへ混ぜない。
- しかしその制御入力が後のカード化・束ね・体系利用の方法を変えることは保持する。
- AIが人間の制御則を自分の洞察へ再記述して provenance を失わない。

HC-008 と強く近い。

---

## HC-010 採用後撤回・再利用を含む長期履歴

**暫定: 部分あり。**

`core/iteration.md` と governance event には `artifact_adoption`、`decision_change`、`delayed_reactivation` 等があり、時間をまたぐ変化を扱う土台はある。

ただし、人的実利用で重要だったのは、**局所的には優れた設計が一度採用された後、上位の問題設定変更によって全面撤回され、それでも局所知見だけは別の場所へ残り得る**という履歴である。

### 残差

- adoption を終点にしない。
- withdrawal / supersession / partial carry-forward のような関係を、event vocabulary を増やさず表現できるか。
- 撤回を「過去の失敗」と単純化しない。

---

## HC-011 人間／AI／通常手法／相互作用の認知寄与 provenance

**暫定: 未表現に近い。**

現行 provenance は、対象所見が `target_supported` か `framework_generated` か等を分けるには強い。しかし、**その問題設定や判断転換を誰の介入がもたらしたか**は別軸である。

### 残差

- 利用者が問題設定そのものを変えた場合。
- AIの提案を利用者が採用・変形した場合。
- 通常編集でも起きた可能性が高い変更。
- 人間とAIの往復でしか立ち上がらなかった構造。

ただし、これを細かなスコアリングや寄与率推定へ変えると再びAI評価汚染を招く。必要なのは**来歴を消さないこと**であり、AIが寄与を採点することではない。

---

## HC-012 発散段階と事実認定段階の条件を同一化しない

**暫定: 部分あり。**

現行の探索利用／帰属利用の分離は、この問題のかなりの部分をすでに扱う。

一方、過去の人的補正では、発想段階で抑制原則を強く反復すると文化体系の異質な発想力そのものが痩せるという問題意識があった。

### 残差

この問題意識そのものは残すが、**「もっと大胆に使う方が良い」というAI側の評価へは直結させない。**

現行探索利用が実際の人的利用で狭すぎるかは、利用者の具体的な補正や成果物差分を追加で集めてから判断する。

---

## HC-013〜015 AI自己評価・測定評価の汚染

**暫定: 現行 research / evaluation governance の重要ギャップ候補。**

現行 Living Lab は event を点数へ潰さない、不使用も記録可能、単一観測から `src/` を変えない等の慎重さを持つ。

しかし、ここでさらに必要なのは、**event を記録した生成AI自身が、そのeventの意味を誤って解釈し得ることを前提にすること**である。

特に以下を分離する必要がある。

1. 何が起きたか。
2. 誰がそう判断したか。
3. 利用者自身がどう判断したか。
4. AIがどう評価したか。
5. 測定値・差分として直接確認できるものは何か。
6. そこからAIが追加した因果・評価は何か。

### 重要

`non_activation` や `useful_nonuse` を削除すべきだ、という結論はこのカードからは出さない。

ここで確定しているのは、**AIがそれを「適切だった」と評価しただけでは、その適切さの証拠にならない**という点である。

---

## HC-016 runtime core 純化と具体技法の能力保存

**暫定: 別層候補。**

現行は領域固有技法をruntimeから外し、CSWを認知方法へ純化している。この方向自体を否定する材料ではない。

一方、過去に外した具体技法が必要時に自動再生成される保証もない。

### 残差

- runtime core へ戻す必要があるもの。
- research / examples に残せばよいもの。
- 別 skill / domain knowledge として持つべきもの。
- 作品・案件固有なので一般化しないもの。

このカード単独では決めない。

# 現段階の暫定構造

生カードを現行sourceへ当てた結果、少なくとも次の四つの塊が見えている。ただし島名はまだ作業名である。

## A. KJの長期安定性

HC-001〜004。

現行は「元へ戻れる」「再編できる」能力が強い。人的利用はそこへ、「**意味が変わっていないなら、変えない**」という安定側の判断を追加しているように見える。

## B. 人間が認知操作を制御する

HC-005、HC-008、HC-009、HC-011。

材料、操作用印、委任範囲、問題設定変更、認知寄与の来歴を分ける必要がある。これは単純な human-in-the-loop より広い。

## C. 探索の自由度と後段の厳密さを分ける

HC-007、HC-012。

現行の探索／帰属分離と近いが、人的利用では「局面固有の抑制を普遍禁止へしない」という補正がより強い。

## D. AI評価器そのものを疑う

HC-010、HC-013〜015。

成果物採用、event記録、測定値、AI評価を一つにしない。とくにAI自身の「成功だった」という評価は一次材料より下流に置く。

HC-016 はまだどの島にも無理に入れない。

# 現時点で runtime source を変更しない理由

今回の照合だけでも、HC-004、HC-006などは現行に十分含まれ、HC-007、HC-008、HC-009、HC-013〜015などは追加検討の価値があるように見える。

しかし、ここでAIが「有力」と評価したこと自体を採用根拠にはしない。

次のラウンドでは、各候補について、**利用者の直接補正が複数案件でどう働いたか、現行sourceのどの文がその補正と衝突または不足しているか**を具体例で確認する。その後に初めて、source変更候補とresearch-only残差を分ける。
