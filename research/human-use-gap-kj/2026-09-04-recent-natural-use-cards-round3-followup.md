# 最近の自然利用から起こしたKJカード――第3ラウンド追補

作成日: 2026-09-04

## 0. この文書の扱い

PR #154で統合した `2026-09-04-recent-natural-use-cards-round3.md` の後、最近の設計作業に残った成果物へもう一度戻り、HC-025〜026とG2/G5の橋に近い材料を追加確認した。

前の文書はその時点のKJ記録として書き換えず、本書で意味差だけを追補する。

今回も、成果物に書かれている設計を、利用者の心理やCSWの因果効果へ読み替えない。公開研究へ持ち込むのは、後から確認できる構造だけである。

---

# 1. 新カードにしない反復

## Ø-03――後から判断が変わっても、旧判断を後知恵で書き換えない

最近の設計成果物では、ある判断の後に新しい観察が加わり、元の仮説が弱くなった場合でも、旧判断を削除せず、新しい判断とのrevision / supersession関係を残す構成が置かれていた。

また、後の時点から「旧判断は当時から誤りだった」と履歴を書き換えないことも明示されていた。

これはG5の、

> **ある時点で採用されたものも、後で何が撤回・変形・再利用されたかをたどれなければ、長期の認知履歴を一点の成功へ潰してしまう。**

という核と意味が変わらない。

したがって新カードは作らず、**G5の別ドメイン再出現**として扱う。

---

# 2. 新しく残す生カード

## HC-027――候補との近さや所属関係を、優先権や決定権へ変えない

最近の設計成果物では、ある目的に対して、人間の手作業、外部サービス、同じ開発系列に近い生成アプリケーションなど複数の候補を比較する場面があった。

そこで、**自分たちの技術体系に近い候補だからという理由だけで優先しない**ことが明示されていた。

候補の比較やmatchingは、Recommendationまたは候補説明に留まり、それだけではDecisionにもAuthorizationにもならない。

このカードの核は、

> **候補がどこから来たか、誰に近いか、既存の世界観と親和的かという関係を、その候補を採る権利や優先順位へ自動変換しない。**

ことである。

これはHC-025〜026の「候補≠決定」を一段具体化する。

- HC-025は、生成・受理・適用・保存を分ける。
- HC-026は、Method出力を検証状態を飛び越えてDecisionへ上げない。
- HC-027は、**候補の由来・近さ・親和性そのものを優先根拠へしない**。

G2の「人間の委任・制御」とG4の「AI側の出力や評価を対象側の事実へ自動昇格しない」の間にも置ける。

### 注意

これは、既存技術との統合コストや実装可能性を比較材料にしてはいけない、という意味ではない。

問題にしているのは、

> 自分たちに近いから
> → より望ましい
> → 採用すべき

という意味の飛躍である。

比較可能なコスト、可逆性、前提、監査可能性などを対象側の材料として扱うこととは両立する。

---

## HC-028――Methodの意味を、その時点の実現方法へ固定しない

別の最近の設計成果物では、Cognitive Methodについて、

- Method Definition
- Method Realization
- Method Application

を分ける構成が採られていた。

同じMethodを、ある時点ではpromptで、後の時点では別のmodel program等で実現しても、**実現方法の交換によって過去のMethod Applicationの意味まで書き換えない**。

また、Applicationは具体的なinput / output / residualを参照できる一方、private chain-of-thoughtそのものを保存する必要はないとされていた。

このカードの核は、

> **方法が何であるか、その方法をどう実現したか、その方法をいつ何へ適用したかを分けることで、実装を交換しても意味上の来歴を失わない。**

ことである。

### R3との関係

HC-016は、

> スキルを純化して具体技法をruntimeから外すことと、必要なときにその技法が再生成されることは同じではない。

という、能力保存先の問題を残していた。

R3棚卸しでは、旧技法を丸ごと保存するのではなく、機能単位で現コア、領域側、資料層、別スキル、履歴へ振り分けた。

HC-028はそこへ、別方向から具体を与える。

能力やMethodを再利用可能に保つには、**一つの実現物を永久保存することだけが方法ではない**。Definition、Realization、Applicationの意味を分け、過去Applicationの意味を実装変更から守ることでも、能力の連続性を保てる。

ただし、この一件だけでR3を前景へ戻さない。

# 3. KJでの置き直し

## 3.1 G2–G5の橋を、候補の「状態」だけでなく「由来」まで広げる

PR #154では、HC-025〜026から次の橋を置いた。

> **AIが作った候補は、受理・適用・検証・保存・決定という境界を越えるまで、候補のままに置く。**

HC-027を加えると、この橋には時間方向の状態遷移だけでなく、候補の由来・近さという横方向の境界も見えてくる。

暫定的には次のように読む。

```text
候補の由来・近さ ──┐
                    │  それ自体では優先権にならない
                    ▼
生成された候補 → 比較 → Recommendation → 人間の受理・Decision
                    ▲
                    │  検証状態・根拠・委任範囲
                    └────────────────
```

ここで、Provenanceや由来を消すのではない。

**残すが、権威へ変換しない。**

この点は、HC-005の「人間が付けた印を本質分類へ変えない」とも遠く接続する。

---

## 3.2 R3へ「意味と実現を分けて持続させる」具体が加わった

HC-028は、新しい島を作るより、R3の具体化として置く方が自然である。

R3にはこれまで、

- runtimeから外した技法の機能をどこへ残すか。
- 旧文書を丸ごと保管し直さず、機能単位で処遇する。
- 複数領域で反復する機能だけを別スキル・事例候補として残す。

という問いがあった。

HC-028は、そこへ次の操作を加える。

> **MethodのDefinitionを、個別RealizationとApplicationから分離しておけば、Realizationを交換してもMethodの意味と過去Applicationの来歴を保てる。**

これは「削除した技法をどう保存するか」だけでなく、**将来交換される実装から方法の意味をどう守るか**という時間方向の設計である。

現時点では、CSW runtimeへ新しい抽象層を足す理由にはしない。

# 4. A型的な関係メモ

```text
HC-005 人間の印を本質へ変えない
       │
       ├───────────────┐
       ▼               ▼
HC-027 由来・近さを   G2 人間の委任・制御
       優先権へ変えない      │
       │                    ▼
       └────→ HC-025/026 ─→ G5 採用後の来歴
                    │
                    └────→ G4 AI出力を事実へ自動昇格しない

HC-016 能力の保存先 ──→ HC-028 Methodの意味と実現を分ける
                                │
                                └──→ R3 runtime純化後の能力継続
```

この図も固定分類ではない。

---

# 5. この追補から直ちに行わないこと

- 候補の由来やProvenanceを捨てる。
- 自分たちに近い技術を選んではいけないという禁止にする。
- Recommendationを弱い情報として扱う。
- Method Definition / Realization / Applicationという名称を、そのままCSW runtimeへ導入する。
- 一件の設計成果物だけでR3を前景化する。
- 最近事例の件数をCSWの有効性指標にする。

---

# 6. 現在の判定

今回の追補で、PR #154のG2–G5橋は少し厚くなった。

> **候補は、生成されたというだけでなく、自分たちに近いというだけでも、Decisionへ近づいたことにはならない。**

候補の由来、比較、検証状態、人間の受理、Decisionを別々に持つことが、最近の設計成果物でも反復している。

またR3には、

> **方法の意味と、その時点の実現方法を分けることで、実装を交換しても過去の適用履歴を壊さない。**

という具体が一件加わった。

ただし、いずれも現時点では新しい`src/`変更を要求しない。

G2/G5の橋が他のAI支援実装でも反復するか、HC-028のようなMethod意味の持続が別の領域でも必要になるかを、引き続き自然な実作業から見る。
