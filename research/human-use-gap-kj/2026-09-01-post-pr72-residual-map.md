# PR #72後の人的利用ギャップを再照合する

作成日: 2026-09-01

## 目的

この文書は、HC-001〜025を、PR #72とPR #70を取り込んだ現在の `develop/v0.5.0` へもう一度戻して読むための再照合記録である。

ここでの目的は、研究カードを減らすことでも、新しい規則を増やすことでもない。以前は不足に見えた論点のうち、すでに現在のsourceへ十分に反映されたものを研究上の「未解決」として重複して持たないようにする。そのうえで、なお材料へ戻る必要がある残差だけを残す。

したがって、以下の区分は方法の優劣を示す評価表ではない。

- **現行で十分に保持**: 核となる意味が現在のsourceに明示されている。
- **大部分を保持し、粒度だけが残る**: 上位原則はあるが、人的利用で現れた具体的な差が一般化できるかは未確定。
- **研究残差**: 現行sourceだけではまだ答えを固定せず、実案件へ戻って確かめたい。
- **別層の残差**: runtime規則ではなく、資料構造や能力保存の設計として考える必要がある。

---

# 1. 現行sourceで十分に保持されたもの

## HC-001――既存島の安定性

PR #72後の `core/iteration.md` には、

- 新しい材料が来たという理由だけで既存のまとまりを作り直さない。
- 新材料が何を足し、何を変え、何を変えなかったかを見る。
- 既存島の核がなお材料をよく表し、差分が局所的なら、その差分だけを追補してよい。

ことが明記されている。

HC-001の核は、現在のsourceで十分に保持されたと読む。

## HC-002〜006――意味保存型のKJ操作

カード数を減らすこと自体を目的にしないこと、意味として生きている単位を守ること、証拠状態が変わる場所では分けること、理由がまだ分からない注意を発明した説明で埋めないことは、現在の `methods/integration.md` にすでに強く保持されている。

HC-005の「人間が操作のために付けた印を、本質分類へ自動昇格させない」についても、材料本文と操作上の付加情報を分ける現行設計と整合する。

これらは、新規規則の候補ではなく、今後も失わないための保持事項として扱う。

## HC-007――文化体系による分類を普遍的に禁止しない

PR #72後の `core/iteration.md` は、文化体系をKJの分類軸として**機械的に固定しない**としたうえで、文化体系に基づく分類や再配列そのものが対象である場合には、目的を明示して利用し、元材料へ戻して確かめることを認めている。

このため、「ある研究局面で必要だった抑制を、あらゆる用途へ広げない」というHC-007の核も、現在は十分に保持されている。

## HC-010、HC-013〜015、HC-022〜025――長期履歴と観測・評価の分離

PR #72によって、次が明示された。

- `artifact_withdrawal` を長期eventとして記録できる。
- event種別は、できるだけ何が起きたかを表し、有用性や害の評価を名前へ埋め込まない。
- 観測された差、測定値、利用者判断、AIや外部評価者の解釈を分ける。
- 判断や解釈には、誰がどの根拠からそう判断したかという来歴を残す。
- 後から訂正・撤回された判断を上書きして消さず、変化をたどれるようにする。

したがって、AI自己評価の混入を防ぐというカード群の核は、現在のgovernanceとLiving Labにかなり直接的に反映されている。

これらを、なお「未解決の方法論上の欠陥」として持ち続ける必要はない。

# 2. 上位原則は保持され、粒度だけが残るもの

## HC-008――AIへの委任範囲

`core/principles-and-constraints.md` には、

> 委ねられた範囲を、勝手に広げず、過度の自制で勝手に狭めもしない。

という上位原則が明示されている。

したがって、「AIが勝手に権限を広げる／縮める」という問題は、現行sourceですでに扱われている。

残るのは、カード化、束ね、表札、構成、一定範囲の採否など、**工程ごとに委任範囲が変わることを独立した記録モデルへする必要が本当にあるか**という粒度の問題である。

現時点では、これを静的規則へ追加しない。実案件で、上位原則だけでは委任範囲を取り違える事例が反復するかを先に見る。

## HC-012――発想段階と採用段階を分ける

`core/principles-and-constraints.md` は、意味の固定を遅らせ、可能性と採用を分け、文化体系を開いた後に危険性だけを探して何も生まれない状態にしないことを定めている。

また、`methods/system-selection.md` と `methods/framework-application.md` は探索利用と帰属利用を分けている。

したがって、HC-012の核も大部分は現行にある。

ただし、「文化体系を**開く前**に、AIがどの程度まで予測で入口を狭めてよいか」という論点は、後述するR1へ残る。

# 3. 研究残差 R1――対象側の要求と、文化体系側からの予期しない供給

HC-017〜021を現在のsourceへ戻すと、単純な「文化体系の発動が抑制されすぎている」という読みは適切ではない。

現在のsourceには、すでに次の歯止めがある。

- 明示指定されたCSW利用を、予測だけで拒まない。
- 対象を文化体系へ従わせるだけでなく、文化体系自体を便利な短い関係文法へ早く薄めないという「二重の忠実性」を置く。
- 探索利用では、対象を全位置へ割り当てなくても、問い、対比、空白、構成候補を得られる。
- 可能性を早く閉じることと、採用を強制することを分ける。

一方で、文化体系を選び、深く開く入口は、現在もかなり強く**対象側の未処理構造**から始まる。

`core/activation.md` の `probe` は、別の認知場を開く具体的な理由を対象側から探す。`methods/system-selection.md` も、現在まだ処理できていない対象構造へ、どのような別の見え方を供給できるかを候補選定の起点にする。

ここに残る問いは、次である。

> **現在の問題設定そのものが狭いとき、対象側からまだ「具体的な理由」として言語化できていない文化体系側の構造へ、どの程度まで先に触れてよいか。**

これは、「fullまで毎回読むべきだ」という問いではない。

また、「体系全体を対象へ一対一対応させるべきだ」という問いでもない。

検討したいのは、`probe` と `preview` の間、あるいは体系資料層の使い方として、**対象側の既存の問いに従属しすぎない程度に、その体系自身が何を見ようとするかへ触れる余地**が必要かどうかである。

### 次に必要な材料

R1は、source文面だけでは決めない。

実案件で、少なくとも次の差を観察する。

1. 対象側の未処理構造から候補を選んだ場合、どの問いが生じたか。
2. 同じ案件で、体系側の主要な位置、経路、周期、関係の全体像へ先に軽く触れた場合、問題設定そのものに別の問いが生じるか。
3. その差が、単なる説明量や体系語彙の増加ではなく、調査先、KJ配置、成果物、判断へ実際に残るか。
4. 対象の非対称性、局所性、不可逆性、証拠状態を薄めていないか。
5. 利用者が、その差を採用、訂正、撤回したか。

通常は `natural_work` の中で観察する。R1を静的規則へ昇格させる直前など、条件差を分ける必要が生じた場合だけ `paired_check` を使う。

# 4. 研究残差 R2――人間による方法制御の来歴を、どこまで分けるか

HC-009とHC-011には、PR #72後も一部の残差がある。

現在のgovernanceは、利用者の判断、生成AIの解釈、外部評価を同じ起源として扱わない。これは大きな前進である。

一方、人的利用では、利用者からの入力そのものに、

- 対象についての新しい材料
- 作品や研究で守るべき制約
- AIへ何をどこまで委ねるかという指示
- KJや文化体系をどのように使うかという方法上の補正

が混在する。

これらを常に別schemaへ分ける必要があるとは限らない。しかし、方法上の補正を対象カードとして取り込んだり、AI自身が発見した原則として書き換えたりすると、後の認知操作が誰の判断によって変わったのかが見えなくなる。

### 次に必要な材料

R2では、利用者が方法そのものを補正した実案件を回収し、次を確認する。

- 上位原則である「委ねられた範囲」と判断来歴だけで、実際には十分だったか。
- 方法制御の入力を別に保持しなかったために、後のカード化、束ね、体系利用が誤った例があるか。
- 利用者による補正を、AIが自分の洞察として再記述したことで、来歴を失った例があるか。
- 工程ごとの委任を明示しなければ、実作業で混乱が繰り返されるか。

反復が見えなければ、R2は静的規則にせず研究・運用上の注意として残す。

# 5. 別層の残差 R3――runtimeを純化した後、具体的な能力をどこへ保存するか

HC-016は、現在も他のカードとは性質が異なる。

領域固有の技法を `src/` の中核から外し、CSWを文化体系の探索とKJ統合へ純化する方向は、現在のskill boundaryと整合している。

しかし、過去に具体的な技法を外したことと、その技法が必要なときに再生成できることは同じではない。

ここで問うべきなのは、「昔の技法をruntimeへ戻すか」ではなく、**対象を支配せず、それでも必要なときに再利用できる形で、具体的な能力をどの層へ残すか**である。

候補には、少なくとも次がある。

- 文化体系ごとの資料層
- 研究記録
- 具体例・ケース集
- 併用する領域スキル
- 案件固有の資料
- 一般化に耐えないため、再利用対象にしないもの

### 次に必要な材料

過去版から外した具体技法を、ただ一覧へ戻すのではなく、次の観点で一つずつ見る。

1. その技法が実際に何を可能にしていたか。
2. 現在のKJコアや文化体系適用から同じ機能を再現できるか。
3. 再現できない場合、その機能は一般的な認知能力か、領域固有技法か、特定体系に属する技法か。
4. 保存することでruntimeを再び肥大化・領域化させないか。
5. 具体例として残すだけで、必要時の再利用に十分か。

R3は、現時点ではruntime規則の問題ではなく、**能力を保存するアーキテクチャの問題**として扱う。

# 6. 現時点の整理

PR #72とPR #70を取り込んだ現在、HC-001〜025の多くは、すでにsourceへ反映されたか、もともと存在していた上位原則によって十分に扱えることが分かった。

したがって、研究の焦点をカード数の多さに置かない。

現段階で前景に残すのは、次の三つで十分である。

- **R1**: 対象側の要求だけでは開きにくい、文化体系側からの予期しない認知供給をどう扱うか。
- **R2**: 人間による方法制御の入力と認知介入の来歴を、どの粒度まで分ける必要があるか。
- **R3**: runtimeを純化した後、具体的な能力をどの層へ保存すれば再利用可能性を失わないか。

R1〜R3は、いずれもこの文書だけを根拠に `src/` へ追加しない。

次のラウンドでは、規則を考えるより先に実案件へ戻り、どの残差が本当に繰り返し現れるのかを見る。現れなかった残差は、無理に方法論へ残さない。
