- 入力: [元草案](cognitive-foundation-architecture.md)、[ChatGPTの独立評価](chatgpt-evaluation-response.md)、[複合方式案](composite-cognition-design-method.md)

## 1. 要約

評価と方式案を合わせると、元草案は次の三点で組み替えが要る。

1. 来歴の扱いを改める。「原文の再読で保証する」は撤回し、由来・変換・検証・採用・権限を別の軸で記録し、再読はそのうち内容の照合を担う手段と位置づける。
2. 十項目を「必要十分な認知要件」から「点検の観点」へ下げる。選択肢の比較と、実行・調整の欠落は認める。
3. 試行の順序を変える。構成は仮置きのまま、先に小さな反証試行を行い、その結果で構成を直す。

これらは、著者が示した方針（承認の有無は運用条件、親和図法を材料理解の中心に置く、先回りして抑制しない、実験より構成を優先する）と衝突しない範囲で採用できる。ただし著者の判断が要る点が三つある（§6のU1、U2、U8）。

ChatGPTの評価は、外部の解釈として扱う。測定でも著者の判断でもない。引用文献は、こちらの調査と重なる範囲（Malthouseほか、Huangほか、Kimほか、EU AI Act第14条）の整合だけを見た。それ以外の引用は再確認していない。

## 3. 採用する提案の整理

採用した提案を、変更の種類で分ける。

**記録と来歴**

- 区別を八つ保持する（方式案§7）：同一性と版、由来と検証、原文と派生物、根拠と発見経路、内容と採用、採用と権限、決定と実行、発生時点と記録時点。
- 再読は「資料との照合」であり、対象側の新しい証拠の取得ではない。両者を別に記録する。
- 発見経路と、後の支持を別に残す。CSW由来の問いQが後に観測Oで支持されても、Qの記録を「最初から観測だった」と書き換えない。
- 決定記録に、却下案、現状維持案、反証、未解決事項への参照を持たせる。
- 実行要求、実行系の応答、対象側の結果、照合結果を別に記録する。

**工程**

- 目的・委任条件・費用の確認を冒頭に置く。
- 材料の統合と、選択肢の比較を別工程にする。孤立した材料と反例を検査する工程を置く。
- 事前登録は結果の取得前に行う。決定には暫定の状態を置く。
- 問いごとに、「何が分かると、何が変わるか」を記録する。変わる対象がない問いは、探索の問いとして区別する。
- 再開の契機に、前提の期限切れ、権限の失効、目的の改訂、参照切れ、実行の部分失敗を含める。関係が記録されていない範囲は、影響が「未確認」と書く。

**評価**

- 評価の中心を、費用に見合う改善を独立に判定できるかに置く。
- 観測の三経路（直接観測、利用者の判断、AIの解釈）を分ける。評価者が生成側とモデルや材料を共有する場合は、その相関を記録する。
- 数値の閾値は、案件と評価者を決める前には置かない。

## 7. 最小試行の設計

目的は、構成の不備を見つけて直すことにある。有効性の主張、体系間の順位づけ、一般化はしない。

### 7.1 共通の取り決め

| 項目 | 内容 |
|---|---|
| 変更しないもの | §5のとおり |
| 記録の置き場 | 実記録は`.living-lab/`（Git無視）またはリポジトリ外。公開する場合は、匿名化・抽象化したものを`research/living-lab/observations/`へ。試行の設計書だけを`research/strategy-2026-10/`に置く |
| 記録形式 | 暫定の代用として、Markdownと簡単なメタデータ。SEI・SUIの実装ではない。用語対応表を別に作り、「SEIの記録を作った」とは書かない |
| 観測の三経路 | 直接観測、利用者（著者）の判断、AIの解釈を、別ファイルで残す |
| 評価者 | 生成側と別のコンテキスト。同一モデルの場合は、誤りの相関の可能性を記録する |
| 事前登録 | 各試行の開始前に、予測、判定する失敗様式、結果と設計変更の対応を、日付つきで固定する。試行の自己適用であり、結果の取得後に書き足さない |
| 閾値 | 置かない。判定は、失敗様式の有無と、設計変更の要否で行う |
| 通常保守への適用 | 日常のリポジトリ保守にCSWを自動適用しない（`AGENTS.md`）。この試行は明示的な研究作業とする |

### 7.2 段階0：机上の試行（モデルの比較なし）

**T0 分類試験**

| 項目 | 内容 |
|---|---|
| 目的 | 十項目が、実際の失敗事例を分類できるかを確かめる。五群への再編が要るかを決める（U3） |

| 事前登録する予測 | 関係が記録されていない箇所で、影響なしと推定する誤りが出る |

### 7.3 段階の移行

段階0で、構成の変更が要らない、または変更を反映できたときに、段階1へ進む。反証された設計は、その結果とともに記録し、仮置きの構成を直す。

| 観察 | 設計上の対応 |
|---|---|
| 発見経路と後の支持を区別できない | 由来と検証の軸を、別の記録に分ける |
| 原文を併用しても、由来を取り違える | 再読以外の系譜の記録を必須にする |
| 影響範囲を、関係の記録なしに推定する | 関係の記録を、決定記録の必須項目にする |
| 却下案が復元できない | 決定記録の項目を増やす |
| 復元者が記録にない推測を足す | 推測を禁じる指示と、未確認の明示を、受け渡しの契約に入れる |

### 7.4 段階1：小規模な対照（段階0の後）

**T3 CSWの対照試行**

| 項目 | 内容 |
|---|---|
| 目的 | 問いの候補に差が出る条件と出ない条件を探る。差の主張はしない |
| 案件 | 公開可能な、開いた問い1〜2件。過去案件の再分析、または公開資料にもとづく課題。実在の機微な資料は使わない |
| 条件 | (a)通常の指示 (b)一般的な構造化視点（既存の汎用的な枠組み）(c)CSWの一体系 (d)追加トークンの量を揃えた、複数視点の要求。費用の上限は同じ |
