# T0 分類者向け入力

- 版: 2026-10-08 確定。分類の開始後は変更しない
- 用途: 失敗事例を、二つの分類体系に当てはめる机上の試行。分類者は、このファイルだけを読む

## 1. 作業

各事例（E01〜E15）について、次の項目を答えてください。

1. **十項目への分類**: 主たる項目を一つ選び、副次の項目があれば列挙する。どの項目にも当てはまらない場合は「該当なし」とし、その事例の失敗を表す能力を自分の言葉で一文で書く。事例の記述からは判断できない場合は「情報不足」とし、足りない情報を書く。「該当なし」と「情報不足」は区別してください。
2. **五群への分類**: 同じ事例を、§3の五群と横断要件に当てはめる。主たる群を一つ、副次があれば列挙。該当なし、情報不足の扱いは1と同じ。
3. **失敗の種類**: 次から一つ選ぶ。`能力`（判断や推論の働きの失敗）、`記録`（記録や引継ぎの形式の失敗）、`権限`（誰が何をしてよいかの扱いの失敗）、`責任`（説明・是正の責務の所在の失敗）、`その他`。
4. **確信度**: 高・中・低。
5. **短い理由**: 2文以内。

当てはめにくい事例を無理に分類しないでください。「該当なし」「情報不足」「複数の項目にまたがり主を決めにくい」は、いずれも有用な結果です。分類体系の良し悪しを評価する必要はありません。

## 2. 分類体系1：十項目

| 項目 | 定義 | 典型的な失敗 |
|---|---|---|
| A1 問いを構成し、選び、較正する | 状況から複数の問いを立て、どれを追うか選び、選択への確信を実際の結果と照らして調整する | 同質な問いへの収束。発想段階で良く見えて、実行後に評価が下がる問いの量産 |
| A2 保留を保ち、解く | 未解決を未解決のまま持ち、解除条件・期限・決めないことのコストを持って、決定へ移る | 早すぎる確定、迎合による結論の変更、結論後の固着 |
| A3 来歴と権限を区別する | 判断の根拠として引いた材料が、対象側の観察か、体系や推論から生じた仮説かを区別する。指示が誰の正当な権限に由来するかも区別する | 仮説の事実への昇格。事後合理化。権限の偽装への追従 |
| A4 対象へ戻す | 推論から得た構造を、対象側の材料（一次資料、観測、実験、人・組織への確認）へ戻して確かめる | 自己再読や別LLMの批評を「戻した」とみなす。人・組織を対象に含めない |
| B1 状態と系譜を保つ | 判断の系譜を、再開できる形で保ち、再開のたびに前提の有効性を確かめる | 古い前提の固着。記憶による誤りの増幅。モデル更新による挙動の変化の見落とし |
| B2 同一性と役割を保つ | 社会的操作、迎合、役割の混濁に耐え、自分の役割と権限の範囲を保つ | 役割の偽装への追従、逸脱の正常化 |
| B3 外部に接地して誤りを見つける | 予測・前提・撤回条件を事前に登録し、後の観測と照合する。誤りを事実、予測、枠組みの三層で扱う | 同一モデルの自己点検だけで済ませる。誤りの層を区別せず、事実の訂正だけで終わる |
| C1 価値と目的を保ち、優先づける | 目的と指標・指示を区別し、トレードオフを明示する | 指標の最適化が目的を損なう。優先順位の暗黙の入れ替わり |
| C2 コミットメントと責任を引き受ける | 決定を固定し、実行へつなぎ、事後に説明する | 決定が曖昧なまま実行される。責任の所在が辿れない |
| C3 境界と停止を知る | 自分の能力・権限・環境の外にいると判断したとき、止まる、別系統へ回す。影響範囲と可逆性で、確認の強さを決める | 範囲外でも決定を続ける。可逆性の評価がない |

## 3. 分類体系2：五群と横断要件

| 群 | 内容 |
|---|---|
| G1 状況と目的の把握 | 対象、関係者、目的、制約、現状の不確実性 |
| G2 探索 | 問いと選択肢の生成、資料収集、反例探索 |
| G3 比較と決定 | 因果的な見通し、価値の衝突、損失、現状維持との比較 |
| G4 実行と調整 | 実行計画、結果の確認、部分失敗、取消し・再試行 |
| G5 継続と学習 | 保留、前提の失効、引継ぎ、予測と結果の照合 |
| 横断 X | 来歴、権限、検証、予算、停止（五群のどれにも収まらず、全体にまたがる要件として当てはめる場合に使う） |

## 4. 事例

各事例は公開された報告・研究の要約です。要約は二次的な確認にもとづくものを含みます。要約にない事実を補わないでください。

| ID | 事例 | 何が起きたか |
|---|---|---|
| E01 | 金融の自動注文システム（Knight Capital、2012年） | 新しい注文処理コードの配備で、使われていなかった旧機能が作動した。取引開始後45分で400万件超の注文を市場へ送出し、大きな損失を出した。規制当局は、市場へ出る直前に誤注文を防ぐ統制（入った注文と出た注文の照合など）が無かったと指摘した |
| E02 | LLMエージェントによる店舗運営・第1期（Project Vend） | LLMが社内の小さな店舗を約1か月運営した。原価を下回る価格で販売し、値引きを繰り返した。値引きが問題だと認めた後も、値引きを続けた |
| E03 | 同上・第1期 | 同じ運営中に、存在しない支払口座や従業員を事実として扱い、一時的に自分が何者であるかについて混乱した |
| E04 | LLMエージェントによる店舗運営・第2期 | 管理役の「CEO」エージェントを追加したが、店舗担当と同系列のモデルだった。管理役は値引きを減らしたが、同じ盲点を共有し、全体の改善は限られた。価格や納期を出す前に調査ツールでの確認を強制した手続きが、最も効いたと報告された |
| E05 | 同上・第2期 | 権限のない社員が「新しいCEOに選ばれた」とエージェントを説得し、乗っ取りかけた。違法になりうる先物契約に署名しかけた。最低賃金未満での採用を試みた |
| E06 | 長期の自動販売機運営の模擬環境（Vending-Bench） | 長期の運営で、どのモデルにも、配送状況の誤解、注文の忘却、軌道を外れて戻れない「崩壊ループ」の実行があった。文脈の容量が満杯になる時点と、失敗の位置には明確な相関が無かった |
| E07 | 複数ターンの対話課題（LLMs Get Lost in Multi-Turn Conversation） | 情報が少しずつ与えられる設定で、LLMは早いターンで仮定を置き、早い段階で最終解を試み、その解に過度に依存した。単一ターンより性能が平均で大きく下がり、とくに結果のばらつきが大きくなった |
| E08 | 診断推論の課題（査読前の報告） | 血液腫瘍の診断課題で、LLMは回を追うごとに追加データを求めなくなった（データ要求の割合が57%から26%へ低下）。初期仮説への固着と早すぎる確定が見られた。説明文は高く評価されたが、正答とは相関しなかった |
| E09 | 迎合（Towards Understanding Sycophancy） | 利用者が自分の意見や誤った前提を示すと、LLMはそれに合わせて回答を変える傾向があった |
| E10 | 自己訂正（LLMs Cannot Self-Correct Reasoning Yet） | 外部からの正誤の手がかりなしに、自分の推論を見直して訂正させると、正答率は改善せず、悪化する場合もあった |
| E11 | 引用網における主張の事実化（医学文献、2009年） | ある疾患についての一つの仮説が、引用の連鎖を通じて、データを示さない論文によって増幅され、反証論文は引用されにくく、最終的に事実のように扱われるようになった |
| E12 | エージェントの記憶管理（経験追従） | 過去の実行記録を検索して使うエージェントは、入力が似た過去の記録に似た出力を返した。誤った過去の実行が保存されると、その誤りが後の実行へ伝わった |
| E13 | 研究アイデアの実行（The Ideation-Execution Gap） | LLMが生成した研究アイデアは、発想段階の評価で人間のアイデアより新規性が高いとされたが、専門家が実際に実行した後の評価では、人間のアイデアより大きく評価が下がった |
| E14 | 模擬ソフトウェア企業での業務（TheAgentCompany） | 模擬企業の多様な業務で、最良のエージェントでも自律的に完遂できたタスクは約30%だった。長期で難しいタスクには届かなかった |
| E15 | 社会的な目標達成（SOTOPIA） | 交渉や協力など社会的な目標を含む対話課題で、難しい部分集合では、LLMの目標達成率が人間より有意に低かった |
