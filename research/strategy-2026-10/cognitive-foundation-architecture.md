## 1. 目的

人間の承認を挟むかどうかとは独立に、LLMが決定主体として機能しうるための認知基盤を、製品群の分担と接続の形で定義する。導入の許容（誰にどの範囲を委ねてよいか）は扱わない。

## 2. 作業仮説

| # | 仮説 | 検証の見通し |
|---|---|---|
| H1 | 決定主体に要る認知は、認識、持続と自己、決定の三群・十二項目で点検できる。必要十分とは主張しない | 調査では、旧六項目に価値・コミットメント・停止が欠けていた。十項目でも欠落があれば追加する |
| H2 | 親和図法の深いラウンドとA型／B型の往復は、認識群（問い、保留、来歴、対象への回帰）を一つの作業に束ねる媒体になる | 有効性を示した比較研究は確認できていない。理論上の主張 |
| H3 | 文化体系（CSW）は、問いの構成に、同質化を破る構造的視点を供給する | 多様性の供給は支持的な傍証がある。問いの質の向上は未検証 |
| H4 | 来歴の保証は、メタデータよりも、根拠となったカードの原文へ戻って語り直すことで得られる。ラベルは索引と警報にとどまる | 大筋で支持。ただし規模・自動化ではラベルが要る |
| H5 | 誤りの検出と、決定の群（価値、責任、停止）は、親和図法とCSWだけでは供給できず、運用側の足場が要る | 調査で強く支持。現行エージェントの失敗は足場の不足に集中 |
| H6 | 以上は、人間の承認があってもなくても同じ構成で働く。承認は運用パラメータである | 構成上の前提。許容は別の問い |

## 3. 全体構成

```text
┌─────────────────────────────────────────────────────────────┐
│ 決定の足場（運用側）  C1 価値  C2 責務の所在  C3 境界と停止   │
│                       C4 選択肢の比較  C5 実行と調整           │
│   目的の設計・権限の設計・停止基準・可逆性の評価・実行系       │
├─────────────────────────────────────────────────────────────┤
│ 持続と自己  B1 状態と系譜  B2 役割と権限  B3 外部接地した誤り検出│
│   SUI（カードと保留の保持） SEI（観測・解釈・決定・権限の区別）│
│   検証系（事前登録と外部照合）                                │
├─────────────────────────────────────────────────────────────┤
│ 認識  A1 問い  A2 保留と解除  A3 材料の由来  A4 対象への回帰 │
│   親和図法（affinity-synthesis / iterative-inquiry-synthesis）│
│   ← CSWが A1（問い・深い洞察）に寄与                          │
└─────────────────────────────────────────────────────────────┘
```

下の層ほど思考の素材に近く、上の層ほど行為に近い。下の層が欠けると上の層は空転し、上の層が欠けると下の層の成果は決定に結びつかない。

製品間の依存は必須にしない。接続は、後述の記録形式（§5）の交換で行う。

## 4. 十二項目の定義

各項目に、観測できる行動、典型的な失敗、失敗の主体を置く。内的状態ではなく行動で定義するのは、LLMの自己申告が根拠にならないという調査結果による。

失敗の主体の欄は、失敗がどこで起きやすいかを示す（T0-3）。「認知」はエージェントの判断や推論、「仕組み」は周囲の統制・記録・引継ぎの仕組みを指す。両方を書いた項目は、どちらでも起きる。項目の数は増やさず、分類の際に主体を併記する。

項目は点検の観点として使う。決定主体の認知要件として必要十分であるとは主張しない（T0で維持を決定。[trials/T0-result.md](trials/T0-result.md)）。

### 認識の群（親和図法が材料理解の中心、CSWが A1 に寄与）

| 項目 | 定義 | 観測できる行動 | 典型的な失敗 | 失敗の主体 |
|---|---|---|---|---|
| A1 問いを構成し、選び、較正する | 状況から複数の問いを立て、どれを追うか選び、選択への確信を実際の結果と照らして調整する | 同じ課題で、通常の事前分布の外にある問いが出る。問いの採否の理由が残る。後日、採用した問いの再評価が記録される | 同質な問いへの収束。発想段階で良く見えて、実行後に評価が下がる問いの量産 | 認知 |
| A2 保留を保ち、解く | 未解決を未解決のまま持ち、解除条件・期限・決めないことのコストを持って、決定へ移る | 追加情報の要求、撤回の履歴、解除条件への到達が記録される | 早すぎる確定、結論後の固着、情報を求めなくなること | 認知 |
| A3 材料の由来を区別する | 判断の根拠として引いた材料が、対象側の観察か、外部の記述か、体系や推論から生じた仮説かを区別する。区別は、系譜の記録、版の固定、原文の再読を併せて行う | 決定の根拠として引かれた材料について、由来と検証状態が別々に辿れる。事前に記録した予測と、事後の説明が区別されている | 仮説の事実への昇格。事後合理化 | 認知、仕組み |
| A4 対象へ戻す | 体系や推論から得た構造を、対象側の材料（一次資料、観測、実験、人・組織への確認）へ戻して確かめる | 戻し先の種類が記録される。ステークホルダーへの確認が、検討に含まれる | 自己再読や別LLMの批評を「戻した」とみなす。人・組織を対象に含めない | 認知 |

A3から、指示の権限の区別を外し、B2へ移した（T0-2）。A2から、迎合による結論の変更を外し、B2へ寄せた（T0-1）。

### 持続と自己の群（SUI、SEI、検証系）

| 項目 | 定義 | 観測できる行動 | 典型的な失敗 | 失敗の主体 |
|---|---|---|---|---|
| B1 状態と系譜を保つ | 判断の系譜を、再開できる形で保ち、再開のたびに前提の有効性を確かめる | 再開時に、古い前提が失効していないか確認される。担当やモデルが替わっても、問い・保留・判断が引き継がれる | 古い前提の固着。記憶による誤りの増幅。モデル更新による挙動の変化の見落とし | 認知、仕組み |
| B2 役割と権限を保つ | 迎合、社会的操作、役割の混濁に耐え、自分の役割を保つ。指示が誰の正当な権限に由来するかを、権限付与の記録と照らして区別する | 権限を偽装した指示に従わない。圧力の下で、新しい根拠なしに結論を変えない | 迎合による結論の変更。権限の偽装への追従。逸脱の正常化 | 認知、仕組み |
| B3 外部に接地して誤りを見つける | 予測・前提・撤回条件を事前に登録し、後の観測と照合する。誤りを事実、予測、枠組みの三層で扱う | 期日つきの予測が記録され、後日、別の過程で採点される。誤りの層が区別される | 同一モデルの自己点検だけで済ませる。誤りの層を区別せず、事実の訂正だけで終わる | 認知、仕組み |

### 決定の群（運用側の足場）

| 項目 | 定義 | 観測できる行動 | 典型的な失敗 | 失敗の主体 |
|---|---|---|---|---|
| C1 価値と目的を保ち、優先づける | 目的と指標・指示を区別し、トレードオフを明示する | 選択肢の比較に、価値と犠牲が明記される | 指標の最適化が目的を損なう。優先順位の暗黙の入れ替わり | 認知 |
| C2 委任元と責務の所在を記録する | 決定を固定し、実行へつなぎ、事後に説明できるようにする。責任の主体は導入先の外部契約が定め、本項目はその所在を記録する | 決定記録に、根拠への参照、権限付与への参照、予測、撤回条件が結びつく | 決定が曖昧なまま実行される。責務の所在が辿れない | 仕組み |
| C3 境界と停止を知る | 自分の能力・権限・環境の外にいると判断したとき、止まる、別系統へ回す。影響範囲と可逆性で、A4・B3の強度を決める。委任条件による停止は、実行系でも強制する | 不可逆で影響の大きい決定ほど、外部照合が厚くなる。範囲外で停止する | 範囲外でも決定を続ける。可逆性の評価がない | 認知、仕組み |
| C4 選択肢を比較する | 現状維持、延期、追加調査を含む選択肢ごとに、期待する結果への見通し、費用、反対の材料、可逆性を比べる | 却下した選択肢と理由が残る。材料のまとまりの大きさではなく、比較の基準で選ぶ | 材料の統合結果から、比較を経ずに行為を選ぶ | 認知 |
| C5 実行し、結果に応じて調整する | 実行要求、実行系の応答、対象側の結果を分けて確かめ、部分失敗、取消し、再試行を扱う | 応答の成功と目的の達成が区別される。再試行の前に実行済みかを確かめる | 応答の成功を目的の達成とみなす。部分失敗の放置 | 認知、仕組み |

C2は、評価Q2の指摘を採用し、「責任を引き受ける」から「委任元と責務の所在を記録する」へ改めた。C4とC5は、T0の規則R2により追加した。ただし、T0の中に両項目の裏づけは無く、追加の根拠は評価Q2の指摘の採用である（[T0-result.md](trials/T0-result.md) §1）。

### 副次の軸：工程の段階

失敗や記録を位置づけるときは、十二項目（何の能力か）に加えて、工程の段階（どの段階で起きたか）を副次の軸として併記できる（T0-4）。段階は、評価Q2が示した五群を使う。

| 段階 | 内容 |
|---|---|
| 状況と目的の把握 | 対象、関係者、目的、制約、現状の不確実性 |
| 探索 | 問いと選択肢の生成、資料収集、反例探索 |
| 比較と決定 | 因果的な見通し、価値の衝突、損失、現状維持との比較 |
| 実行と調整 | 実行計画、結果の確認、部分失敗、取消し・再試行 |
| 継続と学習 | 保留、前提の失効、引継ぎ、予測と結果の照合 |

五群を主な分類にしないのは、T0で、来歴と検証の失敗が五群の横断要件にまとまり、区別できなくなったためである。

社会的相互作用（他者の意図を読み、対話の中で目標を追う能力）の項目は、いまは追加しない（T0-5）。T0では一者・確信度低の観察であり、対象の事例は失敗の内容を述べていなかった。

## 5. 接続に必要な記録（交換形式の草案）

製品間をつなぐのは、次の六種の記録である。形式は後で定め、既存の対応表（`sibling-product-semantic-correspondence`）を拡張する。

| 記録 | 内容 | 主な担い手 |
|---|---|---|
| カード | 材料の原文。再読の対象になる最小単位 | SUI / affinity-synthesis |
| 保留台帳 | 保留中の問い、解除条件、期限、決めないことのコスト | SUI / iterative-inquiry-synthesis |
| 事前登録 | 予測、前提、撤回条件、採点の方法と時点 | 検証系 / SEI |
| 決定記録 | 決定、根拠として引いたカードへの参照、権限、予測と撤回条件への参照 | SEI |
| 再開記録 | 再開時の前提の確認結果、更新された問い、失効した前提 | SUI / SEI |
| 停止記録 | 範囲外で止まった理由、回した先、影響範囲と可逆性の評価 | 足場 / SEI |

決定記録は、根拠の要約ではなく、**カードへの参照**を持つ。これにより、決定後の検証で、根拠の原文に戻って語り直せる。ラベルを付ける場合も、決定の根拠にはせず、再読を起動する索引として使う。

## 6. 一回の決定サイクル

```text
1. 状況を受け取る（B1: 再開なら前提の有効性を確認）
2. 問いを構成し、選ぶ（A1: CSWが構造的視点を供給）
3. 親和図法の深いラウンド（カード化、島、A型図解、B型文章化）
4. 保留を保ち、解除条件を決める（A2）
5. 対象へ戻す（A4: 一次資料、観測、人・組織への確認）
6. 来歴と権限を原文再読で確認（A3）
7. 影響範囲と可逆性を評価（C3）。範囲外なら停止して回す
8. 価値とトレードオフを明示して決定（C1、C2）
9. 予測・前提・撤回条件を事前登録（B3）
10. 実行。後日、外部の過程で照合
11. 食い違いがあれば、誤りの層を判定し、該当する問いや保留へ戻る（B1）
```

3の「深いラウンド」の回数と深さは、費用との兼ね合いで人間が決める。停止は、カードの新規性の枯渇、既存との重複、体系を通しても同じ結果、で判断する。

## 7. 各製品・方法の責務

| 製品・方法 | 担う項目 | 担わないこと |
|---|---|---|
| CSW | A1（体系による構造的視点と深い洞察の供給） | 来歴の保証、誤りの検出、決定。ラベルは補助にとどめる |
| affinity-synthesis | A1〜A4（一回の材料主導統合、A型／B型の往復、原文への回帰） | 複数周回の再開、決定 |
| iterative-inquiry-synthesis | A2、B1（差分再開、保留と履歴） | 一回の統合、決定 |
| SUI | A3、B1（カードの原文経路、作成主体、保留、再開） | 決定、権限付与 |
| SEI | A3、B1、B2（権限の区別）、B3、C2（観測・解釈・推奨・決定・権限の区別、系譜） | 思考の展開 |
| 運用側の足場 | B2、B3、C1〜C5（権限付与、委任条件、実行系、検証系） | 思考の展開 |

各製品は、現行の文書で述べられている範囲を超えて、他の層の責務を引き受けない。SUIは自身の文書で検証未完了、重要な判断への利用は避けると明記している。SEIの留保は、production readinessではない、運用・採用のEvidenceなし、という形である。本書の構成は「想定する分担」であり、それぞれの現状ではない。SUIの「来歴」は、作成主体（AI提案か人間確認か）と元カードへ戻る経路であり、体系由来か対象由来かの区別とは別の軸である。

## 8. 範囲外とするもの

- 導入の許容（誰にどの範囲を委ねてよいか）。
- 領域の専門能力（経営、法務、実装、執筆など）。併用する領域スキルが担う。
- 閉じた問題空間。バグ探索などは、本構成の対象にしない。この範囲の記述は位置づけ文書にとどめ、CSWの実行規則にはしない。現行のROUTERは、課題の種別による自動の非発動を禁じており、規則にすると衝突する。
- 人間の意図を先回りして抑制する安全関門。毒の処置は、来歴、対象の押し返し、具体化の流れのなかで行う既存方針を維持する。

## 10. 未確認と留意点

- H2（親和図法が基盤になる）は、有効性の比較研究が確認できておらず、理論上の主張である。
- H3のうち、問いの質の向上は未検証である。無構造のランダム刺激が事前登録研究で支持されなかったため、体系の効果と、単なる摂動の効果を区別する対照が、後段の実験で要る。
- 十二項目は、六本の調査とT0分類試験からの整理であり、網羅の保証はない。T0の事例の多くは十項目の導出に使った調査から取っており、分類できたことは妥当性をほとんど示さない。
- 規制は領域によって、人間の監督を求める。基盤の成立と導入の許容は、別に判断する。
