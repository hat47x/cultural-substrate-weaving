# 文化体系のモデル用途一覧の開放性監査

## 対象

`methods/system-selection.md` のモデル用途一覧を監査する。

現行JAでは、必要に応じて次の4用途を選ぶ形になっている。

1. 構造モデル
2. 一貫性モデル
3. 時間モデル
4. 遷移モデル

この監査で問うのは4用途の有用性ではない。4つを閉じた完全分類として扱う必要があるかである。

## 履歴

### 1. v0.1.0ではファイル内列挙が明示的に非網羅だった

初期公開 `cd580449e942e7b80786dd70eb9c963f41287296` の `system-selection.md` には、本文冒頭で次が明示されていた。

> このファイルの列挙は、対象に応じて選択して使う。対象固有の追加項目は動的層に置く。

その非網羅前提の下で、当時は次の3用途が並んでいた。

- 構造モデル
- 一貫性モデル
- 時間モデル

したがって初期設計は、3用途を完全taxonomyとして固定するものではなかった。

### 2. `785da4a…` で第4用途が追加された

`785da4a62358476f4624ba38af89a4c754094f54` では、「framework could only be used statically」という能力上の欠落を埋めるため、遷移モデルが第4用途として追加された。

変更前は「次の三つから選ぶ」、変更後は「次の四つから選ぶ」となった。

この履歴自体が、用途一覧を外部体系から与えられた固定分類ではなく、CSWの認知能力追加に応じて拡張される実装語彙として扱っている。

### 3. `182cea0…` は時間・遷移用途を強化したが、網羅性は検証していない

`182cea0001787474519eff22300be447f2fb1fad` では、時間モデルと遷移モデルが静的配置から出にくい問いを生むことを明示し、遷移の因子別軌跡も強化した。

ここでも4用途の価値や違いは補強されたが、「この4つですべての文化体系利用を覆う」という比較・検証は記録されていない。

## 現行で閉じて読む場合の問題

文化体系は、位置、周期、方向、流れ、層、パス、対応、変換、生成・抑制など、対象ごとに異なる認知操作を供給しうる。

4用途を許可リストとして読むと、新しい体系や対象から別の有効な使い方が立った場合でも、既存4用途のどれかへ近似して押し込むことになる。

それは、

- 体系固有の操作差を失う
- 新しい認知能力を既存taxonomyで早期分類する
- 体系側から問題設定に無かった問いを開くという探索利用を狭める

可能性がある。

## 維持すべきもの

次は変更しない。

- 構造・一貫性・時間・遷移の4用途
- 時間モデルと遷移モデルを静的配置から区別すること
- 探索利用と帰属利用の区別
- 用途、適用範囲、読み込み深度を別状態として扱うこと
- 帰属利用では対象側の材料へ戻して確かめること
- 遷移規則を持つ体系でのみ遷移を帰属利用するという証拠境界

## runtime改定方針

最小変更として、4用途が代表例であって非網羅であることだけを局所的に明示する。

例:

- JA: `必要に応じて、次のような用途を選ぶ。`
- EN: `Use modes such as the following as needed.`

新しい用途名は追加しない。既存4用途の意味も変更しない。

また、新しい固定回数、採否、停止、成功条件は追加しない。

## 結論

現行4用途は、CSWが繰り返し使う有用な標準モードとして維持する価値がある。

一方、初期v0.1.0はファイル内列挙を明示的に非網羅としており、その後も能力追加によって3用途から4用途へ実際に拡張された。4つを完全分類として固定する根拠は確認できない。

したがってruntimeでは、**既存4用途を残しつつ、対象・体系から別の認知用途が立つ余地を残す開いた一覧へ戻す**のが履歴と現行の探索方針に整合する。
