# 欠落要素の四分類が閉じた一覧になった経緯を監査する

作成日: 2026-09-05

## 1. 対象

`methods/transformation.md` の次の箇所を監査する。

> 要素自体が存在しない場合は、次の四つを区別する。

1. 今回の対象範囲外である。
2. 対象の主要変化構造と両立しない。
3. 意図的に省略されている。
4. 対象の目的に必要だが、まだ扱われていない。

監査対象は、この四つの区別そのものではない。対象範囲外、構造的不適合、意図的省略、未処理の必要要素という区別は、欠落を即座に「不足」とみなさないために有用である。

問題にするのは、四つが現在の文面上、欠落要素の原因を尽くす閉じた分類として読める状態になっていることである。

## 2. 初回公開時点

`cd58044…` のv0.1.0初回公開では、同じ四分類が既に存在していた。

ただし、同じファイル冒頭には次の境界が明記されていた。

> このファイルの列挙は、対象に応じて選択して使う。対象固有の追加項目は動的層に置く。

また、四分類の箇所は「次の四つに分類する」と書かれていた。

したがって、初回設計において四分類は静的な唯一の原因集合ではなかった。ファイル内の列挙は選択的に使い、対象固有の追加項目を許すという上位境界の下に置かれていた。

## 3. `3988e12…` の縮約

`3988e12…` は、スキルを文化体系探索とKJ統合の二核心へ切り詰める大規模縮約だった。

この時点の `methods/transformation.md` を確認すると、冒頭の

> このファイルの列挙は、対象に応じて選択して使う。対象固有の追加項目は動的層に置く。

が消えている一方、欠落要素の四分類はそのまま残っている。

同コミットの目的は領域固有の一般技能・評価項目を除去することであり、欠落原因を四つへ限定する比較実験や、四分類を網羅集合へ昇格させる説明は確認できない。

このため、**列挙を開いていた上位境界だけが縮約で失われ、列挙本文が閉じた分類のように残った**と読むのが履歴に最も整合する。

## 4. 後続変更

後続では「分類する」が「区別する」へ緩和され、どの候補を実作業へ採用するかは外部利用条件または委任された判断へ戻された。

一方、四分類の前には現在も「次の四つを区別する」とあり、対象固有の第五・第六の状態をこの箇所で明示的に許す文言は戻っていない。

semantic-retention が保護しているのは、

> 要素自体の欠落と、接続の欠落を区別する

という上位の証拠・構造境界であり、四分類を閉じた集合にする文言ではない。

## 5. 機能と閉鎖性を分ける

四つの区別が守る機能は維持できる。

- 対象範囲外を、対象の欠陥へ変えない。
- 体系と両立しない対象固有性を、不足として埋めない。
- 意図的省略を、無自覚な欠落と混同しない。
- 対象目的に必要だが未処理のものを、追加候補として見つける。

ただし、実際の対象ではこれら以外の理由が生じ得る。たとえば、資料不足のため存在判定自体が未確定、層・時点・観測単位が異なる、体系側の分節が対象へ移せない、といった状態は既存の四つへ無理に押し込めるより、対象固有の追加区別として保持する方が来歴と証拠状態を守れる。

ここで新しい第五分類を静的に追加する必要はない。そうすると別の閉じた五分類を作るだけになる。

## 6. runtime 改定方針

最小変更は、四項目を残したまま、列挙が非網羅であることをその箇所へ局所的に戻すことである。

例:

> 要素自体が存在しない場合は、少なくとも次を区別する。

これにより、

- 四つの既存区別は維持する。
- 対象固有の追加状態を許す。
- 欠落を即座に不足や追加要求へ変えない。
- 新しい固定分類数を作らない。
- 採否・実作業への反映は引き続き外部利用条件または委任判断へ戻す。

## 7. 変更しないもの

この監査は、次を弱めるものではない。

- 要素自体の欠落と接続の欠落を分けること。
- 欠落を検討する前に体系の被覆範囲を見ること。
- 閉集合／開一覧、排他／重複、離散／連続を区別すること。
- 対象固有性を体系完成のために埋めないこと。
- 欠落検出と一貫性検査を分けること。

復元するのは、初回公開時点に存在していた**列挙の開放性**だけである。
