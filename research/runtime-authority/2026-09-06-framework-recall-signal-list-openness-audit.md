# 文化体系候補の想起シグナル一覧を監査する

## 対象

`src/ja-JP/methods/system-selection.md` 冒頭にある、対象側から候補体系を探すときの次の8項目です。

- 複数の状態・位置
- 経路、中間点、分岐、戻り
- 周期、位相、蓄積、再来、ずれ
- 境界、移行帯、中心／周辺
- 複数の時間尺度
- 流れ、接続、詰まり
- 連続体と分節
- 既存の問題設定とは別の問い

監査したい点は、この8項目を文化体系探索の完全な入口集合として扱う根拠があるか、それとも代表的な探索手掛かりとして開いておくべきかです。

## 現行での役割

現行文では、通常は「対象側でまだ保持しにくいもの」から候補体系を探し、その直後にモデルの自然連想だけへ候補想起を任せないための検索アンカーを置いています。

後段の検索アンカーは明示的に「完全な候補一覧ではない」とされ、状態格子、周期・暦、経路・流れ、方向、層とパスなど、対象の現在の分節とは異なる構造型へ到達することを目的にしています。

したがってこの8項目の機能は、候補を閉じる分類表ではなく、対象側の未処理構造から別の認知場を開くための入口を与えることです。

## 由来

### `3988e12…` より前

Skillを二つのコア能力へ縮約した `3988e12e5f7f316f377d3391e9486c8467a111d5` 時点の `system-selection.md` には、現在の8項目はありませんでした。

当時は、体系名の列挙ではなく構造型の違いに基づいて候補を絞り、各体系の構成要素、関係、時間・周期・段階、生成と抑制、適用領域、歴史的文脈、異説と限界を調査する構成でした。

つまり8項目は、初期KJや文化体系の外部原典から固定的に継承されたtaxonomyではありません。

### `3dc8777…` — v40 production semantics統合

`3dc8777491977dd58ab506249a30306769011fbc` は `feat: integrate v40 production semantics into ja-JP core` として、`system-selection.md` の入口を大きく組み替えました。

この変更で、従来の体系側チェックリストに代わり、まず対象側の未処理構造を見る方針が前景化し、現在につながる8項目が導入されました。

コミット全体の目的は、発動範囲と文化体系の読み込み深度を分離し、探索と帰属を分け、KJと文化体系を実作業へ接続するv40の運用意味論をコアへ統合することでした。8項目の網羅性を比較・測定した変更ではありません。

したがって、ここで成立したのは「対象側の未処理構造から候補を探す」という探索方向であって、「未処理構造はこの8種類に尽きる」という主張ではありません。

### 二方向の探索入口への拡張

その後、体系起点の `preview` をもう一つの入口として扱う変更が入りました。

`6becc684b0fffd49a114fffad579ce8f69fcc17f` のCHANGELOG記録では、既存の対象起点 `probe` を通常経路として保ちながら、候補体系自身の位置、経路、周期、関係、遷移、境界へ軽く触れることで現在の問題設定を揺らす体系起点探索を追加したと説明されています。

`f547a0cf7e35b589946802a65172d0f59e48ecc5` では、この二入口の責務を `system-selection.md` へ整理し、8項目を対象起点側の手掛かりとして残しつつ、体系起点では現在の問題設定にない区別や問いが生じるかを見る形に整理しました。

この時点で、候補探索は8項目だけでは閉じないことが設計上さらに明瞭になっています。

### `8da5aaf…` — 検索アンカー追加

`8da5aafc67f02c347b22223342a6e812f6ea5475` は `method: add framework recall search anchors` として、四季、五行、五大、八卦、方位、虹の七色、十干、十二支、ツォルキン、経絡、チャクラ、セフィロトとパスなどを、異なる構造型へ到達するための検索アンカーとして追加しました。

ここでは明示的に、具体名を「採用推奨や完全な候補一覧ではない」としています。また、同じ体系が複数の探索型に現れてよく、伝統上の分類や体系間の同一性ともみなさないとされています。

この後付けの検索アンカーは、候補想起の目的が固定taxonomyを完成させることではなく、モデルの自然連想が近接語彙だけで閉じるのを避け、異なる構造型へ探索を開くことだったことを補強します。

## 判断

8項目は有用です。状態、経路、周期、境界、複数時間尺度、流れ、連続体、問題設定そのものという、文化体系探索で繰り返し重要になる入口を短く保持しています。

一方で、次の理由から完全分類として固定する根拠は確認できませんでした。

1. 8項目は `3dc8777…` のruntime再編で導入された現代的な探索語彙であり、外部原典から継承された固定分類ではない。
2. 導入コミットは8種類の網羅性を測定していない。
3. 後から体系起点previewが追加され、対象側の未処理構造だけではない探索入口が明示された。
4. 後から追加された検索アンカー自身が、完全一覧ではないことを明示している。
5. CSWの目的は現在の問題設定だけで探索可能性を閉じないことであり、入口語彙を閉じることはその目的と逆向きになり得る。

## runtimeへの含意

変更するなら最小限でよいです。

- 現行8項目はすべて保持する。
- 「通常は、対象側でまだ保持しにくいものから候補体系を探す」という対象起点の基本経路も保持する。
- 8項目を代表的な手掛かりとして明示し、対象固有の別の未処理構造も候補探索の入口にできるようにする。
- 体系起点preview、検索アンカー、探索／帰属境界、資料確認、非採否急進の規則は変更しない。
- 新しい固定項目、最低件数、必須被覆率、停止条件、採否条件を追加しない。

たとえば日本語では、導入文を「たとえば、次のようなものを見る。」とするだけで、8項目の実用性を保ったまま閉鎖性を外せます。

## 結論

この8項目は、文化体系候補を対象側から想起するための**強い代表例**として保持するのがよいです。

ただし、それ以外の未処理構造を探索入口から除外する完全taxonomyとして扱う根拠はありません。局所的に非網羅性を明示し、文化体系探索の想起能力を事前分類で閉じない形へ戻すのが、履歴と現行設計の双方に整合します。
