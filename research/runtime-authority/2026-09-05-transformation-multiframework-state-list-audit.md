# transformation multi-framework state list audit

作成日: 2026-09-05

## 対象

`src/ja-JP/methods/transformation.md` の、複数体系を使う際に観察する三つの状態を監査する。

現行は次の三項目を挙げる。

1. 不採用条件のない体系が、確証を増やし、対象側の検証を弱めている。
2. 体系間の一致が、対象由来ではなく解釈者の変換規則から生じている可能性がある。
3. 対象の事実や因果関係に結び付かない記号が、既存理解の言い換えだけを生んでいる。

続く本文は、これらを複数体系の利用を自動的に縮小する規則ではなく、外部利用条件に応じた判断材料または追加検査の入口として扱う。

## 初期設計

v0.1.0 初回公開 `cd580449e942e7b80786dd70eb9c963f41287296` には、同じ位置に三つの「リスク」が存在した。

同じファイル冒頭には、次の前置きがあった。

> このファイルの列挙は、対象に応じて選択して使う。対象固有の追加項目は動的層に置く。

したがって、初期の三項目も網羅的な全リスク集合ではなく、対象に応じて選択・追加可能な観察項目だったと読める。

## 開放性が失われた経緯

`3988e12e5f7f316f377d3391e9486c8467a111d5` の二核心縮約で、ファイル全体に掛かっていた「列挙は選択的」「対象固有の追加項目は動的層へ」という前置きが削除された。

三つのリスク本文は残ったため、局所的には三項目が閉じた集合のようにも読める状態になった。

この縮約は領域固有の一般技能・評価項目を除去してCSWの二核心を明確化する変更であり、三項目を網羅集合へ変更する比較実験ではない。

## authority rebaseline

`5867d9f59726d5bee4c58086afccac7bc11883c8` の runtime authority rebaseline では、三項目の位置づけが変えられた。

- `次のリスクを確認する` から `次の状態を観察できる` へ変更。
- 三項目の内容を観察状態として書き直した。
- 直後に、これらは複数体系利用を自動的に縮小する規則ではないと明記した。
- 採否や追加検査への利用は外部利用条件へ戻した。

この変更の目的は、観察信号と決定権を分離することだった。三項目の網羅性を証明または固定する変更ではない。

## 判断

三つの観察状態は残す価値がある。

いずれも、複数体系の一致が独立証拠に見えてしまうこと、解釈規則由来の一致、記号的言い換えだけが増えることを見分けるための有用な信号である。

一方、対象や利用する体系によっては、これ以外にも観察すべき状態が生じ得る。たとえば、体系同士が異なる時間尺度を持つため比較不能になる、同じ対象断片が複数の変換規則で重複計上される、体系間の不一致そのものが新しい探索入口になる、といった状態である。

これらを新しい固定一覧として追加する必要はない。必要なのは、三項目を標準的な観察例として残しつつ、対象固有の追加状態を保持できることである。

## runtime改定方針

現行の三項目と、その後の「自動縮小ルールではない」という境界を維持する。

JAは、たとえば次のように局所的に開く。

> 複数体系を使う場合は、たとえば次の状態を観察できる。

ENも同等に `for example` / `such as` を用いる。

これにより、

- 三つの既存観察信号を維持する。
- 観察状態と決定権の分離を維持する。
- 対象固有の追加観察状態を保持できる。
- 新しい固定分類、縮小条件、停止条件、成功条件を追加しない。

## 結論

三つの観察状態は、削除や弱体化の対象ではない。

第19・20段と同じく、初期設計にあった列挙の開放性だけを局所的に復元し、既存の観察能力とauthority rebaselineで確立した決定権境界をそのまま残すのが妥当である。
