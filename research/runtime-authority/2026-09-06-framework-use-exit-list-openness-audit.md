# 文化体系利用の出口分類を監査する

## 対象

`src/ja-JP/methods/framework-application.md` の `## 3c. 利用目的ごとの出口` にある二つの見出しを監査する。

- 調査・診断
- 生成・構成

監査したい点は、この二分類を文化体系利用の完全な出口分類として扱う根拠があるか、それとも代表的な出口として開いておくべきかである。

## 現行での役割

現行の二つの出口は、それぞれ異なる証拠境界を持つ。

### 調査・診断

文化体系から生じた問い、仮説、反証条件、観察項目、比較軸、追加資料、残差を対象側へ戻し、独立した対象材料で支えられたものだけを `target_supported` へ移す。

### 生成・構成

文章、作品、設計構想、世界構築などでは `framework_generated` を構成資源として採用できる。ただし、伝統上の事実、現実世界の因果、対象の実証的所見とは混同しない。

この二つの境界自体は重要である。調査・診断で要求される証拠水準を、創作上の構成資源へそのまま要求しない一方、生成物を現実世界の事実へ昇格させないためである。

問題は二つの手続きではなく、見出し `利用目的ごとの出口` が二分類だけで利用目的全体を覆うようにも読める点にある。

## 由来

### `3988e12…` 時点

Skillを二つのコア能力へ縮約した `3988e12e5f7f316f377d3391e9486c8467a111d5` の `framework-application.md` には、現在の `利用目的ごとの出口` セクションは存在しない。

当時は、割当、遷移試行、採用後の反転・代替・不適合・除去検査、採用状態、過剰適用が中心であり、利用目的を二つへ分類する静的taxonomyは置かれていなかった。

したがって、この二分類は外部の文化体系やKJ法から受け継いだ固定分類ではない。

### `3dc8777…` — v40 production semantics統合

`3dc8777491977dd58ab506249a30306769011fbc` の `feat: integrate v40 production semantics into ja-JP core` で、現在の二出口が新設された。

同じコミットはRouterの最小実行手順も再編し、文化体系とKJを実作業へ接続する出口を次のように広く記述している。

- 成果物
- 判断
- 調査方針
- 残差・再開条件

現在のRouterでも、`実作業へ反映する` の項目は「成果物、判断材料、調査方針、残差、再開条件へ反映する」としている。

つまり、二出口を導入した同じ設計変更の中で、Skill全体の実作業上の出口はすでに「調査・診断」と「生成・構成」だけでは表せない形で記述されていた。

とくに次の用途は二分類のどちらかへ自明には入らない。

- 意思決定の判断材料へ返す
- 実装や運用の選択肢・制約へ返す
- 調査を終えず、残差や再開条件だけを次へ渡す
- 体系から生じた問いを、制作でも診断でもない設計・計画上の選択肢として保持する

二分類の網羅性を比較・測定した記録は確認できない。

## 後続設計との関係

### 決定権の外部化

v0.5.0のruntime rebaselineでは、Skillが採否・停止・公開・利用範囲を自律的に決めず、依頼者・著者・上位条件または実行AIへ委任された裁量へ返す境界が明示された。

この設計では、文化体系から生じたものが最終的にどの作業面へ出るかも、静的Skillが二種類だけへ限定する必要はない。

### `state recording ≠ decision authority`

出口の種類を記録することと、その種類によって利用可否を決めることは別である。

調査・診断と生成・構成に対する現行の証拠上の注意は保持できる。一方で、それ以外の利用目的を二分類のどちらかへ強制的に押し込む必要はない。

## 判断

二つの出口は削除しない。

- 調査・診断は、対象所見へ進むための独立証拠境界を明確にしている。
- 生成・構成は、探索生成物を構成資源として利用しつつ事実帰属と混同しない境界を明確にしている。

ただし、この二つを文化体系利用の完全な出口taxonomyとして扱う根拠はない。

理由は次のとおりである。

1. 二分類は `3dc8777…` の現代的runtime再編で新設されたもので、外部原典由来の固定分類ではない。
2. 導入時に二分類の網羅性は測定されていない。
3. 同じ `3dc8777…` のRouter側が、成果物・判断・調査方針・残差というより広い実作業出口を持っていた。
4. 現行Routerも同じ広い出口を保持している。
5. v0.5.0の決定権再基準化では、利用目的や採否を静的Skillが必要以上に狭めない方向が明確になっている。

## runtimeへの含意

最小変更でよい。

- `調査・診断` と `生成・構成` の二つの手続きはそのまま保持する。
- セクション見出しまたは導入に、二つが**代表的な出口**であることを明示する。
- その他の出口では、外部利用条件と領域側の証拠要件に従い、`target_supported / framework_generated / cross_field_emergent / unresolved` の境界を維持する。
- 新しい固定出口分類を追加しない。
- 意思決定、実装、運用などを新しい必須カテゴリとして列挙する必要もない。それらを例示して再び別の閉じたtaxonomyを作らない。
- 調査・診断の独立証拠要件、生成・構成の事実混同防止、cross-field provenanceは変更しない。

たとえば見出しを `## 3c. 代表的な利用目的ごとの出口` とするだけでも、現行二手続きの意味を保ちながら完全分類の含意を外せる。

## 結論

`調査・診断` と `生成・構成` は、文化体系利用の二つの重要な出口であり、証拠境界も異なるため保持すべきである。

しかし、両者だけが利用目的の全体を構成するという根拠は確認できない。現行Routerがもともと持つ広い実作業出口と整合させ、二つを代表的な出口として扱うのが妥当である。
