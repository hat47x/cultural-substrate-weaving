# 独立支持と系譜束ねの境界監査

日付: 2026-09-06

## 対象

`governance/governance-and-records.md` の二重計上節にある次の一般則を監査する。

> 同じ原因機構と採否を持つ記録は、一つの系譜として扱う。

この規則は、同じ変更を複数の記録形式で何度も数えることを防ぐ一方、別資料・別観測・別導出で独立に得られた支持まで、原因機構や採否が同じという理由だけで一つへ束ねる可能性がある。

## 初回公開時点

v0.1.0 初回公開 `cd58044…` の governance には、この規則は存在しない。

当時は判断理由、棄却案、制約、未確定事項、反証条件、再評価条件を残す設計だったが、独立支持を「原因機構＋採否」で束ねる規則はまだなかった。

したがって、これは初期の基礎語彙や外部典拠に由来する固定境界ではなく、後から追加された運用規則である。

## 導入点

`2b39432…` で、外部レビュー由来の次の提案が採用された。

- 同じ変更を diagnosis / diff / rule / correction として複数回数えない。

コミットメッセージも、採用事項を次のように要約している。

> Do not count one change several times across diagnosis, diff, rule, and correction.

一方、実装差分ではこれが次の形へ拡張された。

> 同じ変更を、全体診断、個別差分、規則への一般化、後日の訂正として重複計上しない。同じ原因機構と採否を持つ記録は一つの連鎖として束ね、記録件数と独立した効果件数を分ける。

前半はレビューで明示された重複除去に対応する。後半の「同じ原因機構と採否」という一般化は、コミットメッセージで比較・測定された事項としては説明されていない。

## 後続の系譜

`3988e12…` の縮約後もこの規則は残った。

v40 `3dc8777…` では governance の二重計上節へ移され、次の具体例と並べられた。

- 同一資料の転載
- 一枚のカードから派生した複数カード
- 同じ所見を複数の文化体系から再発見したこと
- 同じ仮説の言い換え

これらの具体例は「元の証拠が増えていない」という共通性を持つ。

また、`0499918…` では repost や derived card を独立した appeal として数えないことが、source と discovery path の分離とともに補強されている。

この系列が支えているのは、同じ証拠・同じ派生元・同じ所見の再表現を独立支持へ数えないことである。

## 問題

「原因機構が同じ」と「証拠が独立していない」は同義ではない。

たとえば、互いに独立した複数の一次資料や観測が同じ機構を支持する場合、原因機構が同じであることはむしろ支持対象が一致していることを示すだけで、証拠源まで同じとは限らない。

同様に、採否状態が同じであることも証拠独立性を決めない。

したがって、原因機構と採否だけを系譜束ねの判定条件にすると、次の異なるケースを一列にしてしまう。

1. 同じ一件を診断・差分・修正として言い換えただけの記録。
2. 同じ資料から派生した複数カード。
3. 同じ所見を異なる文化体系から再発見しただけの記録。
4. 独立した別資料・別観測が、同じ機構を別々に支持した記録。

1〜3は独立支持を増やさない。4は、独立性が本当に確保されていれば増え得る。

## 現行runtimeとの整合

現行CSWはすでに、発見経路と証拠源を分ける。

`governance-and-records.md` 自身も、

> 発見経路が増えても、それだけで証拠が増えたことにはならない。

とする。

この文は、逆に言えば独立性の判断軸を discovery path の数ではなく evidence source の独立性へ置く方が自然であることを示す。

また、`framework-application.md` でも複数体系から同じ候補が出ただけでは独立対象証拠が増えないと明示している。

## 結論

維持するもの:

- 同じ変更を診断・差分・一般化・訂正として重複計上しない。
- 同一資料の転載を独立支持に数えない。
- 同じ派生元から出た複数カードを独立支持に数えない。
- 同じ所見を複数体系から再発見しただけでは独立支持に数えない。
- 同じ仮説の言い換えを独立支持に数えない。
- 発見経路と証拠源を分ける。

再基準化するもの:

- 「同じ原因機構と採否なら一つの系譜」という一律判定。

代わりに、同じ変更または同じ根拠から派生した記録を同一系譜として扱い、独立支持かどうかは証拠源・観察・導出の独立性で判断する。

原因機構や採否が同じでも、独立した証拠源まで自動的に束ねない。

## runtime方針

`governance-and-records.md` の該当箇所を、概ね次の意味へ変更する。

- 同じ変更や同じ根拠から派生した記録は一つの系譜として扱う。
- 独立支持かどうかは、原因機構や採否の一致ではなく、証拠源・観察・導出の独立性で見る。
- 現行の四つの重複例は維持する。

これは支持を増やす規則ではない。独立性が確認できないものを独立支持へ昇格させるのではなく、**独立しているものまで原因機構の一致だけで潰さない**ための境界修正である。

## 非対象

- `target_supported / framework_generated / cross_field_emergent / unresolved` の帰属語彙
- repost / derived card / framework rediscovery / paraphrase の重複除去
- 採否語彙の開放性
- 体系固有の寄与と対象側証拠の区別
