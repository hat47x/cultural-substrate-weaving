# governance採否語彙の開放性監査

## 対象

`governance/governance-and-records.md` の判断来歴にある次の語彙を監査する。

> 採否：`adopted / backgrounded / rejected / distorting / reopened`

PR #251 / #252 では、framework application側で「体系由来のものがどこに残ったか」と「体系利用をどう判断したか」を別軸へ戻した。

その結果、採否判断の記録先としてgovernanceのこの語彙がより重要になる。そこで、5状態が閉じた完全集合として必要なのか、それとも代表的な記録語彙なのかを確認する。

## 系譜

### 1. v0.1系 — governanceの列挙は非網羅

初期governanceには、ファイル全体について次の前置きがあった。

> このファイルの列挙は、対象に応じて選択して使う。対象固有の追加項目は動的層に置く。

`2b39432…` で4つの「体系の採用状態」が導入された時点でも、この非網羅前置きは残っていた。

当時の4語は次だった。

- 反映
- 内部足場
- 補助模型
- 不採用

したがって、初期設計ではこの4語を閉じたenumとして扱う根拠はなかった。

### 2. `3988e12…` — 縮約で一般前置きが消える

`3988e12e5f7f316f377d3391e9486c8467a111d5` のskill-boundary縮約後も、判断来歴には

> 体系の採用状態（反映、内部足場、補助模型、不採用）

が残った。

一方、ファイル全体の「列挙は対象に応じて選択」という一般前置きは消えた。

この変更は4状態の網羅性を検証したものではなく、Skillを二つの中核能力へ縮約する作業だった。

### 3. `d2b735d…` — 4状態の一軸化に実測上の欠陥

`d2b735dc0abf79d22e743790e225fce09fac0cb1` では、4状態がframework validityとproduced findingsを一つに折り畳むため、棄却体系が生存所見を産むケースを表現できないことが実測された。

この結果は、状態語彙が固定的・相互排他的な完全集合として十分でないことを示す。

### 4. v40 `3dc8777…` — 5つの判断来歴語彙へ置換

`3dc8777491977dd58ab506249a30306769011fbc` はgovernanceの採否を次へ置き換えた。

- `adopted`
- `backgrounded`
- `rejected`
- `distorting`
- `reopened`

これは旧4語の単純翻訳ではない。

- artifact placementだった`reflection / internal scaffolding / auxiliary model`は消える
- `backgrounded`が入る
- `distorting`が入る
- 時間的な再開状態`reopened`が入る

つまり語彙自体が、置き場所の分類から判断・ライフサイクルの記録語彙へ再編されている。

同コミットに5状態の網羅性を比較・測定した記録はない。

## 既存監査との関係

### evaluation misfit authority audit

`2026-09-05-evaluation-misfit-authority-audit.md` は、この採否語彙をCSW自身の処置命令ではなく、外側で生じた判断の来歴を記録する状態語彙として読むべきだと整理した。

同監査の非目標には「採否状態語彙を削除すること」が含まれる。

今回も5語は削除しない。監査対象は**語彙の閉鎖性だけ**である。

### framework placement/adoption audit

PR #251 / #252 は、成果物への残り方と採否判断を別軸へ戻した。

これによりgovernanceの採否語彙は、artifact placementを網羅する必要はなくなった。必要なのは、実際に生じた採否・歪み・再開などの判断状態を、主体と根拠とともに追跡できることである。

## 閉じた5状態にする必要があるか

確認できた履歴からは、必要性は支持されない。

- 初期governanceは列挙全体を非網羅としていた
- 状態語彙は4語から5語へ実際に置換・拡張されている
- `reopened`のような時間状態も後から入っている
- 5状態の完全性を測定した記録はない
- 現行設計の目的はdecision provenanceであり、固定enumを満たすことではない

したがって、5語に入らない採否状態が生じたとき、それを既存5語へ無理に押し込むことは、判断来歴をむしろ失わせる可能性がある。

## 保持すべきもの

次は維持する。

1. `adopted / backgrounded / rejected / distorting / reopened` の5語は、繰り返し使える代表的な記録語彙として残す。
2. 採否状態を記録した場合は、判断主体と根拠を追えるようにする。
3. 採否状態から`target_supported`等の証拠状態を自動導出しない。
4. `rejected`だけを理由に、独立に支えられた所見を撤回しない。
5. 状態記録からSkill自身の採否決定権を復活させない。

## runtime方針

局所的に、採否語彙を代表例として開くのが妥当である。

たとえばJAでは、

> 採否：`adopted / backgrounded / rejected / distorting / reopened` など

のように、既存5語をすべて維持したまま非網羅性を明示できる。

ENも同様に representative / e.g. の意味を持たせる。

新しい具体的状態を追加して別の固定taxonomyを作る必要はない。

## 結論

**5つの採否語彙は保持し、閉じた完全集合としては扱わない。**

これは採否の証拠境界を弱める変更ではなく、decision provenanceが実際の判断状態を正確に記録できるようにする変更である。
